# R02 — Atomic collection replacement and non-overwriting IDs

Root-approved contract; prerequisite R01 accepted. Own VectorCollection.swift only, new VectorCollectionTransactionTests.swift, optional R02-prefixed external consumer fixtures, reports/R02*. Breaking changes authorized. No R05 score policy, Index implementation, package edit, shared index/commit or nested agents.

## Replacement contract

Remove MutableVectorCollection's remove-then-add default update implementation. Keep update as a protocol requirement and document transactional failure: every thrown update leaves the previous binding and collection membership intact. Arbitrary conformers must supply their own replacement implementation; generic rollback through add is not promised. This is an intentional source break for conformers that inherited the default. Migration is to validate and commit a replacement within the conformer's own synchronization/transaction boundary. Do not implement a generic deep copy or catch-and-reinsert fallback.

SimpleVectorCollection implements update directly: validate candidate dimension, then under its existing lock require the ID to exist and replace the dictionary value without removing it. Missing ID retains existing indexOutOfBounds error family; dimension mismatch retains dimensionMismatch. If both are invalid, dimension validation precedes lookup. Success must not use duplicate-rejecting add. No caller callback or metric executes under the lock. Value/snapshot semantics of stored V remain an IndexableVector conformer obligation; the collection cannot freeze external mutable reference aliases.

## Insertion and ID allocation

Explicit add rejects an existing ID using VectorError(.invalidConfiguration) with an ID/duplicate diagnostic, leaving stored value/count/allocator state unchanged. Any Int explicit ID, including negative and Int.max, remains allowed. Validate dimension first. Explicit insertion does not advance the generated-ID cursor.

Generated IDs are nonnegative and monotonic: begin at0, scan from the current cursor until an unused ID is found, insert atomically, then move the cursor past that ID using checked arithmetic. Never overwrite explicit or generated entries. Removal does not rewind/reuse already consumed generated IDs, and removeAll preserves the cursor. Explicit reinsertion of a removed ID is allowed. After allocating Int.max, the cursor is explicitly exhausted; subsequent generated insertions throw VectorError(.resourceExhausted) without changing collection contents. If occupied IDs extend through Int.max, throw the same error without integer overflow. Failed dimension validation, duplicate insertion or exhaustion must not advance the cursor. The scan examines occupied successors, not the whole Int space; do not allocate a capacity-sized bitmap.

A narrow internal initializer/helper may seed a cursor near Int.max for tests; no public seed/configuration API. Keep the field private outside the bounded internal construction seam. Do not attempt billions of inserts to test exhaustion.

## Search and batch snapshots

SimpleVectorCollection captures the complete dictionary/value snapshot under one lock before search, then computes the supplied metric and TopK outside the lock. Its batch vectors(for:) also reads the requested bindings under one lock. Snapshot means captured V bindings; no universal deep-immutability claim. Preserve R01's actual Float metric witness, candidate count, NaN/tie behavior and existing result construction. A small private/file-private search helper accepting a captured [(ID,V)] may be shared with the existing protocol default to avoid duplicating metric/TopK logic.

The generic VectorCollection default can only compose allIDs/vector(for:); explicitly document that concurrent snapshot consistency is the conformer's responsibility and that the default does not provide an atomic snapshot. Do not add another public protocol requirement solely for this task. Simple's override is the concrete atomic snapshot implementation. Do not sort IDs or transplant a new tie policy. Searches retain entries captured before concurrent removal/update, and no lock spans arbitrary distance metric code; a metric that reenters collection methods must not deadlock.
