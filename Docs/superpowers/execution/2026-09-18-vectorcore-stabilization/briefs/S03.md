## Contract and repair

A TopKResult always has equal indices/distances counts, including after decoding. Decode both arrays into local candidates, reject mismatched counts with DecodingError.dataCorruptedError at the distances key, include both actual counts in the diagnostic, and assign only after validation. Nested coding paths must preserve the enclosing keys. Do not invoke the trapping public initializer on untrusted mismatched arrays. Missing keys, wrong types and out-of-range numeric values retain ordinary decoder errors.

Keep the two existing encoding keys and array order exactly. Do not sort, trim, pad or recompute values. Indices remain arbitrary Int labels at this construction boundary: negative/extreme/duplicate values are not a new rejection criterion. Distances may be negative, infinite or NaN under the existing selection/result policy; Codable support for nonfinite values depends on the selected encoder/decoder strategy. Use explicit JSON string strategies for those tests. No universal ordering, uniqueness or finite-score invariant is added. NaN payload identity is not promised by JSON; finite Float values and signed zero retain their represented values. The nonthrowing direct initializer's existing count guard is already the construction contract; no new crashing path is needed for this task.

SearchResults(from: TopKResult) must now receive a valid pair array and preserve every pair, including through Collection access, toTuples and mapIDs forwarding. Tests cover this adapter, but do not add metadata restrictions to SearchResults or touch computedScore. SearchResult/SearchResults serialize nested records, not independent parallel arrays; preserve their existing optional score/time fields and keys. R05 owns metric-aware relevance. No claim is made that serialized metadata describes an actually performed search.

## Class-wide decoded boundary matrix

Create one maintained table of the relevant representations and their existing contracts; avoid claiming all Codable types in the library are covered merely because these tests pass.

- Generic Vector at zero/small dimensions and supported fixed widths: elements count equals static dimension; valid encoding is keyed elements. Wrong counts throw through its existing initializer.
- DynamicVector: dimension equals elements.count, including valid zero. Negative/extreme declared dimensions with small arrays reject without huge allocation; keyed dimension/elements format remains unchanged.
- Optimized Float widths 384/512/768/1536: existing single-array wire format, exact scalar count. Test both short and long arrays at every width.
- INT8 widths 512/768/1536: existing keyed storage/quantizationParams, exact SIMD4 lane count at every width; malformed short/long/empty storage rejects. Confirm malformed SIMD lane shape or out-of-range Int8 values reject through their ordinary decoder.
- LinearQuantizationParams, standalone and nested at every INT8 width: preserve Q01's five-key tuple semantics, not recalibration. scale finite and positive, min/max finite and ordered, symmetric implies zeroPoint==0; asymmetric legacy zeroPoint retains the full Int32 domain. Valid legacy tuples may differ from current calibrator output and may dequantize to nonfinite Float values; do not reject them based on a new metric-output constraint. Test scale zero/negative/NaN/infinities, nonfinite/reversed bounds, invalid symmetric offset, missing/wrong-type keys and Int32 out-of-range values. Finite min==max and subnormal positive scales remain valid. Re-encoding preserves the stored tuple and raw quantized codes, with nonfinite decode strategies only used for deliberately invalid inputs.
- NormalizationHint wrapping representative generic/optimized/Dynamic vectors: nested malformed vector fails, and accepted I01 behavior ignores decoded hint/cache claims and reconstructs false/nil. Do not re-trust hints or require obsolete optional metadata to be well typed when the accepted decoder intentionally ignores it.
- TopKResult: valid empty/normal, both mismatch directions including empty/nonempty, label/value preservation and nested coding path. SearchResult/SearchResults: valid legacy nested-record round trips and full TopK adapter pair preservation only.

Inventory FP16/SoA/storage wrappers to record whether they expose Codable at all. Non-Codable types are not given new serialization support here. Existing S01/Q01 decoder implementations should remain unchanged unless the new bounded matrix finds an actual contract gap; report that concrete discrepancy to root before expanding production ownership.
