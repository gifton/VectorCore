## Compiler decision

The installed Xcode frontend remains `448457da…` and the verified Swift.org 6.4.2 frontend remains `956438a6…`. The short Swift version does not identify the compiler. Every one of the 64 probe programs exited zero; the numerical acceptance check correctly rejects stale `2.0` where `1.0` is required. The eight deliberately omitted-write controls are successful rejection controls, not positive numerical passes.

Apple lists [Xcode 27.3 beta, build 27C5020n](https://developer.apple.com/news/releases/?id=11032026g), released November 3. No inspected release note establishes a fix for this exact reproducer, and that binary was not locally available. Beta qualification would remain exploratory; a different released compiler and its submission eligibility would require their own acceptance. Existing Xcode 16.2 results provide a legacy-build option, but Apple's [current mobile/TV/spatial upload requirements](https://developer.apple.com/news/upcoming-requirements/?id=04282026a) prevent a complete app built with that old Xcode from satisfying the current upload path.

The recommended decision is to preserve the existing broad intent and hold release sign-off until a suitable Xcode compiler qualifies. The report also makes a narrower exact Swift.org native scope and legacy Xcode scope concrete, without adopting either. Binary distribution is a separate product change: generic and `@inlinable` client code keeps the importing compiler relevant. No source workaround, optimization suppression or canary waiver is justified by the pure-Swift defect.

## Coverage and additional findings

The Catalyst run uses ordinary Release optimization, all three package test bundles and no case filters. Expanded parameterized accounting is **3,447 passed / 163 skipped / one failed**; this is a second counting level for the same run. All seven benchmark numerical-observation methods and the portable arithmetic/copy control pass. It executes the current Catalyst combination; it does not qualify the minimum macOS runtime, Intel, or a corrected compiler.

The paired physical iPhone was available with its existing development setup. A cached-signing Release build and all three bundle signature checks passed, but unfiltered `test-without-building` exited 70 before any test body: Xcode does not support these tool-hosted package tests on a device destination. A dedicated app-hosted test harness or bounded signed public-consumer app is the next infrastructure requirement. No application was generated or installed, and no provisioning or device-security setting changed.

The skip ledger distinguishes 117 subprocess/replacement capability cases, 27 explicit extended-performance XCTest cases, 18 extended Swift Testing methods, and one disabled C-wrapper feature case on iOS/Catalyst. The native sanitizer record has 18 Swift Testing and 28 XCTest skips. Direct C work has separate passing controls; the wrapper skip does not mean all C kernels were absent or unexecuted.

Six extended methods mix timing with ordinary assertions. Independent review found ordinary executed counterparts for four of those properties. The remaining two count results produced by test-authored parallel wrappers; their numerical operations have ordinary coverage, but those exact concurrent contexts remain unqualified. No distinct production dispatcher was found hidden solely behind those six skips. The review identifies bounded optional strengthening if a stronger concurrency-validation claim is desired; it does not invent a new implementation failure or broadly change test gates.

Catalyst metadata needs a separate follow-up: actual compile/link commands select SDK 27.2, while `LC_BUILD_VERSION` in the retained test bundles records Catalyst SDK 13.1. A nonexecuting driver/linker trace reproduces that encoding; a diagnostic-only `-isysroot` variant differs. No actual build flag was changed. These are distinct observations, and neither harmlessness nor downstream runtime equivalence is established.

TSan's invalid-dyld-map/backtrace warnings also occur in the selected mandatory workload. Its 39 passing bodies remain valid scoped execution evidence, with that diagnostic limitation attached. ASan still has leak detection disabled; the earlier separate leak consumer is bounded evidence, not whole-project leak freedom. Existing selected and broader outcomes are not relabeled as warning-free or no-skips qualification.

## Performance result and tool repairs

The original three repeats retain all 63 strict-correctness records and both comparison outcomes. In repeat 2, all samples for generic 512D and 768D dot products lie above their repeat-0 ranges; other operations shift differently. This is not a single extreme sample or a uniform global slowdown. The data does not establish which host/process/cache/frequency condition caused each shift, and no performance implementation change follows from it.

The formal observation ran from **20:07:21.894 to 20:08:21.900 UTC** after competing agent work stopped. All five frames verified AC power, nominal OS thermal pressure and low-power mode off. The four CPU intervals still failed. `PerfPowerServices` had conservative upper bounds of **174.2–179.6% of one core**; other observed processes also exceeded the predeclared per-process limit. Nominal thermal pressure is not a frequency or no-throttling guarantee. The observer exited zero because capture succeeded, while its admission result is explicitly `ready=false`.

Independent review found and repaired fail-open cases in the new readiness evaluator, including empty/nonfinite data, malformed clocks, PID identity and scheduling ambiguity, and optimistic rates over long capture spans. Twenty controls pass under normal Python, `-O` and `-OO`, independently rerun by the coordinator. The active rule is `readiness-rule-refined.json`, SHA-256 `56fb9a40…`; the original rule and both premeasurement refinements remain preserved. Thresholds were not loosened. Snapshot churn and between-snapshot activity remain explicit limitations.

The separate device recorder collision and its class controls are described in the platform report. The task-local guard now rejects conflicting declared payload and capture destinations within and across calls, with controls for normalized/symlink aliases, output flags and surviving child payloads. The overwritten earlier payload remains explicitly lost. The exact prelaunch plan was retained only by hash; the completed cross-call output plan was audited after the physical exit-70 outcome. That later audit is not presented as the byte-identical plan used before launch.

Future timing requires a documented change in host conditions and a complete predetermined batch. The existing repeat runner needs complementary current thermal/power observations for any later acceptance claim; the readiness tool does not automatically authorize or invoke it. There was no timing retry, process termination or system power-setting change in this investigation.
