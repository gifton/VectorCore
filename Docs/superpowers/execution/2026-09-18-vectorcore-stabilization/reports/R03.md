# R03 matrix semantics and logical output bounds

## Change and migration

`BatchOperations.pairwiseDistances` and internal `ExecutionOperations.distanceMatrix` now evaluate every diagonal with the supplied metric. This preserves negative dot self scores and the cosine metric's zero-vector self score of one. The BatchOperations GEMM wrapper replaces its diagonal with direct supplied-metric results while leaving off-diagonal GEMM computation intact. Custom metrics must be symmetric; neither API promises directed-metric parity across execution routes. Existing row/task scheduling and routing conditions remain unchanged.

The public 768-dimensional array convenience now returns cosine similarity by negating the negative-dot score matrix after the existing normalization-once pipeline. Finite results are clamped to [-1, 1]; nonfinite scores remain nonfinite. Identical nonzero, opposite, orthogonal and zero-vector examples follow similarity semantics, including zero self similarity. The accepted N01 normalization implementation is unchanged.

The blocked2, blocked4 and tiled general SoA cosine implementations now fill only `0..<soa.count` on zero queries. Oversized and offset output views preserve all surrounding sentinel bits. Empty SoA writes nothing, including with a nil empty output buffer. Existing nonzero arithmetic, capacity rejection, layout, padding, ownership, tile size and routing threshold are unchanged.

No signatures changed. Callers that assumed universal zero matrix diagonals must use the supplied metric's self score instead. Callers of `cosineSimilarityMatrix` must interpret its result as similarity, rather than negative dot score. The separately documented VectorMath zero-diagonal helper was not changed. Existing tests required no expectation migration. No MatrixDistance implementation change was necessary.

## Numerical and route coverage

The independent oracle computes scalar Double values from six hand-selected three-coordinate patterns: zero, (3,4,0), its opposite, its orthogonal direction, (1,1,1), and (1,-2,2). Remaining optimized dimensions are exactly zero. Every matrix cell is checked for finite output against both the direct supplied metric and the independent oracle; diagonals additionally match the direct metric bit pattern. Tests do not rely on NaN-blind absolute-error predicates.

Pairwise tests cover N0/1/2/99/100/101 with every built-in Float metric, configured Hamming thresholds, Minkowski p1/p2/p3/infinity, and a configured symmetric custom metric whose self score is nonzero. ExecutionOperations covers N0/1/2/31/32, including the 1000-entry serial/parallel gate. The public similarity convenience covers the same execution-boundary sizes, all pattern pairings and nonfinite propagation.

There are 45 independent configuration scenarios. For each optimized width 512/768/1536, Euclidean and cosine run at N255/256/257 with the default threshold 256, N257 with routing disabled, and N7/8/9 with threshold eight. A custom symmetric metric also runs at N257 for each optimized width, with its call counter proving supplied-witness execution despite otherwise eligible dimensions/counts. Enabled eligible Euclidean/cosine cases additionally compare off-diagonal results with direct MatrixDistance output under finite-aware tolerances. This is not an exact pairwise/GEMM numerical-identity claim or a nearby-vector relative-accuracy proof.

Each configuration scenario is a fresh separately filtered process. Only the child mutates configuration, and it restores the entire configuration on success or a thrown error. The parent has no global configuration mutation. Children record actual argv and loader-path overrides, body and completion markers, and route eligibility. The parent installs a termination handler before launch, captures to a file, enforces 15 seconds plus at most two seconds of owned-PID cleanup, and requires successful exit and actual body/completion markers.

SoA covers widths 512/768/1536, N0/1/3/4/5, tile neighbors 255/256/257, and the logical 8 MiB gate neighbors. These are 4095/4096/4097 for width512, 2729/2730/2731 for width768, and 1364/1365/1366 for width1536. The gate is `count * lanes * sizeof(SIMD4<Float>) > 8 MiB`, distinct from page-rounded allocation capacity. Tests explicitly inspect both logical and allocated bytes. Public dimension wrappers, Safe512, and direct blocked2/blocked4/tiled implementations run with zero/nonzero queries, exact/oversized capacities, offset views and bitwise sentinels. Safe512's existing insufficient-capacity error and untouched output are separately checked.
