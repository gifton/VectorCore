# E02 independent design review

## Verdict

**ACCEPT DESIGN with root-confirmed clarifications recorded below.** This is a source/design review, not implementation authorization or runtime acceptance. No build, source/test edit, nested delegation or index operation was performed. Read the E02 candidate, approved R03/N03 briefs, prior mechanical E02 inventory and current provider, batch, transform, context and triangular-matrix sources. E01/O01/R03/N03/E04 acceptance and integration remain dispatch prerequisites, not assumptions established by this review.

## Reviewed clarifications and root resolutions

1. **Submission bound applies to a scheduling phase, not cumulative submissions of every composed public API.** Current public Array.cosineSimilarityMatrix calls normalized(), then distanceMatrix(). Under the proposed design each can submit K workers, for 2K cumulative submissions in one public call although they never overlap. The brief's “at most K child worker tasks in total” and “one root invocation” need an explicit unit. Recommended contract: each shared scheduler invocation/phase submits at most its K total children; nested scheduling from its callback region submits zero additional workers. Sequentially composed phases have additive total submissions. Tests should distinguish phase submission counts from concurrent active-body counts. If root instead wants a public-call-wide cumulative budget, the design needs additional orchestration and that stronger claim is not established by callback-region suppression alone.

2. **Make retained matrix threshold arithmetic explicit.** ExecutionOperations.distanceMatrix currently tests n*n < parallelThreshold before allocation. The brief requires safe partition arithmetic but should expressly require an overflow-free equivalent threshold decision (or checked product with the overflow branch choosing the large-work path). This is a scheduling expression within the owned method, not a request to broaden into all TriangularMatrix storage arithmetic. Do not accidentally preserve the unchecked product while replacing the task group.

Root accepted both corrections during review; the updated brief was reread and verified to incorporate them: cumulative at-most-K submissions per shared scheduling phase, at-most-K library-created workers outstanding across sequential phases, phase-tagged observations, and overflow-free matrix threshold selection preserving the threshold. Nested calls create no additional library workers; suspended outer callback frames are not additional active leaf computations. All user-created fan-out (Task, TaskGroup, async let and detached tasks) is outside the bound, not only detached tasks. These explicit resolutions remove the design ambiguities. No remaining design blocker was found. The observations above preserve the original finding and its disposition.

## Scheduling and cancellation assessment

Coarse contiguous workers satisfy the requested task-submission bound without an eager item/pair closure array. Per-worker partial storage and parent-only assembly avoid unsafe shared output pointers. Use quotient/remainder ceiling division and bounded endpoints after representable range validation; clamp Int.max concurrency to actual work before multiplication/division. A valid tiny range at a negative or near-Int.max origin can be partitioned safely by remaining distance rather than origin multiplication. Empty input still validates explicit concurrency/minChunk domains before the throwing cancellation check.

The common task-local marker must enclose callbacks on both serial and parallel paths, rather than only creation of an outer group. This makes default-to-CPU, CPU-to-default and batch/matrix nested calls inline even when an outer mode selected serial execution. The existing internal CPU test seam can remain as an additional suppression control. Avoiding CPUContext.execute on retained loops is necessary: its queue.async continuation does not preserve the caller's task-local/cancellation context. Keeping that separate public ExecutionContext conformance behavior unchanged while treating these internal call parameters as hints is a coherent scoped choice.

Throwing work has explicit pre/post-body and per-unit checkpoints, including serial/empty routes and direct CPU execute. Structural errors precede cancellation by contract. Sibling cancellation plus structured join prevents returned partial success and abandoned workers; it does not promise preemption of a synchronous row/range kernel. Concurrent failures may choose different original errors. Tests must gate events and observe cancellation rather than assuming a wall-clock ordering. A body already past a checkpoint may finish after cancellation without violating the contract.

The nonthrowing completion policy is consistent: nearest/pairwise/statistics/TriangularMatrix finish all work even when cancelled, while still respecting scheduling and nested suppression. Their utility must not use cancellation-sensitive submission that silently omits work. Explicitly documented cancellation-ignoring completion is preferable to manufacturing zero/partial results. Async Triangular compute closures can observe cancellation themselves; the nonthrowing library contract cannot override arbitrary user-produced values.

## Order, numerical preservation and shape

Input-index assembly, process batch-order flattening and stable filter order remain implementable with indexed worker results independent of completion order. Ordered associative reductions do not require commutativity. Combining initial once with the nonempty serial aggregate aligns that branch with the partition law; empty input invokes neither work nor combine. Exact noncommutative concatenation exposes a completion-order bug that commutative sums would miss. Floating-point partition equality remains expressly unpromised.

N03 logical chunk boundaries must remain independent of worker ranges: collect each original chunk's accumulator and merge in original chunk order, rather than merging worker aggregates and thereby changing the reduction tree. The draft explicitly preserves that distinction. R03 matrix diagonal/zero/sign semantics and symmetric-metric restriction stay unchanged; TriangularMatrix continues strict-upper-triangle callbacks and no callbacks at sizes zero/one. E02 does not repair or activate numerical kernels, configuration settings or autotuning.

Exhaustive shape validation belongs to retained ExecutionOperations.distanceMatrix before any metric invocation in both configurations. Per-row map/normalize may retain ragged dimensions because rows are independent. Replacing both try! factories by throwing calls preserves the exact custom factory error and correct ordered results. Retaining N01 permissive normalization and E04 OperationContext release behavior is feasible with scheduling-only changes. Current fixed-Dim768 public matrix forwarding does not itself prove a dynamic-row Release failure; the proposed internal generic spy/child is the appropriate evidence route.

## Scope and compatibility

The proposed internal dormant removals match the prior qualified and unqualified/member-call inventory. Repeating it at dispatch is mandatory because N03/R03/E04 have isolated work in the same files. Retain Sync statistics, Array.batchStatistics and the NaNInfinityHandling Sync extension; their edges must not be lost when deleting neighboring engines. Do not equate internal declaration access with dormancy for the public Array transform forwarding routes.

executeBatch's existing synchronous one-call behavior is preserved, with a named short-output guard and no writes to an oversized suffix from a correct kernel. Its mode/minChunk/autotuning prose is corrected rather than activating the dormant measureProbes implementation. Removing that unused helper is scoped. The optional initializer minChunk remains documented as ineffective; operative per-method hints still validate and influence coarse scheduling. The brief does not require a public signature break or a new global scheduler guarantee.

## Feasible proof obligations

The specified task-scoped submission/completion seam plus independent active-body recorders can verify both queue and callback bounds without timing inference. Nested calls require recording zero inner submissions and correct complete ordered outputs, including serial outer mode. Phase-aware recording is necessary for composed conveniences as noted above. All finite gates need teardown/release on failed expectations as well as success; do not let a gate waiting for more than K bodies deadlock a correct implementation.

Focused unchanged-base RED for default maxConcurrency=1, pre-cancelled serial work, factory traps and sampled Release validation is well chosen. Baseline executeBatch is a control. Count/range boundaries can be tested without enormous storage through tiny ranges near integer limits and Int.max hints. All six optimized Batch distance helpers, the inherited BatchKernelProvider query default, actual Array conveniences, N03 explicit partition helper and nonthrowing cancelled controls need source-derived route evidence. Existing N03/R03/N01/Top-K suites protect numerical contracts during the scheduling edit. External Swift 6 positive consumers and bounded diagnostic children cover public/default dispatch and guards; they establish no sibling runtime, throughput or memory-envelope claim.
