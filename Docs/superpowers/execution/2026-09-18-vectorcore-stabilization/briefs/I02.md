# I02 — Exact FP16 conversion cache identity and explicit retention limits

Status: approved design, depends on S01 acceptance. See DESIGN_DECISIONS.md for source-breaking API rulings. No production workload target is selected by this task.

## Root contract

A cache hit means identical ordered candidate count, dimension and every Float coordinate bit pattern. Store immutable `[UInt32]` snapshots, not sampled vector hash values and not a digest alone. Hashing chooses a dictionary bucket; full snapshot equality decides identity. Signed zero and NaN payload bits are deliberately distinct. A caller mutating an original array/vector after insertion must not mutate the retained key or payload. Returned SoA retains its own immutable COW allocation after eviction.

Require an explicit `maxBytes` initializer argument, alongside `maxSize: Int = 100`. Both limits precondition nonnegative, zero in either disables retention without disabling uncached conversion. Remove the unconfigured static `shared` actor; Core has no production call site using it. Consumers migrate to a budgeted actor they own. Do not invent a default byte envelope.

Remove public `store(_ soa, for vectors:)`, which permits associating unrelated payload with an exact key. Public getOrCreate constructs a conversion and inserts it privately together with the snapshot of those same candidate values. Public get/clear/statistics remain. Manual-store consumers migrate to getOrCreate. Do not add a public unchecked identity/payload insertion alternative.

Account for retained allocated capacity of the UInt32 identity snapshot and UInt16 SoA backing storage, with checked multiply/add. Exclude dictionary/LRU metadata, transient conversion/lookup allocations and arrays retained only by callers; state those exclusions explicitly. Oversized or overflow-cost entries return an uncached conversion and do not evict existing useful entries. Evict least-recently-used entries until both count and byte constraints fit. Repeated hits change recency but not byte totals. LRU keys must share/reuse the retained identity allocation, rather than retaining a newly built duplicate snapshot on each hit. Clear removes entries, resets byte totals and resets existing hit/miss statistics.

Keep existing statistics() tuple shape for count callers if convenient; add an explicit retentionStatistics value/method exposing used bytes and byte limit. Do not imply byte counts are RSS. Checked cost helpers must be independently testable without enormous allocation. An internal fingerprint-injection seam is authorized for deliberate collision tests; it must not bypass snapshot equality and must not appear in public API.

## Independent regressions

Compare every returned SoA UInt16 element and metadata against an independently invoked uncached `createSoA512FP16` call for the same candidates. The oracle is conversion identity, not a timing assertion or cache's own key builder. For a base vector, change each of all 512 coordinates and check the result matches uncached conversion and does not falsely hit the previous snapshot. Include reorder, candidate count changes, and source mutation after insertion with a retained baseline copy. Test candidate counts 0,1,3,4,5,7 to cover group padding; repeated identical contents in freshly allocated vectors should hit. Add signed-zero and distinct NaN-payload cases: exact key distinction is required even if conversions canonicalize some payloads.

Inject a constant fingerprint into a test cache and use same-count, same-dimension candidate sets with different coordinates. They must remain separate entries and repeated identical inputs must still hit. This exercises the real get/getOrCreate dictionary route, not only a standalone Key equality helper.

Count policy: capacities 0 and 1 with empty/nonempty inputs, repeated hits, more than one eviction, recency updates and clear. Negative limits reject at initialization in isolated child tests with the documented guard diagnostic, not a later removeFirst trap. Byte policy: exact-fit, one-byte-short, oversized-entry bypass preserving an existing entry, multi-entry eviction, repeated-hit accounting, zero bytes and clear. Include both identity capacity and padded SoA capacity in independently computed expected byte cost. Validate overflow helper with near-Int.max artificial counts without constructing huge buffers. Holding an evicted result must preserve its contents; explain why that external allocation is outside cache-retained accounting.

Prior manual-store tests must become real getOrCreate tests and continue asserting identity, eviction and statistics. Test a former false-hit fixture before repair. Runtime RED is required; signature compilation failures alone are not RED.
