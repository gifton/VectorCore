# L02 independent design review

**ACCEPT — design only. No blocking mathematical or scope contradiction found.** Reviewed the candidate L02 brief against current PCA.swift, PCATests.swift, the actual KNNGraph/UMAP callers, MatrixMultiply.swift's LP64 conversions, approved L01, and canonical NUM-10/API-20. No implementation, build, or runtime claim is made.

## Centering and public boundary

The [Double] public mean is an honest representation of the fitted center. There is no public model initializer or Codable wire representation to preserve. Searches of current source/tests/benchmarks identify PCATests reconstruction as the arithmetic migration; existing count/zero/offset assertions can infer Double literals. UMAP uses fit and transform without reading mean, and KNN uses only flattenColumnMajor. No production caller migration outside PCA.swift is presently required.

Compensated Double accumulation followed by one division removes the audited early Float rounding. Applying exactly Float(Double(x)-mean[j]) through one helper in all three paths prevents fit/transform disagreement. Keeping Float panels and SGEMM makes the stated limitations necessary: original input rounding, residual rounding/underflow, and GEMM accumulation remain. Neither translation invariance for arbitrary inputs nor exact compensated sums is implied. The analytic [0,2] and [16777216,16777218] fixtures have exactly representable Float inputs and residuals and independently justify mean offset+1, variance2, and signed projections[-1,1].

The finite boundaries are coherent with L01: public original-input nonfinites are invalidData; PCA-owned residual/public-result overflow is operationFailed; errors actually thrown by the factorization provider retain identity. An overflowing Float GEMM may therefore be rejected by the following L01 provider as invalidData rather than by a newly introduced PCA kernel error. This is consistent with the explicit error-propagation rule and absence of an intermediate-GEMM recovery guarantee. Successful models must check components as well as mean, variances and ratios; successful single/batch projections must check every coordinate. No ratio clamping should conceal numerical error.

Total variance from the rounded centered Float panel is the appropriate denominator for the actual factorized matrix. Double squaring and division avoid the prior narrowing point while checked Float publication deliberately rejects unrepresentable variance. Retaining n-1 for center=false preserves existing raw-second-moment semantics rather than inventing a population estimator migration.

## Shape, sketch, and shared flattening

After validating k<=limit=min(n,d), remaining=limit-k is nonnegative and sketchWidth=k+min(p,remaining)<=limit; no overflowing k+p is evaluated. At/above remaining, exact fallback is selected exactly as intended. Huge nonnegative powerIterations is harmless only on that fallback and remains caller-selected work on randomized routes.

The listed products cover all current PCA SGEMM shapes: input n*d, Gaussian/power panels d*ell and n*ell, projected ell*d, components k*d, and batch output n*k. All SGEMM dimensions and leading dimensions derive from n/d/k/ell, so validating those against Int32.max plus checked element/byte products protects these PCA callers' narrowing/allocation arithmetic. It does not establish arbitrary LAMatMul or upstream LAPACK safety. Validate internal n>=2 before n-1 and exact flat-buffer length before centering/indexing. Pure helpers allow boundary tests without giant arrays or vendor calls.

The shared flatten helper must retain the separation stated in the brief: general row-count/dimension/product checks and unchanged Float payload for KNN, with PCA finite-value checks and PCA BLAS preconditions owned by fit/transform. In particular, do not implement the shared helper by routing KNN through a PCA-only finite-input validator. Ragged validation must precede the PCA finite scan, including a fixture with a nonfinite earlier row and a later shape mismatch. Empty batch transform remains a no-computation return.

Two small implementation details should be made explicit in tests rather than left accidental: choose typed shape errors for internal row-count/flat-count mismatch and unrepresentable dimensions/products, and test the same error category through pure helpers and touched callers; check the mean allocation using its actual Double element width if the generic byte helper is reused. These are implementation precision suggestions, not missing design decisions that block dispatch.

## Tests and bounded claim discipline

The proposed acceptance matrix is sufficient and independently grounded: analytic offset RED, both providers after L01, public single/batch/Operations routes, nondegenerate multicolumn translated covariance, seeded randomized route, full-rank reconstruction, zero/constant and uncentered controls, plus finite-input/residual/variance/projection failures. Every numerical predicate must establish shape and finiteness before error calculations. Backend parity is supplemental, and projection tolerances must account for the differing single-reduction and SGEMM orders.

Provider spies can prove sketch/fallback dimensions and call counts; throwing-provider identity tests cover propagation without broadening this task to adversarial malformed provider result buffers. Public mean migration has a separate non-@testable compile/run fixture. KNN/UMAP controls cover the sole shared flatten consumer and PCA-backed initialization without changing those algorithms. The oversampling trap RED belongs in a bounded child; Int.max iteration tests must never reach a randomized loop. The explicit timeout throw before status access avoids the E02 helper defect class.

The production scope of PCA.swift is adequate. L01 acceptance must precede the baseline and implementation because its algorithms determine the meaningful provider controls. Current header claims about never forming full n*d factorization and guaranteed corpus-scale speed are already contradicted/unsupported by the existing exact fallback; the brief's adjacent-claim correction should remove or qualify them while documenting the actual fallback and Float-panel limits. No new workload target, timing result, general conditioning guarantee, backend safety guarantee, or downstream execution claim is justified by this design.
