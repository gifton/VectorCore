# O03 independent design review

**ACCEPT DESIGN.** No blocking contract contradiction or necessary scope expansion was found. This is design-only acceptance, with actual-library allocation and runtime proof still required before implementation acceptance. Read the candidate O03 brief, current HybridStorage/DimensionStorage/ManagedStorage/DynamicVector/VectorCoreOperations code, OWN-12/22/26 and accepted O01/O02 briefs/pattern. No source edits, builds, index operations or nested agents were performed.

## Ownership and mutation

The proposed move-out/restore approach removes only the enum's incidental owner reference before delegating to the real ManagedStorage COW boundary. Retained value aliases remain owners and therefore force a genuine first detach. Removing HybridStorage's outer copy-and-copyFrom layer avoids the current redundant allocation before the ManagedStorage setter's own check. A scalar setter should delegate directly after extraction; a bulk fill should borrow once and write once through the resulting buffer. Avoid an additional mutable borrow solely to check uniqueness before invoking a setter, which would undermine the stated one-check policy.

DimensionStorage must apply the same discipline at its wrapping enum when it extracts HybridStorage; otherwise the outer wrapper can recreate the alias that HybridStorage just removed. The managed path remains a negative performance control, even if its diagnostic getter/makeUnique needs explicit enum extraction. The design correctly rejects an inference that generic default managed writes were historically quadratic. Restoring a zero-capacity Hybrid inline placeholder after exclusive access does not alter the final mode/shape/data; legal retained copies cannot observe that placeholder. An unsafe escaped pointer or overlapping mutable access is not newly authorized.

Throwing mutable borrows restore the extracted payload with defer, preserving writes already performed and returning the identical error. Inline mutation needs restoration too, because its local buffer is a value copy. Tests must retain a true source/copy through the mutation and then inspect all elements in both values, not merely observe an address or retain an alias that the optimizer can destroy early. Empty closures are invoked once, with no base-address dereference.

The public mutating uniqueness getter must remove only incidental wrapping references, inspect the real underlying owner, and restore it without allocation or data change. Inline values are unique by value. Retained heap aliases report false; after one genuine detach the changed value reports true. makeUnique should delegate to one actual COW boundary rather than allocate a zero-filled replacement and copy through another potentially shared wrapper. It is valid to use a no-op mutable borrow to trigger that one detach, provided allocation evidence confirms no double-detach and the public diagnostic itself remains allocation-free.

Hybrid copyFrom and DynamicVector resized already target initialized floating-point elements; update/assignment is the correct contract. In copyFrom, a retained source sharing the old heap forces destination detachment before the copy, preserving source isolation. Resize uses a distinct initialized destination, preserves its copied prefix and explicit fill tail, and does not mutate its source. No new provider, storage layout, mode gate or escaped-slice lifetime contract is needed.

## Concrete matrix clarifications

DimensionStorage.init(generator:) currently always constructs .managed storage, even for dimensions <=16. The default-mode rule applies to the mode-selecting zero/array/repeating constructors; do not accidentally change the generator's observable isUsingHybridStorage result. Its generator factory is also not an initializer with explicit hybrid/heap modes. Test its existing route separately rather than demand nonexistent mode parameters. This clarification was sent to root and is consistent with the brief's instruction to preserve factories and mode selection.

Likewise, zero heap-payload allocation belongs to actual inline controls. Explicit .heap at Float16 or Double8 legitimately allocates. Default Double9/16 is HybridStorage-backed but internally heap-backed because HybridStorage's threshold is 64 bytes; default Double17 instead selects managed storage. Record both metadata layers honestly. A count-zero capacity or allocator bookkeeping operation should not be mislabeled as a nonzero inline payload allocation.

The existing DimensionStorage Float/Double add, multiply and copyFrom wrappers all pass through the edited mutable-borrow boundary. Including small retained-alias controls for those wrappers is a useful scoped extension of the prescribed fill/bulk matrix; no separate numerical rewrite is warranted. Generator error propagation can be checked without changing its construction algorithm.

## Provider dispatch and compatibility

The three DynamicVector wrappers currently build input arrays, allocate an unused zero result, invoke the selected Operations.simdProvider exactly once and replace the result. Removing only the unused initialization preserves the custom provider witness, original argument order and pre-provider shape check for min/max. clamped has no two-vector mismatch check to invent. Distinctive spy outputs are necessary: numeric agreement with built-in providers alone would fail to detect a bypass. Keep TaskLocal provider installation scoped per test and compare signed-zero/NaN/infinity classifications or bits according to the selected provider's existing behavior.

The array-based provider interface still requires its input/result conversions. The design correctly leaves those and generic fixed wrappers alone. No new public signature, nonfinite policy, SIMD route or unchecked Sendable annotation is required. Existing S01 dimensions and ownership gates remain prerequisites; this task must not repair unrelated factory numerical boundaries or escaped slices opportunistically.

## Allocation evidence and audit disposition

OWN-12 has source/optimized-path evidence of redundant ownership and repeated copying, but the old 1026 count belongs to an instrumented fixture. Requiring fresh linked actual-library Release RED, calibrated allocator coverage, identical workload/flags and exact source/object/executable provenance avoids promoting that fixture count to runtime fact. Measure setup separately from ten scalar writes, complete fills, repeating construction, resize, factories and shared-first-detach/subsequent-unique writes. Consume complete results outside measurement and retain true aliases through measured shared controls.

The acceptance criteria distinguish a detach from malloc count: owner metadata and aligned payload may each allocate. Unique post-setup mutation must not detach, a true shared destination detaches once, and complete construction/fill/resize allocation events remain bounded with at-most-linear requested bytes across the measured dimension series. Default managed controls must retain their optimized behavior. These are fixture allocation properties, not timing/RSS/workload-readiness claims.

OWN-22 may already be optimized away. The brief correctly permits unchanged before/after Release counts while removing dead source initialization, and requires an explicit qualified root disposition rather than fabricating a measured reduction. Input/provider-result arrays remain an intentionally unresolved array-interface opportunity. Parent task/root adjudication should state which source cleanup was completed and which performance opportunity remains, without treating the original acceptance wording as a reason to bypass the provider.

The behavioral matrix, retained-alias Release measurements and focused ASan cover the observable ownership/lifetime changes. Existing unrelated guards or baseline setup failures must remain separate from behavioral RED. Final implementation review should reconstruct the complete patch and verify production-linked allocation provenance, including unchanged controls and all measured-region boundaries. No broader implementation authorization or audit closure follows from this design acceptance.
