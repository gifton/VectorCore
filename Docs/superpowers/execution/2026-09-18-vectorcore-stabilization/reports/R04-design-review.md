# R04 independent design review

ACCEPT — design only. No concrete contract or current-source feasibility blocker identified. Reviewed the root-approved brief, complete MinHeap.swift, shared TopK ordering/heap route and actual Sources/Tests caller search. No builds or implementation were performed.

The generic comparator orientation is consistent with current insert: compare(root,new) admits a later element, so bounded `<` retains largest values and bounded `>` retains smallest. Bulk heapify followed by arbitrary leaf deletion does not implement that selection law; bounded streaming construction fixes membership without reversing the working insertion rule. Validating capacity before allocation/heapify also isolates negative-domain behavior, including the baseline negative-capacity empty removal loop that makes no progress. Empty construction should not call siftDown with an invalid node. Nil/full-retention heapify and bounded selection can coexist; positive capacity need not eagerly reserve Int.max slots.

Strict-weak-order comparator equivalence, rejection of equivalent newcomers at a full heap and unspecified equivalent-key drain order are mutually consistent. Independent numeric suffix references apply to retained multisets; record fixtures must avoid asserting a unique equivalent-key identity when the comparator does not supply it. Array COW copy/mutation controls preserve ordinary value semantics. No generic NaN contract is assumed for an invalid Float comparator.

KNearestHeap can reverse TopKSelection.orderedAscending with smallerIndex to put the worst retained member at the root, while its existing reversed heap drain produces best-first results. The shared comparator is internal @usableFromInline and available in the same module; no TopKSelection edit is required. Numeric-before-NaN, signed-zero index ties, NaN fillers, duplicate identical entries and k0 are explicitly selected behavior changes. Negative k is rejected before allocation. Independent classification/index oracle and both comparator orientations cover the repeated membership class rather than one fixture.

Current production search finds KNearestHeap only at its public declaration; the TopKSelection comment is historical, not an executable caller. Accepted E02 removed ExecutionOperations.findNearestSequential. Direct public KNearestHeap tests are the actual current route and must not resurrect that engine. Modern TopK selection uses TopKBuffer and remains a control. IntegrationProtocolsSuite and TopKNaN test symbols exist; the new heap suite is to be supplied by implementation. Bounded negative-domain child tests must retain hang/timeout versus intentional rejection distinctions. No pointer work is needed, so value/lifetime controls without ASan are proportionate. No new performance/downstream claim is authorized.
