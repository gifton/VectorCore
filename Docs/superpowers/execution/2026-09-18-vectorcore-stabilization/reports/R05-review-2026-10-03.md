## Findings

### Important

**I1. The child-capture directory is chosen from an incidental parent-directory name. It can write outside the repository or fail falsely.** `Tests/ComprehensiveTests/SearchResultScoreContractTests.swift:319-324`
```swift
let base = source.deletingLastPathComponent().lastPathComponent == "workspaces"
    ? source.deletingLastPathComponent().deletingLastPathComponent().appendingPathComponent("R05/children")
    : source.appendingPathComponent(".build/R05-children")
```

This is permanent repository test code, but it hard-codes this recovery program's evidence layout.
- **Checkout at `~/workspaces/VectorCore`:** every test run silently creates `~/R05/children/<UUID>/{score.log,command.json}` in the developer's home directory.
- **Checkout at `/workspaces/<repo>`:** the target is `/R05/children`. `createDirectory` fails for a non-root user, so the test throws even though the code is correct.
- **Any other layout:** UUID directories pile up under `.build/R05-children` with no cleanup.

R02's equivalent harness uses `FileManager.default.temporaryDirectory` (`VectorCollectionTransactionTests.swift:355`).

Fix: use the temporary directory. If the evidence capture needs a stable location, add an explicit opt-in environment variable that the capture driver sets, for example `R05_CHILD_CAPTURE_DIR`. Never infer the location from a path name.

### Minor

**M1. The rationale comment is false.** `Sources/VectorCore/Operations/DistanceMetrics.swift:20-21`: "Double prevents Float addition overflow at maxFinite."
- In binary32, `1 + greatestFiniteMagnitude` rounds back to `greatestFiniteMagnitude`, because half an ULP there is 2^103. Nothing overflows.
- `1 / greatestFiniteMagnitude` in Float gives `0x00200000` (2^-128), which is bit-identical to the Double path. I checked this offline.
- The cited test cannot tell the two forms apart.

The brief-mandated Double form is fine. Its real benefit is a single final rounding for interior values. Restate the comment that way, or drop the clause. The program's claim discipline treats a false claim as a defect.

**M2. The inverse-builtin oracle copies the production expression, and the extreme checks are loose.** `SearchResultScoreContractTests.swift:32-39`, `:9`
- `closeScore(score, Float(1 / (1 + Double(distance))))` repeats `DistanceMetrics.swift:25` verbatim. That includes the `greatestFiniteMagnitude` extreme, where the addendum asks for a limiting endpoint or an offline high-precision value.
- Signed zero should give exactly 1, per the brief. For `-0.0` the test only checks a value within `4 * Float(1).ulp` (about 4.8e-7) at or below 1. Exact `== 1` is asserted for `+0` alone.
- `4 * expected.ulp` measures the ULP above `expected`. When `expected` is a power of two (1, 0.5 or 0.25), that allows 8 ULPs of the lower binade.

My 80-digit Decimal reference, correctly rounded to binary32, puts production at 0 ULP from the reference at every inverse and logistic test point. So nothing is masked today.

Fix: add offline literals: `Float(bitPattern: 0x0020_0000)` at maxFinite, and an exact 1 for `-0.0`, `leastNonzeroMagnitude` and `leastNormalMagnitude`.

**M3. The negative control is tied to the old `Float` return type.** `Scripts/ci/fixtures/R05OldPropertyNegative.swift:3-4`, `R05_public_driver.py:72`
- **What it does prove:** removal of `var computedScore: Float`. With that property present, the file would type-check.
- **How the error arises:** the diagnostic is a type mismatch against the unapplied method `computedScore(using:)`, not "no member". The driver's `'computedScore' in result` check is satisfied by the echoed source snippet, not by the message.
- **What it would miss:** a reintroduced metric-free `var computedScore: Float?`. The control would still fail to compile, and so would still pass.
- **Why environment failures are excluded:** the positive compile runs first with identical flags, so an environmental failure cannot pose as the negative result.

Fix: use `let _: Float? = result.computedScore`. It compiles if a property of either shape exists, and fails only when none does.

**M4. The fixture driver works only with the swiftbuild layout, and it validates with `assert`.** `Scripts/ci/fixtures/R05_public_driver.py:57-60, 69, 72`

### (3) Numerics
**Logistic** (`DistanceMetrics.swift:252-260`):
- For `d >= 0`, including -0.0 because `-0.0 >= 0` is true: `t = exp(-d) ∈ (0, 1]`, `t / (1 + t) ∈ (0, 0.5]`.
- For `d < 0`: `t = exp(d) ∈ (0, 1)`, `1 / (1 + t) ∈ (0.5, 1)`.
- The exp argument is never positive, so there is no overflow. Every denominator is at least 1, so there is no pole; `d = -1` gives 0.7310586.
- Rounding to Float closes the range to [0, 1], so the documented [0, 1] is honest.
- ±maxFinite and ±1000 give exactly +0 and 1, and the test checks the bits.
- NaN and ±inf give nil. Without the guard, NaN would produce NaN and ±inf would produce 0 or 1; the test checks all three.

**Inverse builtins** (`DistanceMetrics.swift:23-26`):
- The domain is finite and `>= 0`.
- `-0.0` passes the guard and maps to 1.
- Any negative value, including `-leastNonzero`, gives nil, as do NaN and ±inf. Removing the `isFinite` guard would make +inf give 0, which the test catches.
- maxFinite gives `0x00200000` = 2^-128, a positive subnormal.

**Offline check** (my 80-digit Decimal reference, correctly rounded to binary32; script in the scratchpad):
- The production output is 0 ULP from the reference at every test point: all 19 logistic values, ±1000, ±maxFinite, and the 10 inverse values.
- The test's Double oracle is also 0 ULP from the reference.
- The 4-ULP tolerance therefore masks nothing, and the GREEN scores `[0.8807971, 0.7310586, 0.62245935]` are correctly rounded.

**Oracle independence:**
- For logistic modest values the oracle is the direct `1 / (1 + exp(d))`, as the brief prescribes. It differs algebraically from the production branch for `d >= 0`.
- The extremes use exact endpoints.
- The inverse oracle is a copy of production (see M2).

**Finite-before-residual:** `closeScore` (test:6-10) uses `#require` for non-nil, then `#expect` finite, then the residual. A NaN or inf expected value fails both expects.

The cosine kernel clamps similarity to [-1, 1] (`DistanceMetrics.swift:160-164`). So near-identical vectors cannot produce a negative distance and a nil score.

### (4) Test strength

- **Scoring outside the lock:** caught, as the mutation run above showed.
- **One call per selected result, and no call for k <= 0:** caught. The spy array must equal the result distances in result order, for k ∈ {-1, 0, 2, 9} on both producers.
