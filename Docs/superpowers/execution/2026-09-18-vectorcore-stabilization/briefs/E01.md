## Domain and arithmetic

`BatchOperations.process` validates effective batchSize>0 before empty/serial/parallel routing; failure throws VectorError(.invalidConfiguration) naming batchSize. Validate the value actually consumed by this call. Current nil uses the private immutable defaultConfig, not the live configuration actor; keep that routing unchanged (E06 owns live settings). Valid empty input returns [] without invoking transform. Preserve ordered flattened results and original transform errors; both serial and parallel partition endpoints use remaining count, never unchecked start+batchSize. Do not redesign configuration transactions (E03), activate currently ignored settings (E06), or change scheduling (E02).

All five CPU helpers and the corresponding five ComputeProvider defaults accept only Range<Int> with a mathematical length representable as Int. Compute upperBound.subtractingReportingOverflow(lowerBound) before Range.count, allocation or task creation; a nonrepresentable length throws VectorError(.invalidRange). This recoverable failure refines the early precondition proposal after inspection showed every affected entry already throws. Positive/negative tiny ranges including endpoints near Int.min/max remain valid. Empty valid requests invoke neither body nor combine and return []/Void/initial as appropriate.

Explicit method minChunk must be >0 and throws `.invalidConfiguration` before empty/serial/parallel/nested routing. Validate defaults even if they ignore the hint for partition selection. Do not activate or redesign currently unused CPU initializer minChunk settings (E06). Do not tighten threshold or maxThreads domains here; default reduction treats nonpositive maxThreads as1 as before and avoids overflow for Int.max.

For nonempty work, target task counts remain >=1. Safe ceiling division is q + (remainder==0 ?0:1), not `(total+tasks-1)/tasks`. Bound doubling of hardware hints before multiplication. Partition end is `start + min(chunk, upperBound-start)`, with the remaining difference proven representable by validated total. Do not clamp an already overflowing sum. Existing coarse chunk choices/mode thresholds/nested-region policy remain unchanged. CPU sequential reduction's initial/combine discrepancy and completion-order reduction belong to E02; arithmetic tests use identity initial values and must not imply those laws are fixed.

`unrolledLoop` and `vectorizedLoop` keep rethrows signatures and precondition count>=0 and width>0 before work, including count0. All positive widths are supported. Emit exactly indices0..<count in increasing order, or consecutive nonempty ranges whose concatenation is exactly0..<count. Arbitrary widths1/5/8/17 must not duplicate/skip. Stop and propagate the original body error. Bound using count-i before endpoint addition; no allocation proportional to count. Specialize common widths only if complete arbitrary-width fallback is retained. API names express intent, not a proven compiler/performance result; no unverified speedup comment.
