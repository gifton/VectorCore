## C arithmetic and evidence

Modulo 2^32 is a complete generic INT8 result policy, matches the explicit wrapping fallback intent and preserves exact fixed-width results. Int8 products safely form in Int32; conversion of each product to unsigned before addition, unsigned final/tail combination, and explicit in-range signed numeric mapping avoid signed-overflow UB and implementation-defined narrowing. SIMD lane accumulation/horizontal reduction must obey the same modular law, not merely return a plausible scalar test value. The existing NEON final horizontal-plus-tail and AVX scalar tail require direct attention. The maximum-magnitude vector at131072 establishes scalar prefix overflow; a SIMD tail/final-add witness must be chosen for that specific path rather than assuming the same all-negative vector trips its signed final addition.

Remaining-count loops maintain i≤lanes and allow a full block exactly when lanes−i≥block, proving the following increment bounded without evaluating i+block prematurely. Pure helper boundary tests near SIZE_MAX test arithmetic, not fictitious huge buffers. Bounded Int64 reference vectors, cancellation patterns and several wrap crossings can independently check all executed implementations. Unsupported architecture execution remains staged; cross-compilation/disassembly is supporting source evidence only.

The compact range512 contract matches all existing implementations and the Swift wrapper. Nonzero lower bounds, padded strides, offset guarded output and nil/empty controls make the documentation executable while retaining unsafe caller obligations. Declared/defined/link inventories should classify internal architecture symbols separately from public-header declarations; linker visibility alone does not make them a new supported public header API. Retaining accepted LAPACK entries/sentinels must use the final L01 header, including its qualified local-workspace boundary.

The planned ordinary C/C++ consumers, public Swift symbol diffs, Debug/Release/custom-dimension controls, actual-source sanitizers and bounded child provenance are adequate for local acceptance when executed. API-38/D01, all-architecture NUM-32 and unmeasured NUM-34 remain explicitly staged or qualified; no downstream support or performance target is supplied by this review.
