# T07 brief: public VectorCoreBenchmarking fails to build on declared non-macOS platforms (root-created)

## Finding (V04 phase C fix-3 re-review, 2026-10-04; root-confirmed on main 8b02e75)
- `Package.swift` declares iOS, tvOS, watchOS and visionOS (`.visionOS(.v1)` among them) and exports the PUBLIC library product `VectorCoreBenchmarking`.
- `Sources/VectorCoreBenchmarking/EnvCapture.swift` calls `Host.current()` and `Process()` without an `#if os(macOS)` guard. On main they are at :113, :148 and :168; in V04-c at :140, :187, :192 and :200.
- Both APIs are macOS-only in Foundation.
- `xcodebuild -scheme vectorcore-bench -destination 'generic/platform=visionOS Simulator'` fails at those lines, on the V04 trees 99d9096 and 23be36f alike (evidence: V04/phaseC/fix3-review/).
- iOS, tvOS and watchOS are expected to fail the same way, but that is not yet verified.
- Class gap: `.github/workflows/ci.yml` (≈:117-123) builds ONLY `-scheme VectorCore` for the simulator and Catalyst destinations, so a public product can break on a declared platform unseen.

## Required (sequenced after V04, which owns EnvCapture.swift until it is integrated)
1. Make `VectorCoreBenchmarking` build on every declared platform:
   - guard macOS-only calls (`Host`, `Process`, and any other API found);
   - give an honest fallback, recorded as unavailable with a reason, not a fabricated value.
   - The macOS output must stay byte-identical.
2. **Mechanical closure.** CI builds EVERY library product, enumerated from `Package.swift` (not a hand list), for EVERY declared platform destination. A policy test fails if the product set or the platform list and the CI loop diverge.
   - Account for the `validate_github.rb` pins: any pinned-file change needs root review.
3. Local evidence: an xcodebuild generic-destination build per declared platform for each product, before and after (RED, then GREEN).
4. Re-derive reachability. Any code newly compiled on those platforms (previously dead there) must be checked for platform assumptions.
