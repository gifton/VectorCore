## Allocation probe design and controls

External `O02-allocation.c`, `O02-main.swift`, `O02-run-probe.py` link the actual SwiftPM Release `VectorCore.build/*.o` and `VectorCoreC.build/**/*.o` with the Release module using @testable import. No copied-source fixture, production counter or production hook. Swift driver uses `swiftc -O`; C callback uses `clang -O2 -fno-builtin-malloc -fno-builtin-free`. These last two flags prevent elimination of the C calibration malloc/free pair only; production object compilation is unmodified SwiftPM Release. Initial calibration observed only the aligned call because Clang eliminated malloc; corrected calibration records both allocations.

The process-local Darwin malloc_logger callback follows Apple's source ABI: [private/stack_logging.h lines37–67](https://github.com/apple-oss-distributions/libmalloc/blob/main/private/stack_logging.h#L37-L67) defines allocation bit2, deallocation bit4, zone bit8, cleared bit64 and callback signature. [src/malloc.c](https://github.com/apple-oss-distributions/libmalloc/blob/main/src/malloc.c) lines1999–2004 (malloc),2079–2086 (calloc),2220–2227 (realloc),2346–2351 (memalign) pass requested size in arg2 except realloc in arg3. The installed SDK public headers omit this SPI; it is used only by this validation executable. Successful heap-allocation events require allocation bit and nonnull result. Deallocations and failed allocations are ignored. Bytes are requested allocation bytes, not resident size, peak memory, memcpy traffic or latency. Direct VM allocation is outside this hook; covered production buffer paths use Swift Array allocation and aligned malloc allocation, confirmed by positive calibration and baseline observed detaches.

Callback performs only atomic counters/loads, no allocation or formatting. Start refuses any preexisting callback (assert), saves it, resets counters, installs logger; stop disables measurement and restores the previous callback. The standalone driver is synchronous. Counters retain all events/bytes and events/bytes >= current payload size. The synthetic filter control injects successful allocation, realloc, failed allocation, free and sub-threshold cleared allocation: expected3 allocations/290bytes, threshold100=>2/270. Real control malloc8192+posix_memalign16384=>2/24576; actual retained ContiguousArray4096 COW=>1/32800 including32 header bytes. Control failure aborts before interpreting measurements.

Metadata/generic paths and output are warmed outside the measured series; explicit warmup output precedes MEASURED marker. Each scalar value is built before start. First mutation has its own region; next100 scalar mutations and next10 bulk borrows are separately bounded. Shared original remains alive through the full sequence. Construction full input rows are built before start; region includes complete fromFullMatrix result initialization and all upper-triangle assignments. Results remain alive through stop and are consumed after stop. Cold metadata in a previously unwarmed compact path can appear in all-event counts; payload counts and geometric series reveal buffer cost.
