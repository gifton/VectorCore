# L01 — Range-safe Float factorization with checked workspace boundaries

Root-approved design after independent review; dispatch requires accepted N01. N01 accepted Core work is the prerequisite. Read L01-root-investigation.md, L01-workspace-inventory.md and canonical NUM-08/09/35. This task repairs the reproduced Swift factorization defects and local workspace arithmetic. NUM-35 remains a qualified concern about extreme vendor-internal arithmetic: do not claim all Int32-shaped Accelerate calls safe merely because local guards pass. No practical corruption or real allocation failure has been reproduced.

## Public numerical contract

Keep public result types, column-major layout, QR m>=n, thin SVD k=min(m,n), descending singular values, ascending eigenvalues and lower-triangle-only symmetric input. Input arrays retain value semantics. QR/SVD reject any nonfinite input value as invalidData after existing shape validation. Eigen rejects nonfinite referenced lower-triangle values, but ignores strict upper-triangle values including NaNs/infinities. Apply these input rules consistently to Swift and LAPACK providers; normal shape-error ordering remains before input-value checks and backend availability.

For the Swift provider use Double working matrices, accumulators, reflector parameters, rotations, convergence decisions and normalization throughout all three algorithms. Convert to Float only at the public result boundary. Do not widen a sum then narrow it back before alpha-beta/reciprocal/rotation operations. This uses larger temporary storage and does not promise a speedup. Preserve Householder QR, cyclic symmetric Jacobi and one-sided Jacobi SVD; no Gram-matrix SVD, third-party dependency or replacement backend.

Successful results must contain finite Float factors and spectra. If an otherwise finite input produces an output that overflows Float or an internal nonfinite state, throw operationFailed with a factorization-specific diagnostic. Do not clamp an overflowing spectrum or return NaN/Inf factors. Ordinary Float rounding is allowed, including nonzero subnormal scalar values rounding to zero; docs must distinguish this output-spacing limit from failure to normalize in the widened workspace. The public API cannot promise relative accuracy below Float representable spacing. Apply finite-output validation to LAPACK returned results as well (not the unused workspace matrix when eigenvectors were not requested), without claiming that its accuracy/stopping policy now matches Swift.

Retain the explicit Swift SVD rank-deficiency caveat: it need not complete a null-space basis for exact zero working columns. For tall/square matrices zero columns can remain in U; for wide transpose mapping they can become zero rows in Vt. Nonzero working columns are normalized in Double even if their singular value later rounds to Float zero. Do not misclassify the audited full-rank golden-ratio fixture as this exception. QR still returns the accumulated thin identity/reflection columns for zero/rank-deficient input. No universal relative accuracy or convergence guarantee for arbitrarily ill-conditioned matrices is added.

## Arithmetic and stopping rules

QR: compute column norms with a scaled Double sum-of-squares or stable iterative hypot; form signed beta, tau and alpha-beta in Double, normalize the reflector tail by direct Double division, apply reflectors to Double trailing columns, and accumulate Double Q. Avoid a Float reciprocal, including during final conversion. Preserve zero-column identity behavior. The published R strict lower triangle is constructed as exact zero.

Eigen: copy only the referenced lower triangle into a symmetric Double working matrix and form Double identity eigenvectors when requested. Compute a stable Double Frobenius scale. Use a relative stopping tolerance based on `epsilon(d)=max(1e-12, 8*gamma(d))`, where `u=Double.ulpOfOne/2` and `gamma(d)=d*u/(1-d*u)` with d=n; current Int32 bounds keep the denominator positive. Compare the maximum absolute off-diagonal entry to epsilon(n)*Frobenius norm (zero matrix converges immediately). This is the chosen stopping criterion, not a claimed rigorous forward-error bound. Rotation construction must use stable hypot/scaled arithmetic rather than squaring an unbounded theta. Preserve symmetry on every update and eigenvectors-off behavior.

SVD: retain the tall algorithm and wide transpose/swap, keeping an internal widened decomposition through that mapping until final public conversion. Compute column inner products/norms in Double; test normalized pair correlation against epsilon(m) above, with exact zero columns skipped. Do not use the old squared Float comparison. Construct a stable smaller Jacobi rotation without unsafe zeta-squared overflow; keep both the rotating input and V in Double. Final singular values come from stable Double column norms, and nonzero U columns divide directly by the Double norm. Sort the widened spectra before final Float conversion and permute all factors consistently.

Keep the 60-sweep cap. A final explicit convergence check is allowed after the last sweep; otherwise exhaustion throws operationFailed rather than returning an unchecked decomposition. Every intermediate nonfinite condition must terminate with a typed error. Do not claim unconditional convergence or a fixed typical sweep count. Small stable norm/rotation helpers may be shared internally and exercised directly at boundary values; no architecture-specific unsafe workaround or fast-math compiler flags.

## Local workspace and index representability

Preserve modern Accelerate LP64 (__LAPACK_int is signed32) and non-Apple unavailable stubs. Add small internal pure C helpers, preferably an unexported private header usable by a standalone test driver, for checked count products/sums, element-to-byte conversion, auxiliary IWORK size, sufficient workspace formulas and returned query conversion. Promote before multiplication; every subsequent narrowing has a validated bound. Swift validation checks that required input/output/Double-working element-byte counts fit Int before allocation, in addition to existing shape checks. This is representability, not a successful-allocation or memory-budget promise.

Before a vendor query or local allocation, validate the routine's dimension/leading-dimension relationships and all local count/byte expressions. Use explicit int64/size_t checks for 8*min(m,n), never multiply in signed32 first. For thin SVD preflight the representability of the reference sufficient Float-work count4*k*k+7*k and integer-work8*k; for symmetric eigen apply the appropriate mode: n<=1 needs one; eigenvalues-only n>1 needs2*n+1 Float work and one integer; eigenvectors n>1 needs1+6*n+2*n*n Float and3+5*n integer work. Treat exceeding signed32 workspace lengths as a checked unsupported-size condition before query; do not silently saturate. Document that these sufficient bounds can conservatively reject shapes whose vendor-specific tighter path might fit. QR/ORGQR preflight their dimension/leading-dimension and minimum-workspace counts; a returned optimal query remains separately validated.

Direct C calls retain LAPACK's valid zero-size quick-return domain: validate scalar dimension/job/leading-dimension constraints first, then return success for valid zero work without allocation or pointer access. Positive-size pointer capacity/initialization/layout remains the caller's unsafe precondition; this patch does not invent runtime lengths or claim arbitrary pointer validation. Invalid scalar parameters return the documented routine argument-position info codes before local arithmetic. Record the exact mapping in the header/tests. Non-Apple stubs still return unavailable without using buffers.

Returned Float workspace queries must be finite and positive before rounding or integer conversion. Compute a conservative upward count in a widened type, preserving the existing positive 1/64-plus-one headroom if desired, but check every addition and reject an excessive result instead of clamping to INT32_MAX. Explain the conservative policy without asserting an unverified Accelerate version. The accepted floating query/count must also meet the routine's known minimum; integer query results must be positive and meet the documented minimum before conversion to bytes. Validate every malloc byte count; free all previously allocated buffers on every rejection path. Add distinct C sentinels for invalid workspace query and unrepresentable local workspace, recognized before generic negative-info mapping by the Swift provider. Map invalid query to operationFailed and unrepresentable workspace to invalidDimension with a specific size diagnostic; preserve unavailable/allocation-failure mapping and document its current shared sentinel honestly.

These checks do NOT prove arithmetic inside Accelerate's query or factorization implementation safe for every accepted shape. Retain the small-panel operating guidance and explicitly qualify that Int32/local-workspace representability does not establish an arbitrary-shape production envelope. Root will disposition NUM-35 as local arithmetic repaired with the upstream extreme-shape question still qualified/staged unless new independent evidence establishes a stronger envelope. Do not choose an arbitrary workload cap or switch to ILP64 to manufacture closure.

Unsafe/nonfinite/hang-risk probes are bounded children; no arbitrary huge vendor calls.
