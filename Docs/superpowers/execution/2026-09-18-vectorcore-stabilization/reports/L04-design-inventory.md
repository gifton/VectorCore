## Actual routes and retained behavior

Public PCAModel.fit → internal fit (PCA.swift:114/130), Operations.pca → fit then batch transform (334–340), and both public transform overloads (247/280) are synchronous. UMAP's vector entry (UMAP.swift:164) either accepts CSR or calls KNNGraph.bruteForce, then selects PCA or random initialization; graph-only entry (199) copies supplied nested coordinates or generates random coordinates. Both share umapLayout (231), fuzzy build, curve fit and serial optimizer. PCA initialization (266–296) fits, obtains nested projected rows, then copies to flat coordinates. UMAPResult.point (132) creates a row array; its SIMD2 accessor creates a separate output array.

In-tree production consumers of PCA are Operations.pca and UMAP PCA initialization; shared flatten also serves KNNGraph.bruteForce. FuzzySimplicialSet and UMAPLayout are internal and called by the UMAP tail, with direct @testable tests. Provider QR/SVD public methods are used by PCA and provider tests. Searches across Sources, Tests and Benchmarks found no benchmark cases invoking these PCA/UMAP/KNN APIs. Public external callers remain possible; absence of in-tree calls is not removal authorization. Existing UMAPTests cover direct-distance ordinary kNN, hand-graph membership/fusion, isolated rows, deterministic seed replay, graph injection, both initialization paths and result accessors. PCATests cover reconstruction/subspace and single/batch/one-shot equivalence. These are small correctness controls, not memory envelopes or cancellation evidence.

The provider seam is Operations.$linearAlgebraProvider (LinearAlgebraProvider.swift:147–154), default LAPACK when compiled with Accelerate, otherwise Swift. It is TaskLocal; preserve custom provider dispatch/error identity when designing any new entry. LAMatMul.multiply (MatrixMultiply.swift:29–60) separately calls column-major LP64 cblas_sgemm or its synchronous Swift loop (68–113); overriding the factorization provider does not override GEMM. There is no C UMAP optimizer route. LAPACKLinearAlgebraProvider calls the C shim synchronously; vc_lapack.c:54–144 queries and allocates routine workspaces, calls backend routines, then frees workspace. No cancellation callback enters BLAS/LAPACK. A future checkpoint around such a call cannot promise interrupting its internals or a wall-clock upper bound without a separate bounded-operation assumption.

## Analytical storage and work anchors

Let N be samples, D input width, K components/output width as appropriate, L sketch width, E stored directed CSR entries, F fused directed edges and R edges surviving optimizer pruning. Counts below are logical payloads, not allocator requested/live bytes or RSS, and simultaneous lifetime requires measurement.

- PCA.swift:148–203 materializes and centers N×D Float input (4ND bytes). Randomized fit also constructs D×L Gaussian omega, N×L Y/Q, D×L Z/Qz and L×D panel, with QR R factors created by the provider even when only `.q` is read. Exact fallback selects the full panel when L reaches min(N,D); it does not avoid full factorization. SVD always returns both thin factors, although PCA only consumes singular values/VT. Components require 4KD bytes plus means/statistics. L02 changes mean to Double; L01 changes Swift working matrices to Double, so current Float-only profiles cannot establish the eventual envelope.
- SwiftLinearAlgebraProvider.swift:197–213 transposes wide input, recursively factors the transpose and transposes both returned factors. Tall path creates rotated input and square right rotations (215), then sorted U/VT (282–293). QR creates working input, tau, R and explicit Q (38–93). COW bindings are not automatically additional allocations; actual detach/lifetime must be observed. LAPACK provider:65–93 holds mutable input copy plus U (N×min(N,D)), VT (min(N,D)×D) and singular values. The C shim's JOBZ='S' (common/vc_lapack.c:96) requests both thin factors; changing that contract is not a trivial local discard optimization.
- PCA batch transform:247–277 allocates centered N×D input, N×K projected flat output and N separately allocated row arrays. Components are already reinterpretable as column-major D×K, so no physical component transpose is present. Single transform allocates K output values. UMAP's PCA initializer then adds another N×K flat output while nested projection exists.
- KNNGraph.bruteForce:132–199 holds 4ND input, 4N norms, 8NK output indices/distances plus CSR offsets, and 8K top-k scratch. Each block has B×D copied query panel and B×N Gram output, B=min(N,256). This bounds the Gram panel, not total memory or total work: candidate enumeration remains quadratic and insertion can take O(K) per accepted candidate. Preserve existing tie order and the separately qualified Float Gram cancellation limitation.
- FuzzySimplicialSet.swift:97–160 allocates rho/sigma, canonical tuples reserved to E, sorts canonical keys, allocates fused tuples with capacity reserved to 2E, sorts again, then emits separate head/tail/weight arrays. Canonical tuple fields logically total16 bytes/entry; fused fields total12 but actual tuple stride/padding and reserved capacity must be measured (typically16 on this platform). Final edge payload is12F. Duplicate directions reduce by max then probabilistic union; sorting yields lexicographic (head,tail). Equal-key reduction is not summation, but changing event order later affects layout.
- UMAP.optimize:400–460 keeps original edges and builds retained head/tail arrays plus four Double schedule arrays: 8R+32R=40R payload. `nextSample = cadence` initially shares then detaches on writes. Negative-rate zero still creates both negative schedule arrays. Current 12F+40R excludes input CSR, tuple staging, coordinates, allocator slack and other live references; audit example F=R=150M gives7.8GB decimal, an analytical illustration only.
- Each epoch scans all R entries (`for e ... where nextSample[e] <= now`, UMAP.swift:442–444), then updates eligible edges and draws negative samples. A sparse schedule could change order of RNG consumption, attraction and repulsion; identical membership alone would not establish identical coordinates. Current fuzzy calibration performs up to64 row passes; sorting costs O(E log E + F log F). L03 changes numerical calibration, not graph architecture or epoch scan strategy.

## Remaining root decisions and bounded prerequisites

1. Wait for accepted L01–L03 numerical/shape contracts and V04's measurement/claim discipline. L02 expressly retains arbitrary nonnegative powerIterations, synchronous semantics and Float panels; L03's 2^53−1 scheduling/product domain is numeric representability, not a runtime budget. Their pending implementation must not be represented as current behavior. L04 resource admission, if selected, needs a distinct contract and explicit compatibility choice.
2. Choose which public routes receive cancellation/progress and whether legacy synchronous success behavior remains untouched. Define checkpoint phases, error identity, input/model publication behavior, and custom-provider obligations. Task cancellation can be checked synchronously in task context, but these APIs also have ordinary synchronous callers. Do not silently introduce a new ambient failure mode or promise cancellation inside external provider/GEMM calls. E01/E02 async task scheduling contracts do not automatically apply here. R03's distance-matrix corrections do not repair or replace the distinct KNN Gram route.
3. Choose supported measured shapes/routes rather than inferring five-million corpus support from comments. Separate fit sample N from transform corpus N; graph-only UMAP from vector/PCA/brute-force entry; exact/randomized PCA; default/Swift/custom provider. Budget estimates must state whether caller-owned input, output, staging and backend workspaces count. Checked Int/LP64 byte representability from L01–L03 is not OOM recovery or a successful allocation promise.
4. Select any specific representation/schedule optimization only after evidence. A right-factor-only provider extension, flat transform API, compact graph or event schedule each changes a different contract and scope. Public tuple/model/CSR ordering and custom witness migrations must be explicit; do not implement all opportunities merely because L04 names memory/work.

## Independent executable acceptance options

Use tiny analytic axis-aligned PCA fixtures with known mean/spectrum/projection and independent Double residual/subspace checks; preserve finite/shape checks and sign/subspace ambiguity from L01/L02. Use hand CSR graphs with independently computed directed memberships, duplicate max/union and exact lexicographic edge lists. For schedule changes, an independent small reference trace should record epoch, edge and RNG draw/update order, with deterministic no-cancel output comparison on the same backend/build. Seed equality alone or comparison against a newly rewritten helper is insufficient. Exact results should only be required when arithmetic/event order is preserved; changed arithmetic needs an explicit numerical contract.

Cancellation tests should deterministically request cancellation at named phases/checkpoint counters, prove no later work/publication and cleanup, and retain ordinary no-cancel results. Include pre-entry, flatten/centering, power iteration, factorization boundaries, calibration/fusion, epoch/negative-sampling and transform phases as applicable to the chosen scope. Huge loops or timing-only races are unnecessary. Backend boundary tests must identify the uninterruptible interval rather than manufacture a latency guarantee.

Release profiling should coordinate an identical seeded workload, consumed full results and exact binary/source provenance. Report analytical logical payload separately from total allocation events/requested bytes, measured peak live bytes and process RSS/high-water metrics; existing O03/Q01/E04 malloc_logger counters do not by themselves measure live/retained memory because they count allocations without a complete free ledger. Measure fit/transform and graph-build/layout phases separately and end-to-end; capture retained model/result memory after temporary lifetimes end. Repeat bounded representative cases selected by root, without a new pass/fail throughput target. Preserve inputs, ordering and numerical controls for every measured variant.
