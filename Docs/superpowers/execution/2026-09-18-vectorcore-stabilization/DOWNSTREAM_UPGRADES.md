# VectorCore downstream upgrade list: every consumer-visible change since v0.3.3

- **Baseline:** tag `v0.3.3`, commit `fca4b602383589c46b627d8a0de2b6b2a68cd07d` (2026-09-06), the last release.
- **Target:** branch `codex/vectorcore-stabilization-2026-09-18` at `fa19bc96acca0044945c82a0281308c9d271e687` (2026-10-16). Local only: not pushed, merged or released (D01-L04 decision packet).
- **Scope:** VectorCore only (products `VectorCore`, `VectorCoreBenchmarking`, `vectorcore-bench`, and the `VectorCoreC` headers). Sibling repositories were not read; mapping these rows onto VectorIndex, VectorAccelerate or any other client is the consumer agent's job.
- **Compiled:** 2026-10-16, from four sources: `CHANGELOG.md` `[Unreleased]` at the target; `git log --first-parent v0.3.3..codex/vectorcore-stabilization-2026-09-18`; the task closures with the D01-L04 decision packet; and a mechanical diff of the public symbol graphs and C headers (Appendix C).

## How to use this

Upgrade in this order. (1) Make the client compile: work through section 1 (removed or renamed API, each with its replacement) and section 2 (changed signatures: new parameters, types, `throws`/`async`). (2) Rebuild every binary that links VectorCore from source: the package is not built with library evolution, and section 4 lists the layout and mangled-name changes that make old binaries invalid. (3) Audit section 3 line by line against the client's tests and assumptions: those changes compile silently and alter scores, rankings, NaN and tie handling, defaults, validation order, error kinds and traps. (4) Re-measure anything section 5 touches. (5) Consider section 6. (6) If the client uses `VectorCoreBenchmarking`, `vectorcore-bench` reports or the C headers, read section 7. (7) Read Appendix E for what the target does not promise. Each row has an ID, the change, the consumer action, its source and a tag; a row that names symbols lists them in backticks as `Type.member` paths from the public symbol graph. Rows never state an impact the sources do not state.

## 3. Behaviour changes with no compile error (the dangerous list)

These compile unchanged and return different results, throw or trap in new places, or change their side effects. Re-baseline any test that pins scores, rankings, NaN positions, hashes or error kinds.

### 3a. Search, selection and ranking
