# D03 — Lazy log messages and monotonic elapsed timing

Root-approved design after independent review. API-31 candidate. Preserve public Logger/LogLevel/PerformanceTimer/VectorError.log signatures and the existing default timer threshold. No measured logging overhead or production latency target is claimed. Production ownership is Sources/VectorCore/Logging/Logger.swift only; new LoggingContractTests and narrow bounded public fixtures are allowed.

## Message evaluation contract

Read the configured minimum level once per logging call. If level is below that snapshot, return without evaluating the message autoclosure or constructing location/format strings. If admitted, evaluate the message exactly once, reuse the resulting String for OSLog and the Debug console output, and preserve existing level mapping/category/location/function formatting. 'Admitted' means VectorCore's level gate passes and its backend call is made; OSLog's independent persistence/filtering is not promised. Do not query OSLog enablement to change this library contract.

Preserve laziness across all five convenience wrappers, including their forwarding to the private log helper. The VectorError overload defers its fallback error.description until admitted; a caller-supplied ordinary String? has already been evaluated by the caller and gains no new autoclosure promise. VectorError.log continues to forward source location and message normally. No change to error formatting/numerical behavior outside this file.

Retain the existing lock protecting minimumLevel. Snapshot under the lock, release it before invoking user message/formatting/backend code. A message may read or update configuration or recursively log; no logger lock is held around it. A concurrent level change affects later snapshots, without retracting an already admitted record. Do not add global mutable test state or broaden logging configuration. Fix existing examples referring to nonexistent LogConfiguration.shared/enableOSLog/public log methods to actual APIs; no invented settings.

## PerformanceTimer contract

Replace CFAbsoluteTime wall-clock measurement with ContinuousClock. Capture one start Instant in initialization and compute each log's duration from that same start. Repeated log calls report cumulative elapsed time, not lap/reset intervals. Convert the Duration components to Double seconds without overflowing integer arithmetic, compare against the supplied TimeInterval threshold, and format milliseconds as before. Production elapsed time follows ContinuousClock monotonic semantics and is independent of civil-clock changes; no deadline or exact callback timing is promised.

Because log remains nonthrowing, a negative or nonfinite threshold suppresses that call without message formatting/emission. Finite zero is valid and permits an immediate elapsed0 record if the level gate admits debug. Large finite thresholds simply do not emit for smaller observed durations; do not convert an arbitrary threshold to a trapping integer/Duration representation. Negative elapsed readings supplied by a deliberately invalid test clock also suppress the call. A normal monotonic clock does not need a civil-time correction or arbitrary maximum elapsed cap.

Use a narrow internal initializer accepting a @Sendable closure returning ContinuousClock.Instant for deterministic tests; production supplies the actual clock. Capture start once. Tests can supply fixed instants advanced from one real reference Instant, eliminating sleep and system-clock mutation. Keep this seam internal, with no public clock/backend control.

## Independent tests and actual integration

The five levels crossed with five valid minimum levels form a mechanical25-case matrix: calls below minimum evaluate zero times, admitted calls exactly once. Include an expensive/side-effectful String interpolation, Debug dual-output reuse, source-location forwarding and normal/VectorError forwarding. There is no 'off' minimum above critical in the existing API; do not invent a disabled-critical case. A per-instance internal configuration/emission seam is permitted for isolated deterministic tests, with its default still using the shared public configuration and actual backend. An immutable task-local observation seam is another acceptable implementation; no process-global unsynchronized callback.

Test reentrant configuration access/update from an admitted message and nested logging with a finite depth, verifying exact message counts and no lock reentrancy deadlock. A bounded child protects any actual unchanged-base hang-risk probe; do not use a sleep as evidence of correct sequencing. Retain source-established lock policy even if the race/reentrancy fixture passes at baseline.

A fresh bounded public-consumer child uses the real public initializer/global configuration, changes only minimumLevel, restores it and verifies actual message-side-effect counts for disabled/enabled calls. Parent suite serialization is not sufficient isolation. Preserve E02-style file capture, pre-run termination handler, 15s execution plus <=2s cleanup and throwing before termination-property access on timeout.

Timer tests use supplied Instant sequences for elapsed0, just below threshold, equality, above threshold and repeated cumulative readings. Assert whether a message is constructed and the formatted elapsed value through the test emission seam. Include negative/NaN/+infinity/-infinity thresholds, huge finite threshold, negative injected elapsed and suppressed debug level. The timer should not format its debug message if either threshold or logger-level gate rejects it. Clock-sequence invocation counts establish one start read plus one per log call, including invalid-threshold calls; this does not require formatting or emission for rejected calls. Monotonic clock source is directly visible in adjacent production code; no test pretends to alter the host civil clock.

Actual baseline RED must show disabled debug/info/warning/error message spies evaluating despite the level gate; critical remains admitted under all valid minima. Preserve the timer's source-established civil-clock dependency separately from the deterministic desired elapsed-contract tests: injection added only to the repair does not retrospectively prove a host-clock jump occurred. Run focused Debug/Release and actual public compile/run. No sanitizer or speed benchmark is required for this synchronous repair when locking/ownership remain unchanged.
