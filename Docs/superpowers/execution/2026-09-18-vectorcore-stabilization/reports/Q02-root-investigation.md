Read current WORK_ITEMS Q02, audit NUM-16/17/19/20/21/24, and relevant source at accepted HEAD 6d47ec5. This note records observations only. Do not dispatch or implement from it; prepare/review a bounded brief first.

- MixedPrecisionKernels.adaptiveEuclideanDistance is public opt-in, width512 only. It ignores threshold, examines only query max magnitude <100, then quantizes both query and candidate via a one-candidate FP16 SoA; else returns direct optimized FP32 distance. Reproduced historical examples include threshold0 near ties and reversed zero/70000 operands. A useful contract must specify error units, zero reference, nonfinite behavior and actual reference; checking FP16 representability alone cannot enforce an arbitrary relative bound.
- QuantizedAutoTuner selects using operation, dimension, candidateCount and accuracyRequirement but caches only the first three in an interpolated String. Its thresholds currently choose reduced precision for smaller accuracy values. It has no input values, so shape-only decisions cannot prove an arbitrary actual-data accuracy bound. Define whether the argument is a heuristic hint or an enforceable constraint before changing its direction. Existing dictionary access is locked; no race alleged.
- KernelAutoTuner.WorkloadCharacteristics has memoryBudget and latencyTarget but selection keys and filters ignore them. Workload precision enums include fp32Full/fp16Acceptable/int8Acceptable with overbroad error comments. Public selectStrategy is currently nonthrowing. Override is checked before cached profiles/heuristic, with no feasibility filtering. Persistence uses implicit Application Support by default, private init, lazy load and unversioned profileCache JSON; overrides are not persisted despite docs. CI/test environment bypasses profile selection, so ordinary path needs a standalone temp-path fixture.
- KernelAutoTuner.selectMixedPrecisionStrategy maps fp32Full to tolerance0.0001 and invokes MixedPrecisionAutoTuner. Explicit full mode must return fullFP32 or a documented error before any reduced strategy/calibration/override can win.
- MixedPrecisionAutoTuner is a singleton actor with synchronous calibration inside selection. Cache key includes exact dimension/candidateCount/accuracy string; manual override precedes calibration. Unsupported dimension fatalErrors. Calibration functions at512/768/1536 try all5 strategies, each5warmups+20measurements, plus baseline/generation and possibly another25 full-FP32 fallback executions. Reduced execution converts candidates on each invocation. These profiles measure synthetic, conversion-inclusive behavior, not arbitrary input accuracy or preconverted serving. Full source below calibration entry has not yet been completely reviewed by root.
- FP16VectorPool returns/stores immutable FP16 values; it cannot refill them for new conversions. Removing unsupported conversion-reuse/GC/allocation-elimination wording can proceed without new mutable scratch or O05 ownership changes. Do not silently build a mutable pool.

Open root choices: adaptive validated output versus conservative mathematical bound versus explicitly renamed heuristic; invalid accuracy/shape behavior; cache identity; exact-precision precedence across all public selection routes; hard constraints versus explicit profile filters/no-feasible result; persistence version/hardware/algorithm provenance and explicit path; bounded or explicit calibration and truthful conversion boundary. User performance targets/downstream intent remain deferred. No hard latency/memory workload target may be invented.

Possible policy alternatives were considered but none is selected here. In particular, computing a full baseline to validate every adaptive result is correctness-first but adds work and cannot be called an acceleration; shape-only synthetic heuristics cannot promise arbitrary-data error; profile memory estimates cannot be relabeled as measured peak allocation/RSS.
