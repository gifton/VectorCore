## Hash class and identity boundary

All four optimized vectors have the same sampled hash at Vector384Optimized.swift:336 and Vector512/768/1536Optimized.swift:337: combine SIMD blocks0,1,last-1,last and dimension. Equality scans every block. Thus the first/last eight scalar coordinates determine every hash input, and arbitrary interior-only changes deterministically collide. This is lawful Hashable behavior with poor distribution, not unequal hashes for equal values or an observed dictionary correctness defect. Ordinary Float/SIMD hashing already gives equal signed-zero hashes; replacing it with raw bit hashing would need zero canonicalization to preserve equality. NaN does not obey ordinary reflexive Float equality; do not invent a bitwise NaN equality contract.

R01's SoAFP16CacheKey (Operations/Kernels/SoAFP16Cache.swift:8–39) separately stores exact source bits plus a fingerprint; its equality is not the sampled vector hash. P01 must preserve that accepted exact cache identity and collision controls. No in-tree vector-keyed production dictionary consumer was established by this bounded inventory; public downstream Hashable consumers remain possible. Hashes are process-seeded and not persisted identifiers. O03's COW/alias repairs are fixed controls, not permission to alter storage or introduce cached hashes/invalidation state.

## Selection routes and actual allocation classes

- TopKSelection.select([Float]) (TopKSelection.swift:141–164) constructs N index/score pairs before deciding heap versus full sort at actualK < N/10. The small-k heap itself is O(k), but the wrapper remains O(N) temporary storage. Generic select<T> (278–296) similarly evaluates its closure once per input in input order into N pairs. Generic nearest (310–333) first creates N Float distances and then the pair array. batchNearest (493–509) repeats generic nearest per query.
- Pointer select (188–264) already streams small-k scores through TopKBuffer. It has a count<=Int32.max restriction and returns Int32 labels; ties use source positions before optional ID mapping. It must not be reused to impose that restriction on the Int-indexed array/generic APIs. Its large-k branch creates/sorts N indices, which is a distinct existing strategy.
- Direct optimized TopKSelection nearest Euclidean384/512/768/1536, cosine preNorm/fused512 and dot512 (343–490) already stream into TopKBuffer. Euclidean membership is selected on squared scores, then square roots are applied and output ties sorted on transformed values; dot API maximizes positive similarity. These are controls, not an opportunity to change metric arithmetic.
- TopKBuffer (Kernels/TopKSelectionKernels.swift:10–70) eagerly allocates k Float and k Int slots. Positive-capacity callers protect push; k0 is not a safe standalone push route. mergeTopK (85–97) allocates a fresh destination buffer and iterates both partials. Its preconditions require equal direction/tie policy and destination capacity >= both capacities. Reducing local capacities to min(k,range.count) is conceptually compatible only if range wrappers' current `localTopK.k == k` invariant and every merge/caller are deliberately migrated; do not change a capacity argument at one site alone.
- Public throwing Operations.findNearest (Operations.swift:63–133) validates positive k, nonempty input and all dimensions before dispatch. Installed BatchKernelProvider has priority. CPU Euclidean512/768/1536, cosine512 and dot512 stream only for k<N; other cases compute complete distances then shared selection. The optimized helpers (286–365) allocate initial and per-range k-sized heaps; provider parallelReduce returns ordered partials before combine. E02 bounds library workers but does not make heap storage independent of k/partial count. combine allocates replacement heaps. Near-N selection therefore merits measurement rather than an assumed speed win from streaming.
- findNearestBatch (149–198) validates full query/candidate shapes, then provider override, then eligible GEMM batch (Q>=8,N>=256), then per-query findNearest. The fallback revalidates candidates per query. GEMM materializes Q×N scores and pointer-selects each row. Eliminating repeated validation requires a private validated worker while preserving all public preflight and override/error behavior. Streaming selection alone cannot remove a matrix-producing API's output contract.
- Nonthrowing BatchOperations.findNearest (129–165) returns empty for k<=0 or empty candidates, with complete results under cancellation. Current source chooses serial/parallel using ParallelHeuristic. Serial and parallel optimized helpers create full N distances then N pairs; generic serial creates pairs directly, generic parallel (448–458) creates chunk pair arrays then flatMaps all N pairs. Selection finally uses shared heap/sort (around791). E02 already removed the historical candidate-array chunk copies in favor of integer ranges; do not reproduce that obsolete audit description as current. E06 is changing threshold/config snapshot/chunk routing and activating formerly shielded routes; inventory and reservations must be refreshed on accepted E06 before P01 edits.
- VectorMath.nearestNeighbors (VectorMath.swift:402–413) computes all metrics even for k0, fully sorts with bare `<`, then prefix(k). Negative k traps after work; NaN/tie order is not the modern selector policy. API-45 requires an explicit root decision about k<=0 callback behavior and NaN/tie migration, not an optimization that silently changes those semantics.
- VectorCollection selection (Integration/VectorCollection.swift:138) calls array TopKSelection after computing its distances; it benefits from removing pair materialization but does not thereby become metric-streaming. Preserve accepted R02 snapshot/transaction behavior. Benchmarks/TopKNaNContract exercises array/pointer and optimized Euclidean/dot controls; ordinary benchmark provider batches are not necessarily these nearest APIs.

R04's approved brief still mentions ExecutionOperations.findNearestSequential as a KNearestHeap caller. E02 removed that dormant family from shared source; current production search finds KNearestHeap only at its public declaration in MinHeap.swift, not a live nearest route. R04 remains the legacy heap-contract prerequisite, but its route description must be reconciled rather than reintroducing removed code. R03 matrix metric/zero/prefix contracts remain fixed; API-24's matrix reshape opportunity is broader than a top-k-only change and needs separate explicit scope if selected.

## Decisions and independent acceptance options

Root should select which materializing wrappers change, whether near-N keeps sorting, and whether VectorMath adopts the modern order/k policy. Preserve custom metric/provider witnesses and exactly-once callback count where currently observable. Streaming generic closures must not evaluate lazily only for likely winners or reorder callbacks silently. Throwing Operations versus nonthrowing BatchOperations cancellation contracts differ; E02's worker cap, nested suppression, ordered reduction and error identity remain. New validation must not defer errors until unsafe indexing or metric work, and a private validated worker cannot become a public bypass.

An independent small oracle should explicitly classify numeric-before-NaN, numeric ordering/direction and requested tie policy, without calling the production comparator. Enumerate permutations, NaN first/middle/last/all, infinities, signed-zero ties, equal values at selection boundary, source-position versus arbitrary ID labels, k<=0/1/near-N/N/>N and small/large strategy threshold boundaries. Under `.smallerValue`, equal keys need the documented equivalence policy rather than invented stable membership. Keep squared-score membership distinct from transformed-score output order; use independently supplied score fixtures for selector laws and direct Double/scalar references for metric cases, not kernel parity alone. Test every actual optimized width, generic metric spy, provider override, serial/parallel and varied logical chunks. Public malformed shape/error tests must prove no callback/unsafe route runs before required validation.

For hashes, generate structured sparse/dense interior-only variants at all four widths, copies and signed-zero equivalents. Assert equality implies equal hashes and that the entire interior-varying corpus no longer deterministically collapses, not that every unequal pair has a unique hash. A test can inspect fed coordinate coverage or a deterministic internal test hasher mechanism only if root authorizes it; Swift's randomized final hash must not be hard-coded. Observe actual dictionary insert/lookup results separately from distribution and measure their Release scaling before a speed claim.

Release selection profiles should hold k fixed while N grows, then sweep k near N and chunk sizes. Separate input/candidate payload from temporary scores/pairs/heaps and output; measure allocation events/requested bytes plus appropriately qualified peak/retained process memory using V04 methodology. Existing O03 allocation counters alone are not peak memory. Consume full results, use identical score/kernel workloads and comparison boundaries, retain baseline/final source and linked artifact hashes, and report consumer overhead/raw samples. No performance target or universal O(k) total-memory claim follows when provider chunks, matrix scores or caller input remain live.
