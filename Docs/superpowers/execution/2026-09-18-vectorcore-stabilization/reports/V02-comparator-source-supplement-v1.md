# V02 frozen-v1 comparator schema supplement

Disposition: **CHANGES REQUIRED — IR2**, supplemental to the preserved full source review. Read-only analysis; no comparator execution, builds or source edits.

`Scripts/compare_benchmarks.swift:72–78` conditionally casts `correctness` to a dictionary and its `status` to String. Failed casts silently skip validation. For example, otherwise valid input with `correctness:"invalid"`, `correctness:[]`, or a correctness dictionary containing numeric/boolean status plus positive samples and finite errors can be compared successfully. These are invalid records, not permissible metadata incompatibility. The V02 contract assigns invalid input exit 2 and states that `--allow-incompatible` does not waive failed correctness/execution records. This gap also contradicts the comparator's claimed record validation.

Smallest correction: distinguish absence from a present value before casting. Preserve absent correctness for cases with no observation. Explicit null may be treated as absent if the optional-field policy is documented; it must not be confused with an actual correctness observation. A non-null present correctness value must be a dictionary, its required status must be the exact String `valid`, samples must be a positive integral numeric count, and all four existing error fields must remain finite/nonnegative. Missing or malformed status in a present observation must fail. No new numerical tolerance or requirement that every benchmark family supply correctness is implied.

The inspected historical baseline JSON contains 156 result rows, all with correctness absent; all 156 iterations and unitCount values are integers. Therefore this guard preserves those actual legacy artifacts under their explicit metadata override. No source or fixture evidence justifies accepting arbitrary correctness strings/arrays or non-string statuses as a legacy format. If another real historical status-less schema is later identified, root can explicitly define a narrow migration; silent acceptance is not that migration.

`Run.init` also currently applies only positive finite numeric validation to `iterations` (line 66). Fractional iterations are impossible under the producer's integer count schema and have no legitimate averaging interpretation: timing statistics carry averages, iterations counts completed operations. Add the same positive integrality check already used for unitCount, and apply it to correctness.samples. This is a representation-domain guard, not a workload cap. Do not add an arbitrary practical maximum or claim exact large-integer validation from Double conversion; a full exact UInt64/Int parser redesign is not needed to close the observed fractional-count gap. Existing positivity/finite checks and NSNumber-versus-boolean rejection remain necessary.

A bounded table in the existing independent reporting driver should exercise malformed correctness string/array/number, missing and non-string status, invalid status, fractional iterations and fractional correctness.samples; run each relevant rejection with `--allow-incompatible` to prove the override cannot bypass it. Keep positive controls for absent correctness legacy records and well-formed valid observations. If null is admitted, include its explicit positive control. These are source-required tests; no runtime outcomes are asserted here.
