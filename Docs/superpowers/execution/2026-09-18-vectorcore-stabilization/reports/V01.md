## Changes and contract migration

- `CorrectnessStats` now distinguishes `.valid` from `.invalid` with a reason. Both length mismatch directions, empty comparisons and nonfinite inputs are invalid with zero meaningful samples. All four error statistics must be finite and nonnegative; valid finite errors remain measured values.
- `CorrectnessOut` now includes status/reason and optional numeric fields. Invalid comparisons omit unavailable fields, preserving a normal JSON object without NaN/Infinity or invented zero error. Its old numeric initializer is replaced by `init(from:)`; downstream decoders must adopt the new schema.
- `BenchResult.executionFailure` retains provider error descriptions. `BenchRun.failures` contains named reasons. Failed execution/timing results are represented there and excluded from timed `results`; consumers must check failures rather than assuming every selected case has a timing row. CSV appends a quoted failure table when needed.
- `BenchmarkRunner.run(options:registry:) -> Int32` is the single runner called by `@main` and injected test suites. Missing validation and empty result sets fail strict mode; defaults remain FP32 1e-6, FP16 2e-3, FP16 cosine 3e-3. Finite override meanings are unchanged. Nonfinite/negative/malformed CLI thresholds reject configuration. Output I/O/encoding and execution/timing errors fail regardless of strict mode.
- `Harness.warmupAsync` / `measureAsync` accept throwing bodies and rethrow, including calibration and recursive multisample paths. Fourteen batch case boundaries (28 provider calls, generic and optimized width families) use the shared `BatchExecution.run` boundary. No provider `try?`, discarded 1536-width reduction or guessed zero remains. Every returned reduction value is now compared against an independently precomputed Double aggregate. A bounded `ProviderObservations` collector retains invalidity, maxima, error totals and counts through warmup, calibration, fixed iterations and recursive samples. Existing per-distance evidence is combined by count-weighted means and maxima; invalidity dominates. Independent post-measurement work cannot erase earlier thrown errors or bad returned values.
- Preserve platform floors, dependencies, runtime provider selection, kernel routing, and library numerical policies. Normalization's existing random-input setup fallbacks are unchanged; this task addresses provider execution failures, not registry/reference coverage expansion.
