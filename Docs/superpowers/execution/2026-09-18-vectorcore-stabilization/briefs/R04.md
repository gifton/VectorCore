## Generic heap

The comparator is a strict weak ordering: compare(a,b) means a precedes b at the heap root. A bounded heap retains the last capacity elements in that ordering, so its root is the least desirable retained member for replacement. With numeric `<`, retain the largest values; with `>`, retain the smallest. Correct the existing contradictory insertion comments. Do not invert the working streaming replacement rule.

Both initializers require capacity nil or >=0 before allocation/heapify/work. Nil is unbounded, zero retains nothing and insert returns false. A positive limit is a retention cap, not a demand to reserve that many slots immediately; do not eagerly allocate Int.max capacity for an empty/few-element heap. Bounded bulk construction must select the same retained membership as streaming insertion over the input. Use bounded insertion when truncation is necessary; retain O(n) heapify for the unbounded/full-retention case if desired. Deleting arbitrary leaves of a heap is not selection.

Equal comparator keys need no stable removal order. At a full heap a new comparator-equivalent item does not replace the existing root. Callers needing a deterministic secondary order supply it in compare. No generic Float NaN policy is invented for a caller-supplied comparator that fails strict-weak-order obligations. sorted() drains a copy in comparator order; iterator remains heap layout, not sorted order. Retained element lifetimes and value copies remain ordinary Array semantics.

## KNearestHeap

Deliberately adopt the established TopKSelection ascending-distance order for this legacy helper: numeric distances before NaN, lower distance first including infinities, smaller index for distance ties (including signed zeros and NaN/NaN). NaNs remain eligible only after numeric candidates, so all-NaN/underfilled results can still contain NaNs. This is an explicit newly documented legacy contract, not a claim it had that policy already. Duplicate identical entries are allowed; this is not ID deduplication.

Reuse the reviewed shared comparator in reversed orientation for the bounded heap's worst-at-root order where available. getSorted returns ascending best-first order using that same contract. k must be nonnegative; k0 stays empty. Avoid copying the comparator's logic into a second subtly different NaN implementation. Preserve the public fields/signatures and generic heap behavior.

Route inventory after accepted E02: public Operations and TopKSelection select through TopKBuffer; E02 removed dormant ExecutionOperations.findNearestSequential and its legacy KNearestHeap call. Current production search finds no KNearestHeap caller beyond its public declaration. Preserve that removal; do not reintroduce a dormant route merely to test it. Existing public TopK NaN/tie tests must remain green, and repeat the caller inventory against the actual dispatch base.
