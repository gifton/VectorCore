# Q01 root design candidate

This is a concrete proposal for independent design review, not an approved implementation brief or numerical closure. It supersedes none of the recorded early rulings until root resolves the remaining scope questions below.

## Calibration and finite projection

Use one affine calibration helper for LinearQuantizationParams and QuantizationSchemes per-vector calibration. Require finite ordered min/max. Keep original min/max metadata. All-zero input uses scale1/zeroPoint0. Symmetric nonzero calibration starts with Double(maxAbs)/127 and zeroPoint0. Asymmetric calibration includes zero: lo=min(minValue,0), hi=max(maxValue,0), idealScale=(Double(hi)-Double(lo))/255; derive zeroPoint=roundAway(-128-Double(lo)/idealScale), bounded in floating space to[-128,127] before integer conversion. Constants are handled by this zero-inclusive interval, without a tiny arbitrary fallback scale.

Round idealScale to Float and clamp up to Float.leastNonzeroMagnitude. To keep every legal byte's projection finite for **newly calibrated** tuples, cap scale at the greatest Float no larger than Float.max/max(abs(-128-zeroPoint),abs(127-zeroPoint)). Compute the bound in Double and use Float.nextDown when rounding overshoots. This deliberately permits about one step of endpoint saturation near Float.max, including the symmetric positive endpoint because the stored code domain includes-128. It does not claim nominal half-step accuracy at every clipped endpoint.

Proposed endpoint regression bound: one actual quantization step plus two Float ULPs of the input and decoded endpoint (least-subnormal units near zero), evaluated in Double after asserting finite values. Independent design experiment reports/Q01-calibration-design-probe.py tested100081 intervals/400324 endpoints; worst error was1.0000000596046483 steps at symmetric[0,Float.max]. That script currently uses a looser two-step assertion; it establishes neither a universal bound nor a production repair. A reviewer should assess the tighter proposed bound before dispatch. Retain exact closed-form cases and a deterministic exponent/interval matrix in production regressions rather than porting this helper as its own oracle.

## Conversion and serialized tuples

Classify finite input before any float-to-integer conversion; use Double(value)/Double(scale)+Double(zeroPoint), round nearest-away, clamp to byte bounds in Double, then cast. Use the same observable operation for scalar, packed AoS and transposed SoA including padding. No Float reciprocal. Decode with Float(Double(scale)*(Double(code)-Double(zeroPoint))) once, consistently in scalar and SIMD helpers; large legacy offsets cannot be rounded to Float before subtraction.

Decode validation proposal: positive finite scale, finite ordered original min/max, and symmetric implies zeroPoint0. Preserve every valid legacy tuple's exact serialized fields, including asymmetric Int32 zero points outside the byte range. Do not recalibrate decoded data. Such legacy tuples can have real decoded coordinates outside Float range; their Float projections are IEEE infinities. The finite-projection guarantee above is limited to newly calibrated tuples. Linear decoded values themselves remain finite in Double: code-minus-Int32 is smaller than2^32 and Float scale is smaller than2^128.

Throwing array initializers should reject nonfinite payloads with VectorError before extrema/calibration. Existing nonthrowing scalar/from/repeating/calibrator entry points can require finite inputs with named Debug/Release fatalError diagnostics; changing all protocols to throws is unnecessary. Raw storage and quantization shape guards from S01 remain. Decoders reject invalid parameter tuples with DecodingError, rather than reaching nonthrowing initializer traps. Nonfinite schema calibration also rejects explicitly; perDimension single-vector calibration remains unsupported and should reject before the empty-input shortcut.

## Cosine and mutable borrows

Positive per-vector scale cancellation also applies to asymmetric tuples: x_i=s*(q_i-z). Preserve the existing Int64 symmetric fast path when zero points are0; use compensated Double accumulation of centered codes for asymmetric values. Centered codes are exactly representable in Double and squared-sum magnitude is bounded well below Double range at all three built-in widths, even for Int32 endpoint offsets. Compare against an independent Double **decoded-coordinate** oracle. Either zero vector still has distance1; clip only finite similarity. Do not confuse Float projection overflow in a legacy tuple with an invalid finite mathematical decoded vector.

EX-01 proposal: quantized mutable borrows are explicitly transactional. Throwing body discards the temporary, preserves original storage/parameters exactly and rethrows the original error; no cleanup quantization runs. Successful finite writes recalibrate and commit once. Normal-return nonfinite writes reject with an explicit precondition because the rethrows protocol cannot introduce a new recoverable error. Tests mechanically cover all three widths, normal/throwing body, a nonfinite partial write followed by throw (must still preserve original and error), copy isolation and normal-return invalid children. This preserves existing throw behavior while making the family contract explicit; O02 partial-write semantics do not extend to quantized temporary storage.

## Still unresolved before dispatch

- Define distribution-calibration percentile semantics and finite/domain validation without unbounded Int conversion, and canonical empty SoA/calibrator behavior. Current code's sorted-index formula can reverse the interval; the bounded repair must include this conversion site.
- Re-derive downstream kernel behavior for newly meaningful subnormal scales. Same-scale integer Euclidean multiplies scale after sqrt, but mixed/AoS/SoA Float differences and squares can underflow; symmetric dot multiplies scales in Float and may underflow before a representable sum. These are source-established concerns pending explicit root disposition/reproduction, not repaired by scalar quantization or cosine. Decide a bounded Q01 extension or separately ledgered follow-up rather than claim all INT8 metrics are range-safe.
- Existing approximate scale equality in INT8 Euclidean can treat unequal decoded vectors as identical. Its predicate and witnesses need a separate root decision before numerical consumer closure.
- Validate the proposed endpoint bound, raw-code/legacy compatibility and exact write ownership with an independent reviewer. No implementation dispatch yet.
