# Q03 — Synchronized, rounding-aware FP16 diagnostics

Root-approved contract after independent design review. API-21 and NUM-18 candidates. Own diagnostics and the three live FP32-to-FP16 constructor recording hooks; do not overlap Q02/Q04/O05 edits to MixedPrecisionKernels.swift. No new conversion/precision gate or performance claim. Hardware metadata and MixedPrecisionProfiler are outside this task.

## Recording and snapshot contract

All reads/writes of the mutable enabled flag and statistics use the same lock. Eliminate both unlocked record guards. enable resets the statistics and enables recording atomically, including a repeated enable call. reset atomically resets statistics and finite-range state without changing enabled. disable atomically disables future accepted records while preserving the last snapshot. getStatistics returns a coherent value snapshot. isRecording is only a synchronized hint, not a reservation for a future record.

A scalar record or complete batch is accepted only when enabled at its locked commit. Each accepted batch contributes all its events atomically relative to enable/disable/reset/getStatistics. Optional preflight disabled checks may skip diagnostic preparation; recheck enabled under the commit lock before changing counters. A record that started preparing before reset can join the new generation if enabled when it commits; there is no start-time epoch guarantee. A disabled record changes nothing. Document this exact policy rather than promising every physical conversion during a concurrent toggle is counted.

Classification may be prepared outside the lock from immutable inputs, but mutable enabled/range/counters cannot be sampled there. Logging/formatting happens after unlocking from captured values, so OSLog work does not extend the statistics critical section. Avoid one log per finite event for ordinary batches; preserve useful diagnostics without introducing a timing guarantee. Cumulative integer counters use a documented saturation policy rather than wrap/trap if they reach Int.max; ensure rate computation widens before any potentially overflowing arithmetic.

## Classification of the actual rounded representation

An event is one FP32 input converted to FP16 with the existing round-to-nearest-even kernel. Total conversions counts all accepted events. Classify into the following mutually exclusive exceptional categories:

- nanValues: original input is NaN.
- overflowToInfinity: original input is finite, and the actual rounded FP16 output is signed infinity. Input infinities count toward total but are not arithmetic overflows.
- underflowToZero: original input is finite and nonzero, and rounded FP16 output is either signed zero.
- subnormalValues: rounded FP16 output has exponent zero and nonzero fraction (for finite input).
- Finite normal outputs, original signed zeros, and original infinities have no additional exceptional counter.

Use actual UInt16 output bits for the three live constructors, not magnitude thresholds or a separately recomputed assumed result. Extend the narrow internal recording helper to consume the original lanes and already-produced FP16 storage. Preserve all three constructor storage/shape checks. A raw-fp16Values initializer and FP16-to-FP32 conversion do not perform a new FP32-to-FP16 conversion and must not add these events. The internal scalar/batch recorder APIs used directly by tests can derive Float16 bits through the same documented scalar conversion contract, but must share the classifier and cannot drift from constructor recording.

The range tracks original finite FP32 inputs, independently of rounded classification. Before any finite input, minValueSeen and maxValueSeen remain 0. The first finite input initializes both; later finite inputs update them. Positive-only batches must not include a fictitious zero minimum; negative-only batches must not include a fictitious zero maximum. NaN/infinity-only batches leave the empty range sentinel. If both signs of zero occur, use -0 for minimum and +0 for maximum deterministically. A lone signed zero preserves that sign in both bounds. Track whether any finite input has been observed privately rather than inferring it from totalConversions. reset/enable clear this state.

Correct misleading constructor/recording comments within owned scope: values just above 65504 can still round to finite 65504, and tiny nonzero inputs can round to zero. Do not rewrite actual conversion algorithms unless independent boundary evidence establishes a mismatch and root authorizes that separate repair. The diagnostics repair must not silently change stored FP16 bits or activate a dormant alternate kernel.

## Incorporated independent-review refinements

A false synchronized preflight hint may skip a conversion even if enable happens later; commit-time acceptance applies to records that reach commit, not every conversion during a toggle. Empty batches contribute no events. Counter-coherence assertions near saturation must use widened or checked sums. Signed-zero range ties must be handled explicitly both within a batch summary and when merging that summary into an existing snapshot.

SoA builders already invoke the three instrumented constructors for real vectors. Do not add a second SoA hook or count raw padding storage as conversions. Public low-level conversion functions remain outside this recording coverage. In constructor child tests, prepare expected values before enabling, or use raw-bit fixtures; snapshot assertions must not trigger additional instrumented conversions.

Run the unchanged unsafe TSAN baseline only in an isolated bounded probe, then the fixed case separately. Children must use the same instrumented executable and preserve the sanitizer environment. Require child body and completion markers; sanitizer startup failure or an empty filter is a setup limitation. Join every worker and gate before final assertions and process exit.
