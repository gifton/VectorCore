# T16 brief: NaN contract for reductions (max/min/maximumMagnitude) and element statistics (root-created; from the T15 phase 2 review)

## Finding
Swift's `max(a, b)`/`min(a, b)` drop a NaN in one argument position: `max(1, .nan) == 1` but `max(.nan, 1)` is NaN. This defect class has now appeared in:
- the cosine clamp (T15);
- `ChebyshevDistance` (T15);
- `VectorProtocol.lInfinityNorm` and `Vector<D>.lInfinityNorm` (T15 fix round 1).

The T15 review found the remaining instances outside T15's metric scope:
- the provider reductions `maximum`/`minimum`/`maximumMagnitude`, where the Swift and vDSP implementations may disagree on NaN (unverified);
- the element `min`/`max` statistics.

## Required
1. Inventory every Float/Double reduction or statistic built on `min`/`max`/`Swift.max`/`.maximum`/vDSP `maxv`/`minv`/`maxmgv` in Sources, with its NaN behaviour probed per position and per provider (Swift vs vDSP).
2. Root rules one NaN contract for reductions: propagate NaN, or document a deliberate NaN-ignoring variant. Recommend one, with evidence. Make all providers agree.
3. RED-first tests, and an exceptional table across every reduction and provider.
4. Mechanical class closure: a lexical guard flagging a Float `min(`/`max(` or `.maximum` reduction in Sources numeric code without an explicit NaN decision (an allowlist with reasons), with fixtures and LIMITS, git-less.
5. CHANGELOG for behaviour changes. Ledger 0 problems.

## Order
After T15 and T14 phase 3 merge. Before P02/D02.
