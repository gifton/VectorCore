# Q02 — Explicit precision contracts and opt-in calibration

Root design candidate; independent review required before dispatch. Dependencies Q01, N01 and E05 are accepted. Read the six historical NUM-16/17/19/20/21/24 claims in the canonical audit, plus reports/Q02-root-investigation.md and Q02-kernel-tuner-inventory.md. Breaking API changes are authorized. No production performance target, downstream intent, GPU execution or automatic Operations routing is introduced.

## 1. Actual adaptive distance bound

Keep the public width512 adaptiveEuclideanDistance signature. Define threshold as a nonnegative finite relative tolerance against the actual direct FP32 result `query.euclideanDistance(to: candidate)`, not against an exact real-number distance. Compute that reference once first. A zero or invalid (negative/NaN/infinite) threshold returns the direct result, without reduced conversion. Also return the direct result when it is zero or nonfinite. These nonthrowing fallbacks preserve direct FP32 nonfinite/range behavior; this task does not repair the baseline kernel.

For positive finite reference and threshold, both operands must contain finite values within the finite FP16 range before trying the existing one-candidate FP16 path. Return its result only when it is finite and `abs(Double(reduced) - Double(reference)) <= Double(threshold) * Double(reference)`; otherwise return the reference. The product is representable in Double for finite Float inputs. This final comparison, rather than range screening alone, enforces the observable bound. Threshold zero returns the exact baseline bits. Do not add an absolute-error floor to this public contract. Query/candidate reversal is covered independently against each ordering's direct baseline. Explicitly document the extra baseline computation and conversion/allocation cost: this is validated precision selection with no acceleration claim. Keep kernel arithmetic, SoA layout and ownership unchanged.

## 2. Quantized shape-only suggestion

Replace the misleading `selectOptimalQuantization(...accuracyRequirement:)` entry with throwing `suggestQuantization(for:dimension:candidateCount:relativeErrorHint:)`. The finite nonnegative hint expresses caller willingness to experiment with lossy storage; it is NOT an actual-data bound or calibrated prediction. Zero always suggests fullFP32. Validate dimension > 0, candidateCount >= 0 and finite hint >= 0 before cache lookup; invalid values throw VectorError.invalidConfiguration with the offending field. Empty input returns fullFP32. Preserve operation as an opaque identity string (no unsupported-operation claim).

Use this explicit heuristic: candidateCount > 5000 and hint >= 0.1 suggests bothINT8; otherwise candidateCount > 1000 and hint >= 0.05 suggests candidatesINT8; otherwise fullFP32. These are heuristic cutoffs, not measured accuracy thresholds. Use a typed key containing operation, dimension, candidateCount and normalized hint bits (both signed zero forms mean zero). Keep all cache accesses under the existing lock. Fresh/warm results must agree for every input permutation. A public per-instance initializer is allowed for deterministic independent consumers/tests; shared remains available. Do not touch quantization arithmetic, calibration ranges or decoded metrics accepted in Q01.

## 3. Mixed tuner selection never performs hidden calibration

Keep MixedPrecisionStrategy and the shared actor, and add a public initializer for isolated instances. Replace `selectOptimalStrategy(...accuracyRequirement:)` with throwing `selectStrategy(candidateCount:maximumSyntheticRelativeError:dimension:)`. Validate supported widths 512/768/1536, nonnegative count and finite nonnegative error before any key/override/profile work. A zero count or zero synthetic error limit returns fullFP32, without conversion/calibration. On a cache miss return fullFP32. Selection must perform zero data generation, conversion or kernel invocations. This is an explicit first-call behavior change.

Move the current synthetic benchmark behind explicit public `calibrate(candidateCount:dimension:iterations:warmupIterations:) async throws -> [StrategyMetrics]`; make the existing metrics type a public read-only value with documented units. Defaults may retain 20 measured/5 warmup iterations because the call explicitly requests calibration. Validate iterations > 0, warmups >= 0, count > 0, supported dimension, checked count+1, checked dimension/payload products, and checked total execution count before allocation. Caller chooses calibration size/counts; no arbitrary production envelope is inferred. Check cancellation before generation, between generated vectors, before/after warmup or measured execution and before publication. There is no hard time deadline and synchronous kernels are not interruptible. Accumulate calibration results locally and publish once after the final cancellation check; cancellation or failure before that point preserves all prior profiles and overrides. Cancellation arriving after publication does not roll back the committed result. Apply the same commit-point rule to KernelAutoTuner.

Compute the FP32 baseline once per calibration; benchmark each of the five strategies exactly warmups+iterations times, with no extra fallback rerun. Keep the current conversion-inclusive mixed benchmark: each reduced invocation performs its required query/candidate conversion, and fullFP32 performs none. Record that boundary, deterministic seed, sample counts and a profile algorithm version in the metrics/cache record. Selection filters only finite, semantically valid profiles with max synthetic error <= requested limit, then uses a finite quality score with a deterministic strategy-order tie break. If no compatible profile qualifies, return fullFP32. Reuse the profile family for exact dimension/count across different error filters; all decision inputs remain operative on every lookup. Do not quantize count into workload buckets.

Define synthetic error as `abs(Double(result)-Double(reference)) / max(abs(Double(reference)), 1e-6)` on the generated calibration dataset only. Reject nonfinite result/reference/error/latency/throughput, negative errors and nonsensical metrics. Use widened subtraction, and change StrategyMetrics maximum/mean error fields to Double so a Float round-down cannot weaken the comparison; convert the validated Float caller limit to Double for filtering. Empty calibration is rejected before division. Do not force-unwrap a maximum of an empty list. Use a monotonic clock on all supported platforms; the existing platform floors allow ContinuousClock. Deterministic random input does not promise deterministic timing.

Manual reduced overrides may select only a valid cached profile for the exact dimension/count that meets the current requested synthetic error limit; otherwise throw invalidConfiguration without publication. FullFP32 override is always compatible after input validation. Apply the same rule again at selection so a cache update cannot invalidate a previously accepted override silently. Keep clearCache clearing profiles and overrides. Rename override accuracy label consistently. Zero error/count cannot be weakened by an override. No manual override establishes arbitrary-data accuracy. Per-instance counters/observer seams may verify work but must be immutable or actor-owned and inactive for normal callers; no process-global hooks.

## 4. Kernel resource filters and precision precedence

Keep the kernel strategies and precision modes, but remove the false universal error percentages. Full mode permits only cpuAoS/cpuSoA; fp16Acceptable also permits cpuMixedPrecision; int8Acceptable additionally permits cpuQuantized. These modes permit storage representations, not bounded numerical error. Reject `.auto` as a manual override/profile result. Override/profile/heuristic paths must all pass the same compatibility predicate.

Replace WorkloadCharacteristics.memoryBudget/latencyTarget and their initializer labels with `maximumEstimatedPayloadBytes` and `maximumProfiledMeanLatency`. The first filters the checked scalar query/candidate payload estimate; the second filters the recorded synthetic dot benchmark mean. They are NOT allocation/RSS caps or runtime latency deadlines. Validate optional byte limit >= 0 and optional latency finite > 0, supported dimension and count >= 0 before selection, overrides or profiling. Negative counts/overflow cannot reach loops or allocation. Selection and override setters become throwing; invalid input uses invalidConfiguration, and no strategy satisfying all operative filters throws resourceUnavailable with a `noFeasibleStrategy` diagnostic. No constrained request silently falls back to an infeasible strategy.

Override setters validate all inputs and require a compatible, feasible strategy before replacing any prior override. A rejected setter leaves profiles and the prior override untouched. Selection revalidates a stored override: if a required matching profile no longer qualifies after recalibration, throw resourceUnavailable/noFeasibleStrategy rather than silently ignore the override. Incompatible stored values are invalidConfiguration. Selection order: validate/load; use a revalidated explicit override when present; otherwise rank compatible valid profiles under both filters; otherwise use feasible heuristic candidates only when no latency filter was requested. With a latency filter, a valid matching measured profile is mandatory, including for an override. For a payload-only filter, use checked formulas even without profiles. Prefer the existing unconstrained heuristic when feasible, then the remaining permitted strategies in a documented fixed order. Zero batch selects cpuAoS when unconstrained; a latency-constrained zero workload has no valid measured profile and reports noFeasibleStrategy. Profiles may be keyed by the complete workload (including normalized filter values), or by a typed measurement key with all decision filters re-applied on every selection; do not use an ambiguous string/hash as exact identity.

Rename PerformanceProfile.memoryFootprint to estimatedPayloadBytes and accuracy to syntheticAccuracyScore. Preserve and document the current estimates: full `(N+1)*D*4`, mixed `D*4+N*D*2`, INT8 `(N+1)*D`. They exclude headers, parameters, padding, output and simultaneous calibration representations. This is a deliberate proxy. Reject an unrepresentable estimate as invalidConfiguration before work. Valid profiles require finite positive throughput/latencies, finite accuracy score in [0,1], positive estimate, monotonic percentiles, finite timestamp, compatible workload/strategy/provenance, and measured sample count > 0. Fix nearest-rank percentile indexing using ceil(p*n)-1, clamped only after a valid nonempty sample count. The score must be finite for accepted profiles; an all-invalid cache cannot yield an arbitrary max element.

Keep explicit KernelAutoTuner.profileWorkload but make validation/errors/cancellation observable through async throws. Check cancellation before generation, between generated vectors, before/after every warmup or measured execution, before accuracy evaluation and before publication. Build new profiles locally; cancellation or calibration failure leaves previously published profiles and overrides unchanged. A successful call publishes all valid newly computed profiles together; if no valid profile remains, throw operationFailed and retain the prior cache. A load of previously persisted profiles is not publication of new calibration results. Validate iteration/warmup/count arithmetic before generation; zero-batch profiling returns an explicit invalidConfiguration error. Kernel profiles measure synthetic DOT operations. Retain the current boundary (FP32 input and preconverted reduced candidates generated outside timing; cpuSoA convenience includes packing per execution) but record it honestly and never compare these to preconverted SoA serving latency. Generate only representations needed by permitted strategies; fp32Full must not construct FP16/INT8 data. Accuracy is the existing synthetic mean normalized error score versus FP32 AoS, with subtraction widened before arithmetic and nonfinite values rejected. No universal numerical accuracy claim.

`selectMixedPrecisionStrategy(for:maximumSyntheticRelativeError:)` becomes async throws. Precedence is explicit: validate the workload AND finite nonnegative supplied synthetic limit; then reject any resource-filtered request with unsupportedOperation (including full mode); then return fullFP32 for full mode without consulting either tuner's override/profile. For the filtered-request rejection: a dot profile cannot certify the mixed Euclidean method's latency/payload. For reduced modes without those filters, delegate to the mixed selector with the explicitly supplied synthetic limit (default 0.001); this path also performs no calibration. Document full-mode early return and the filtered-request error clearly; no normal Operations dispatch changes.

## 5. Explicit persistence and immutable pool purpose

KernelAutoTuner gains public `init(persistenceURL: URL? = nil)`; shared and the default initializer are memory-only. A supplied URL opts into persistence. Remove environment/test/CI cache bypasses and implicit Application Support creation: the same in-memory selection logic runs in tests and ordinary consumers. Overrides are intentionally process-local; remove the restart-persistence promise. Add throwing clearCache(removePersistedProfiles: Bool = false). A normal reset clears in-memory profiles and overrides and marks this instance loaded, so it does not immediately reload old disk records; a new instance can still read those records. With true, first remove only the configured profile file if it exists, then clear memory. A deletion failure throws operationFailed and preserves in-memory profiles/overrides. Memory-only instances treat true like false. Do not delete directories or unrelated files.

Persist a versioned envelope with profile algorithm version, operation/conversion-boundary identifier, deterministic dataset version/seed, architecture, hardware model, processor count and OS version. Use existing Foundation/Darwin facilities; preserve platform floors and no new dependencies. If a stable hardware model cannot be obtained, disable disk reuse with an explicit documented status rather than pretending an unknown identity is compatible. Profile fields retain sample counts/timestamp. Equality of provenance is required before use; legacy/unversioned, mismatched or semantically invalid records are cache misses. No fixed performance freshness/expiry guarantee is invented. Provide an internal immutable provenance override for deterministic incompatibility tests, not a global environment switch.

Load before both selection and profile publication so profile-first cannot overwrite unloaded keys. Use an atomic complete-file write after successful publication. Missing file means empty cache; decode/schema/envelope-provenance failures invalidate the entire file; an individually semantically invalid profile is discarded while other valid compatible profiles remain usable. Surface other read/write I/O errors as VectorError.operationFailed (profile computation can succeed but persistence failure must not be falsely reported as persisted). Publish computed profiles to memory before the attempted save; a failed save throws operationFailed but retains those computed profiles in memory and leaves existing overrides unchanged. The error must explicitly distinguish successful in-memory calibration from failed persistence. Selection can subsequently use the in-memory result; there is no automatic rollback or disk-success claim. Multiple instances writing one URL are not a coordinated multi-writer store; document one owner per URL. No synchronization service or file-lock feature is added.

FP16VectorPool continues to cache immutable values. Remove conversion-destination reuse, GC, 80–90% allocation elimination, lock-free and unmeasured contention claims. Document that new values require normal construction and that acquire/release use NSLock; O(1) operations follow the bounded pre-reserved array. No mutable scratch, getter/borrow rewrite, allocation speed claim or O05 ownership dependency is introduced by this wording repair.
