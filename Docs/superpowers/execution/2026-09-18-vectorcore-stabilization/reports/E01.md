## Behavior and scope

Batch process validates the consumed effective batchSize before routing and bounds partition ends by remaining count. Nil still consumes immutable defaults, with an isolated control that sets live defaultBatchSize to0 and observes valid nil processing. No configuration redesign or scheduling change.

All five CPU methods and all five protocol defaults validate representable range length before count/allocation/work. Explicit minChunk must be positive before empty/serial/parallel/nested routing, including defaults that retain their existing scheduling selection. Remaining-count partition ends and quotient/remainder ceiling division avoid intermediate overflow. Hardware doubling saturates before multiplication. Existing CPU initializer settings and reduction laws remain unchanged.

Loop helpers precondition nonnegative count and positive width before work; arbitrary widths use bounded groups/ranges, preserving rethrows. No performance claim.

## Independent behavioral oracles and matrix

ExecutionBoundaryTests uses Array(range) and Array(0..<count) as independent coverage oracles. ForEach visits are locked and sorted, never ordered by execution. Reductions use empty-array identity, sort output, and separately mark rangeWork/combine callbacks to detect callbacks on empty input. Giant representable reductions return only range.count and sum identity0; they never iterate huge contents. Nonidentity initial/completion order are excluded (E02).

- Batch: N0/1/999/1000; batch0/-1/1/N+1/Int.max; doubled output cardinality; exact-once input visits; ordered results; no invalid/empty callback; nil default controls; transform sentinel errors.
- Providers: five helpers; CPU sequential/parallel/automatic threshold1/automatic threshold3; default conformer maxThreads0/-1/1/Int.max; empty ranges at0/Int.min/Int.max, 0..<2,1..<3,-3 ..< -1, near both integer endpoints; method hints1/256/Int.max. Invalid hints0/-1 include nested and empty/nonempty routes. Unrepresentable Int.min..<Int.max is tested across all helpers/providers with no callback.
- Additional huge representable range reduction: lengths Int.max starting0 and Int.min; CPU sequential/parallel/automatic and defaults maxThreads0/-1/1. Both reduction overloads. Default maxThreadsInt.max is limited to tiny ranges to avoid enormous per-item/task scheduling.
- Loops: widths1...17 x counts0...40, synchronous error stopping first/interior/tail, negative count and zero/negative widths including empty work; vectorized count/widthInt.max is one range; unrolled giant width throws immediately.
