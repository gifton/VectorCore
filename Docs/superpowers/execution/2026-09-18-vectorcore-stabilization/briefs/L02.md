# L02 — Consistent widened PCA centering and bounded sketch dimensions

Root-approved design after independent review. Dispatch only after accepted L01. Read canonical NUM-10 (qualified numerical-quality opportunity) and API-20 (actual oversampling overflow), current PCA.swift, PCATests and the UMAP/KNN callers. Do not relabel the qualified offset finding as an unconditional relative-accuracy violation. Breaking source changes are authorized; downstream validation remains separate.

## Model and centering decision

Change public PCAModel.mean from [Float] to [Double]. Store the actual widened center used by fitting; uncentered models store exact Double zeros. Public components, projections, explainedVariance and explainedVarianceRatio remain Float. No Codable/binary format or public model initializer exists to migrate. The source migration is explicit: callers reconstruct in Double or deliberately round the exposed mean; do not silently maintain a rounded public mean while fit/transform use another undisclosed center.

Compute each centered column mean with deterministic compensated Double accumulation of the original Float values and one Double division by sample count. Double can represent every Float input; this prevents the specific early Float rounding in NUM-10, but does not promise an exact mean for arbitrary sample sizes/order or universal translation invariance. Center every coordinate as Float(Double(input)-mean[j]) using the same internal helper in fit, single-vector transform and batch transform. Do not round mean to Float before subtraction. The centered matrix remains Float and existing provider/SGEMM routing remains unchanged; ordinary Float residual rounding, including underflow to zero, is allowed. No new Float64 factorization or entire-PCA precision mode.

Validate finite input coordinates after structural shape checks. Reject NaN/infinity with invalidData consistently in public fit and both transforms. If finite input/center subtraction produces a residual outside finite Float, throw operationFailed with a PCA-centering diagnostic before factoring/projecting. Successful public model statistics and projected coordinates must be finite; reject nonfinite public-result conversions with a stage-specific operationFailed diagnostic rather than returning Inf/NaN. This is a finite-result boundary, not a promise to recover from every Float GEMM intermediate overflow or cancellation; no new matmul kernel is authorized. L01 backend errors propagate without relabeling their identity. Center=false retains raw input residuals and zero mean.

Compute total variance from the actual rounded centered Float matrix using Double sums/squares as today, and compute spectra-derived variances in Double before checked Float conversion. Explained-variance ratios retain the existing zero-total -> zero policy; do not clamp them to manufacture an accuracy guarantee. Sign convention, component ordering, provider TaskLocal override, seed consumption, exact/randomized path selection and Swift rank-deficient basis caveat remain. Correct the header's contradictory claim that no full n*d factorization is ever formed despite exact fallback, and remove unsupported corpus-speed promises. Fix adjacent claims that Double accumulation alone guarantees stability at a production sample size; name the new finite-aware translation tests and state the remaining Float-panel limitation. No new speed/scale-readiness assertion.

Single and batch transforms must use identical per-coordinate centered values. Their existing Float reduction/SGEMM orders may differ, so require numerical agreement with justified tolerances rather than universal bitwise projection equality. Keep the batch GEMM and single streaming API; no repeated model fitting, separate approximate center, projection-derived recentering or result-mean subtraction.

## Shape and sketch arithmetic

Keep nonnegative oversampling and powerIterations validation. All nonnegative Int oversampling values, including Int.max, are accepted: after validating k within the existing centered/uncentered rank bounds, let limit=min(n,d), remaining=limit-k and sketchWidth=k+min(oversampling,remaining). No k+oversampling occurs before clamping. Oversampling at/above remaining selects the existing exact thin-SVD fallback. PowerIterations is still a count with no new arbitrary cap; exact fallback does not iterate it. The randomized path's runtime remains caller-chosen and no cancellation/deadline is added to these synchronous APIs.

Add pure internal checked shape/count helpers in PCA.swift for fit, flatten and transform. Validate n>=2 for fit before n-1, positive dimension, component bounds, nonnegative config, and valid internal flat-buffer count before indexing/allocation. Preserve public n<2 invalidOperation, invalid components/config invalidDimension and ragged input dimensionMismatch. Reject dimensions/counts unrepresentable for current LP64 BLAS (n/d/k/sketchWidth above Int32.max), and checked products/Float element-byte counts before every PCA-owned flat/result/sketch allocation or LAMatMul call. Check n*d, n*sketchWidth, d*sketchWidth, k*d and n*k as applicable. Use Double element width for the stored mean allocation and Float width for PCA panels/results. These are representability checks, not successful allocation or memory-budget guarantees. Transform validates its own batch size against the same BLAS dimension/count boundary; empty batch still returns [] without computation.

Typed internal failures: invalidDimension for invalid n/d or count/product/byte representability and flatten n != vectors.count; dimensionMismatch(expected: checked n*d, actual: flat.count) for a structurally valid fit buffer with the wrong element count. Preserve the explicitly stated public n<2/config/component/row-shape ordering.

flattenColumnMajor is shared by KNNGraph.bruteForce. Preserve its valid n/d behavior and Float values; validate n==vectors.count and a representable n*d before allocation. Shared flatten checks only count/domain and Int/Float-byte representability; PCA entry points separately enforce LP64 limits. Do not introduce PCA-specific centering or nonfinite rejection into KNN's shared flatten call; PCA performs its own finite check. Document this shared shape change and run ordinary KNN/UMAP controls. Inventory current callers before edits; do not modify KNN/UMAP algorithms or their numeric policies. LAMatMul itself remains unchanged; the new checks establish the touched PCA caller preconditions, not arbitrary unsafe/internal calls.

## Independent tests and RED

Establish actual unchanged-production NUM-10 RED using [0,2] and exactly representable [16777216,16777218], under both default and explicit Swift providers after L01. Expected mean offset+1, sample variance 2 and projected values [-1,1] (respecting the documented sign convention), projected mean zero and equal ratios follow independently in Double. Include public fit+single transform, fit+batch transform and Operations.pca; do not validate only fitted components. An API typecheck fixture also demonstrates the public mean type migration separately from numerical RED.

Extend to exactly representable signed/power-of-two translations of multi-column data with known nondegenerate covariance and full-rank axes, ordinary random-offset controls, centered=false, zero/constant columns and a randomized sketch route with fixed seed. Compute covariance, residual mean and normalized reconstruction in independent Double loops from the original Float coordinates; avoid max/zip checks that hide NaN/shape mismatches. Analytic tiny fixtures are primary; backend parity alone is insufficient. Use explicit Float-output ULP/relative allowances tied to residual/projection rounding. Do not claim arbitrary offset invariance where input translation already loses representable differences.

Actual bounded-child RED for Int.max oversampling on two one-dimensional samples must preserve trap evidence before repair. Final oversampling matrix covers 0, normal, remaining-1/remaining/remaining+1 when meaningful, Int.max and negative values on tiny exact/randomized-eligible shapes. A TaskLocal forwarding provider spy records QR/SVD dimensions/call counts to prove exact fallback, and a hostile provider error verifies propagation. Int.max powerIterations may be exercised only on exact fallback; never run a huge randomized loop. Pure shape/count tests cover Int32/Int products and byte boundaries without allocating huge matrices or invoking BLAS. Internal malformed flat-buffer/row-count tests must fail before indexing.

Finite input/output boundary tests cover fit and both transforms, uncentered inputs, residual overflow, variance overflow and ordinary finite controls; preserve original input arrays. Keep those new strengthened contracts separate from historical NUM-10/API-20 claims. Update only actual mean-type consumers in PCATests with widened reconstruction/reference arithmetic. New public non-@testable Swift 6 consumer reads [Double] mean and exercises fit/single/batch transforms. Existing PCATests, factorization suites and small PCA-backed UMAP/KNN controls must pass.
