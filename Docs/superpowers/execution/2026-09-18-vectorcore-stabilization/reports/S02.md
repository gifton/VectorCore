## Behavior and migration

Three binary mutator defaults reject unequal scalarCount before either borrow. Existing VectorFactory arithmetic remains unchanged; separate tests cover its concrete operator route. Root explicitly approved `guard`/`fatalError` spelling for new nonthrowing precondition checks, extending S01's observed Release diagnostic decision. Negative random/zeros/ones/pattern dimensions fail at those named boundaries before ranges, allocation or pattern evaluation; zero remains valid.

`Operations.centroid(of:)` and `Operations.statistics(for:)` are now throwing APIs. Both scan every row's scalarCount before accessing any payload and check actual array counts at existing toArray boundaries. No O(ND) retained row copy was introduced. Empty centroid throws `.insufficientData` for fixed and dynamic types; nonempty zero-dimensional input yields a zero-dimensional centroid. Empty statistics retains all-zero/empty summary semantics; nonempty zero-dimensional rows retain their input count and have zero magnitude summaries without provider work on empty payloads. Existing callers in ExecutionOperationsTests use try/throws. Other aggregate APIs, including SyncBatchOperations, are unchanged.

Centroid and normalize now propagate generic factory errors unchanged using try. Normalize remains independently per row, permits differing row dimensions, and returns empty for empty input. No numerical normalization or stable-statistics algorithm changes were made.

Single vector construction rejects negative dimensions as `.invalidDimension` before count matching, permits dimension 0 with empty data, and retains mismatch errors otherwise. Batch rejects dimension <= 0 before modulo/division (including empty data); positive dimension with empty values returns []; nonmultiples retain `.invalidData`. Basis rejects nonpositive dimension before index error construction, then retains bounds checks. optimalDimension clamps endpoints before subtraction, covering every Int and retaining smaller-width ties.

EX03 was separately approved after baseline `basis(dimension:Int.min,index:0)` exposed overflow in error construction. The public indexOutOfBounds helper now uses max_index=-1 for any nonpositive dimension; positive dimension retains dimension-1. Error family/code, original dimension/index message and index metadata remain intact. Only previously invalid negative-dimension max_index metadata changes; no wire/storage layout or encoded vector format change.

S01 storage/count guards and I01 normalization-hint invalidation remain unchanged. Custom conformers must still report truthful scalar/buffer shape as documented by S01; S02 additionally validates their materialized arrays at aggregation boundaries. There is no new allocation budget or numerical range guarantee.
