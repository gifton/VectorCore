# Q02 independent design review

**Verdict: favorable design, pending four concrete contract clarifications before dispatch.** This is design-only review, with no implementation or runtime claims. Reviewed candidate Q02, prior tuner inventory, canonical NUM-16/17/19/20/21/24 and relevant current tuner/pool declarations. Breaking migration is authorized; none of the findings asks to retain misleading old APIs.

## Decisions to bind before dispatch

1. **Full precision versus filtered mixed integration.** Section 4 says validate, return fullFP32 immediately for full mode, and reject resource-filtered requests. A full-mode request carrying a resource filter meets both descriptions. Specify which wins (the written early-return order suggests full wins, with the filter explicitly inapplicable to this representation-only answer), and explicitly include validation of the supplied maximumSyntheticRelativeError before any return. Otherwise implementations/tests can disagree on full+filter and full+invalid-limit requests.

2. **Kernel override failure and fallback.** “Consider only a compatible and feasible explicit override; otherwise rank” implies ignoring a later-invalid override, whereas the mixed tuner explicitly throws when its override becomes invalid. Distinct policies are possible, but bind the Kernel policy: invalid setter must not replace a previous valid override; specify its error kind, and say whether a profile update that invalidates an existing override causes a selection error or fallback ranking. Rejecting `.auto` and applying the compatibility/filter predicate are already clear. This matters when a latency-qualified override loses its valid measured profile after recalibration.

3. **Persistence/reset observable state.** Section 5 expressly leaves the failed-save in-memory state and cache-reset disk effect to be stated. Choose these before implementation: whether successful computed profiles remain selectable after a thrown write error; whether the old file remains authoritative; which profile/override state reset removes; whether reset removes only the configured file or atomically writes an empty envelope; and what remains after reset I/O failure. This can be a small best-effort persistence policy, not a transaction service. Require corresponding deterministic failure/reconstruction tests. Existing atomic file-write use does not itself define in-memory publication behavior.

4. **Cancellation publication boundary for both tuners.** The mixed section supplies useful checkpoints, but should explicitly state cancelled calibration leaves prior profiles and overrides unchanged. Apply the same concrete checkpoints to Kernel profileWorkload: before generation, between generated vectors/representations, around individual warmup/measured executions, and immediately before publication. Define cancellation observed before publication as no publication; do not promise rollback for cancellation arriving after the commit point. Existing synchronous kernels remain noninterruptible. “Cancellation observable” alone in the Kernel section does not bind this behavior sufficiently for executable acceptance.

## Sound parts and coverage

The adaptive comparison is a sound observable relative bound against the actual FP32 baseline, not real arithmetic. Widened Float differences and the product of finite Float tolerance/reference fit Double. Zero/invalid tolerance, zero/nonfinite baseline and finite-range screens make the fallback explicit. Near ties and operand reversal each use their own reference; no arbitrary-data claim is borrowed from representability or synthetic calibration. Baseline computation costs are honestly stated.

The quantized suggestion has a deterministic shape-only meaning, complete typed cache identity, normalized zero hint, validation before cache work, and explicit cutoff neighbors. It no longer masquerades as an error guarantee. Operation remains opaque identity; no unsupported operation dispatch is implied.

Mixed selection has a coherent separation from explicit calibration: no work on lookup/miss, exact dimension/count profile family, current error filtering on every selection, compatible overrides, full zero/count precedence and deterministic score tie-break. The reference-once plus five times warmup/iteration count is testable without fallback reruns; test accounting should separately report the one baseline invocation. Store/compare maximum synthetic error without rounding it downward across the requested limit (Double metrics are a straightforward option); if retaining Float fields, define conservative conversion. The synthetic denominator floor is permitted here and deliberately absent from the adaptive bound.

Kernel resource fields describe filters on a payload proxy and measured synthetic mean, not hard execution guarantees. Requiring a measured compatible profile for a latency filter avoids a fabricated heuristic latency promise. Payload arithmetic is checked before work. Profile validation, monotonic percentile requirements, finite scores and invalid-cache fallback eliminate arbitrary selection from unusable records. The fixed fallback strategy ordering must be documented by the implementation, as required. Complete precision compatibility across override/profile/heuristic paths closes the known full-mode bypass.

Opt-in URL persistence, no environment bypass, provenance equality, load-before-profile-publication and process-local overrides directly address the ordinary-path gaps found in the inventory. The external A-then-B-before-selection roundtrip is the correct reachable persistence oracle. Schema/provenance/semantic invalidation is distinct from I/O failure, and unknown hardware status is honestly limited. Multiple writers are explicitly outside the contract.

Scope stays within the four owned tuner/adaptive/documentation areas and necessary migration/test support. The identified unawaited memory tests and leaked override need migration as stated; no sibling runtime dependency has been established. FP16 pool wording correctly remains about immutable values, with no mutable conversion destination or unmeasured allocation-elimination assertion.

Acceptance is feasible with separate semantic injection tests, actual small calibrations at each width, public ordinary-environment consumers, and bounded subprocesses. Baseline seams that did not exist must not be fabricated. Release timing/allocation evidence and a supported peak-live measurement remain distinct; functional removal of hidden work does not establish a workload latency target. No build, benchmark, source edit or API redesign was performed for this review.

## Scoped revised-design verdict — ACCEPT

Re-read the complete revised brief (SHA256 `36805606eebf1126344c0f015524141d990b72ff9eef1dbb6bcb436464ae9cae`). **ACCEPT design-only; no remaining contract blocker found.** All four pre-dispatch decisions and the error-metric rounding clarification above are resolved.

The integration order now validates both workload and synthetic limit, rejects every resource-filtered request including full mode, then honors full precision without tuner consultation. Kernel override setter rejection preserves existing state; selection revalidates stored overrides and reports the specified incompatibility/no-feasible error instead of silently ignoring them.

The reset contract specifies memory-only versus configured-file removal, loaded-state behavior, and failure preservation. Calibration publishes to memory before saving; persistence failure explicitly reports that distinction and retains the computed profiles and existing overrides. Envelope/schema/provenance invalidation and individual invalid-profile rejection now have distinct scopes.

Both tuners stage calibration results and check cancellation before the publication boundary; pre-commit cancellation/failure preserves prior state, while post-commit cancellation does not undo publication. Kernel checkpoints and the empty-valid-profile error are explicit. Mixed maximum/mean synthetic errors use Double, comparing against the widened validated Float limit, eliminating the identified downward-rounding weakness.

The selected full-plus-filter policy differs from the suggested ordering in the initial finding but is consistent and executable as written. No implementation, runtime result, performance target or downstream behavior is accepted by this design verdict. No builds or source changes were performed.
