## Dimensionless output-curve fitting

Keep the 300-point grid and target curve, but fit in t=x/spread on [0,3], r=Double(minDist)/Double(spread). Target is1 for t<r and exp(-(t-r)) otherwise. Fit f(t)=1/(1+alpha*t^(2*beta)) in positive log parameters A=log(alpha), B=log(beta); x=0 gives exactly1. Compute logistic f stably from ell=A+2*exp(B)*log(t): use exp(-abs(ell)) with sign-specific algebra, avoiding overflow in exp(ell). Its Jacobian is df/dA=-f*(1-f), df/dB=-2*beta*log(t)*f*(1-f). Accumulate Double SSE/JtJ/Jtr in deterministic grid order.

Retain a small deterministic two-parameter damped Gauss-Newton/LM solver: initial A=B=0, lambda=1e-3, accept only finite lower-SSE steps, decrease lambda by3 to floor1e-12 on acceptance, increase by10 on rejection. Check positive finite determinant and candidate beta; invalid trials are rejected rather than published. At most200 iterations. Convergence requires finite gradient infinity norm <=1e-8 in these dimensionless log coordinates, including a final explicit check; this is an engineering stationarity criterion, not a global-optimum proof. Exhaustion, singularity or stalled damping without meeting the criterion throws operationFailed. Never silently return the initial guess after unsuccessful fitting. Root's pure-Python design feasibility values for nine ratios are in L03-curve-design-probe.json; they are not an independent production oracle or runtime RED/GREEN.

Return the existing Float (a,b) representation, now through a throwing internal function. Round beta once to a positive finite Float b, then map log(a)=A-2*Double(b)*log(Double(spread)) so the physical curve uses the returned exponent. Require finite positive representable Float a/b. Verify the returned pair's dimensionless curve over the same grid using log(Double(a))+2*Double(b)*log(spread), with max absolute deviation from the converged Double curve <=64*Float.ulpOfOne. This permits sufficiently accurate subnormal coefficients and rejects underflow/coarse-quantization/overflow that would destroy the fit. Unsupported finite coefficient ranges throw operationFailed with a range diagnostic; invalid input config uses the config errors below. Do not silently clamp a/b or widen the public contract to every positive Float spread.

Independent reference fixtures must use a different solver (e.g. a retained deterministic derivative-free Nelder–Mead script over the same dimensionless objective, optionally cross-checked against an official scientific implementation). Assert finite parameters, dimensionless curve and SSE near the independent minimum, b invariance and mapped a scaling over exact power-of-two scale families with representable input ratios. Cover r=0/.1/.5/1 and interior controls, extreme supported coefficients and explicit unrepresentable failures. Default values should remain numerically consistent with the documented target, not necessarily bitwise identical to the old faulty fit. A scalar formula copied from the implementation is not an independent minimization oracle.

## Smooth-kNN calibration

Keep rho as the smallest strictly positive stored row distance, or0 if none. Distances are finite/nonnegative by checked KNNGraph construction. k is the stored row entry count, including duplicate neighbor IDs as today; target=log2(Double(k)+1), avoiding integer k+1. Isolated rows keep rho=sigma=0. Return and consume rho/sigma in Double through membership evaluation; do not narrow sigma to Float and then interpret underflow as certainty.

Let delta=max(0,Double(distance)-rho), z=count(delta==0). If z>=target, no strictly positive bandwidth can lower the sum below z; choose pre-floor sigma0 as the explicit limiting/equality policy. This handles tied/duplicate/k1 rows without pretending they solve an impossible target. Apply the existing floor afterward:1e-3 times row mean when rho>0, otherwise global mean. All-zero graph/row and isolated behavior is explicit. Duplicate IDs remain separate observations for calibration and are merged by max during fusion; document this existing distinction.

For z<target, a finite positive root exists. Normalize positive deltas by s=max(delta)>0 and solve for log(tau), sigma=s*tau. Set the upper tau bound to2: F(2)>=1+(k-1)*exp(-1/2)>=log2(k+1) for integer k>=2; the k2 margin is positive and the left-minus-right derivative is positive thereafter. Choose residual tolerance=1e-5*max(1,target), epsilon<=min(tolerance/4,(target-z)/2) with0<epsilon<k-z, and lower tau=minPositiveNormalizedDelta/(-log(epsilon/(k-z))). Thus the lower sum is <=z+epsilon<target. Evaluate memberships with exp(-exp(log(normalizedDelta)-log(tau))) and unit contributions for zero deltas. Verify actual bracket inequalities/finite values; a tolerance-close endpoint may be accepted explicitly. Bisect the log interval for at most64 steps, stop only on the finite-aware residual criterion, and throw operationFailed if unmet. This logarithmic bracket handles within-row Float exponent spreads that a linear64-step search cannot resolve.

Compute physical sigma in Double and apply the same local/global floor. Positive Float distance differences and their finite dynamic range keep this chosen Double domain representable; still check all finite/positive results before publication. A floor-dominated final sigma need not satisfy the target equation; tests must identify that policy separately from a solved unfloored row. If sigma==0, membership is1 for delta<=0 and0 for delta>0. Never use sigma==0 as unconditional membership1. Fusion, canonical key ordering, duplicate max and probabilistic union remain; check weights finite in[0,1], with existing Float rounding/underflow-to-zero edge dropping. No storage architecture rewrite here (L04).

Make smoothDistances/build throwing internally so explicit calibration/arithmetic failures reach public umap. Migrate actual tests/callers. Preserve rho, sigma and membership scale behavior under exact representable common distance scaling; verify topology and weights, not an entire stochastic layout equivariance claim. Include unequal row degrees, isolated rows, duplicates/ties, all-zero rows, floor-dominated rows and solvable near/extreme-scale rows. Use analytic two/three-level distance equations and independent Double/log reference bisection or high precision. Require root residual only where solvable and not changed by the floor. Retain actual baseline small/large-scale failures before editing production.

## Config, integer and storage boundaries

Both public umap overloads must validate every floating option for finiteness: spread>0,0<=minDist<=spread and learningRate>0. NaN and either infinity are rejected with existing invalidOperation config diagnostics before graph building, PCA or initialization. Preserve neighbors>=2, epochs>=1 if supplied, negativeSampleRate>=0. Effective epochs default remains500/200 as today. Irrelevant fields keep their documented validation policy consistently across overloads.

The Double schedule must distinguish unit epoch/count steps. Define an explicit representability domain: effective epochs and negativeSampleRate are <=2^53-1 (or native Int.max if smaller), and the checked product effectiveEpochs*max(1,negativeSampleRate) must fit that exact-integer Double bound. Reject violations with invalidOperation before any layout iteration. This is a numeric scheduling domain, not an execution-time budget; large accepted counts can still be expensive. Compute the annealing fraction in Double before Float projection. Do not execute huge accepted loops in tests; test pure preflight at boundaries. Int.max cases must be rejected promptly on the current64-bit platform.

Before every floating-to-Int negative-sample conversion, verify finite nonnegative representable value and use a checked conversion of the intended truncated/floored count. A nonpositive due count skips work before conversion. Compute cadence as Double(maxWeight)/Double(weight), not a Float quotient widened afterward; validate positive finite cadence/negative cadence and finite updates. A runtime schedule arithmetic failure throws operationFailed rather than trapping. No unchecked integer multiplication/addition remains in touched output/edge-size or schedule setup.

Typed count policy: invalidDimension for n/d or allocation/index element/byte representability rejection, retaining invalidOperation for invalid config/schedule bounds, invalidData for malformed CSR/coordinates and operationFailed for runtime numerical failures.

Add shared internal pure checked count helpers for n*dimensions and element bytes before random/provided/PCA initial allocation, output indexing or layout. Validate graph point count>=2 early enough to avoid allocation for an impossible layout. Validate provided coordinate row count and every row width before copying. All supplied coordinates must be finite; invalidData identifies the rejected input. PCA initialization must use widened ratio scaling10*(Double(value)/Double(maxAbs)), not a Float reciprocal10/maxAbs; zero projection retains zero-plus-jitter. The resulting initial buffer is checked finite before optimizer entry.

Keep Float coordinates and existing SGD equations/gradient clipping, but make optimize and its update helpers throwing on a nonfinite difference, squared-distance accumulation, power, coefficient, unclipped gradient, step or updated coordinate. Check before clip4 can hide NaN. Ordinary finite underflow/zero cases preserve existing policy. A finite extreme initialization/learning rate may therefore throw an explicit operationFailed range diagnostic; no promise to produce a meaningful layout for all finite inputs. Public APIs only return finite coordinate buffers; internal inout optimizer mutation on failure is not transactional and is not newly promised to be. Input coordinate arrays remain unmodified by public calls. No whole-layout convergence guarantee.

KNNGraph initializer first validates ALL offsets are in0...edgeCount and nondecreasing, before using ANY row range to index neighbor/distance arrays. Preserve pointCount1...Int32.max, offsets count/endpoints, matching arrays, valid neighbor indices, no self-loops, finite nonnegative distances, unsorted/unequal/isolated rows and duplicate entries. Invalid CSR throws invalidData; no malformed interior offset may reach an array trap merely because the final endpoint is valid.

For bruteForce, check n/d against current LP64 BLAS bounds, n*k, n*d, blockRows*d, blockRows*n, n+1 and element bytes before allocation/Int32 conversion. L02 shared flatten only provides general Int/byte checks and does not establish these KNN-specific preconditions. Keep the current exhaustive Float Gram distance route and selection; do not rerank a truncated set or invent exact nearby-vector accuracy. Correct 'exact/reference builder' wording to exhaustive candidate enumeration with qualified Float Gram cancellation/overflow limitations. Retain the near-offset independently computed direct-distance fixture as documented characterization, not a new hidden implementation promise. A true direct/robust routing change remains P02-dependent and outside L03.

Check2*edgeCount/count/byte expressions before fused-array reservation and output construction. These are representability guards, not OOM recovery or a corpus memory budget. Preserve layout/ownership and deterministic per-build ordinary outputs for a fixed graph/initial/config; cross-platform bitwise reproducibility is not asserted.

## October 2 numerical ruling: objective comparison near stationarity

The retained v2 Swift trace for minDist word0x3e800000 and spread word0x3f333333 reaches gradient1.6307627121077417e-8; its next candidate has gradient1.1750166169915977e-9 but separately summed SSE rounds from .07993836493704175 to .07993836493704182, so the original comparison rejects it. This is an observed numerical comparison defect, not permission to weaken the convergence contract.

For v3, evaluate the algebraic objective change directly as the deterministic Neumaier-compensated sum of `(newF-oldF)*((newF-target)+(oldF-target))`, forming the two residuals separately. Require finite terms and result and strictly negative change. Equality, worsening, or nonfinite change still rejects the trial. Keep the Jacobian, exact gradient bound1e-8, 200-iteration limit, damping policy and Float coefficient fidelity checks unchanged. Add independent derivative-free reference minima for the exact `.5/1.5` and `.25/Float(.7)` input pairs and retain the actual v2 failure, diagnostic source and runtime records.
