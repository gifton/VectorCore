# V04 design review

**One design clarification required before dispatch: automatic cosine pairing conflicts with the approved V02 policy.** The measurement, memory-attribution and claim-maintenance design is otherwise coherent and appropriately bounded. This is design review only; no measurements/builds or source edits were performed.

## V04-DR1 — define the fused/preNorm pairing migration

V04 requires structured per-case inclusion flags in compatibility/pairing checks and says distinct scopes cannot form an automatic speedup pair. Approved V02 explicitly retains 18 default fused/preNorm cosine pairs, although preNorm preparation occurs outside timing while fused preparation is inside, and --ab-only requires complete supported pairs. These cannot simultaneously require equal measured-work boundaries and preserve the old cosine pairing/count contract. A display-only boundary annotation does not resolve which comparisons are allowed.

Minimal correction: choose explicitly whether V04 retires those automatic cosine pairs and updates V02's pair counts/--ab-only expectations, or retains a specifically named strategy comparison with both boundaries displayed and no equal-work/kernel-speed attribution. Keep strict cross-run case compatibility separate from this deliberate within-run strategy comparison. If the latter is chosen, the generic 'distinct scopes cannot form an automatic speedup pair' rule needs that narrow exception and tests proving arbitrary unrelated scope mismatches still reject. No change to the actual kernels is needed. This decision belongs in the brief before the implementer returns the concrete case/CLI inventory.

## Accepted design and bounded implementation details

The scope preserves V01's already-consumed reductions and disclaims historical DCE reproduction. Catalog-owned boundary metadata, explicit fixture/version migration, selection before setup, unavailable optional-route records, full matrix/batch result consumption and independent untimed correctness checks directly address TOOL-07. Separate consumer-only samples appropriately expose rather than subtract observation cost. Actual linked caller/object inspection plus retained commands/hashes is stronger evidence than toy emitted code; it still supports only the inspected routes. No instruction-level throughput conclusion follows merely from a surviving call or instruction.

The existing AoS provider path can allocate intermediate/output storage inside its API; a 'reusable-output counterpart excludes output allocation' label must apply only where the actual route has reusable output. It cannot silently promise an allocation-free AoS public provider path or authorize a new production kernel. The brief's explicit inclusion fields and requested path/case inventory can resolve this mechanically: distinguish caller output allocation from actual provider intermediates, and mark unsupported counterparts unavailable. All setup-inclusive companions should use the same requested metric and input fixtures as their relevant comparisons, and report the defined finite-aware numerical error statistic for FP16; the pre-edit inventory is the right place to pin those exact cases.

The memory design correctly separates handle stride, logical scalar payload, current allocator sums, current resident bytes and process-lifetime resident high-water. Retaining pre-creation high-water and refusing to subtract maxima avoids misattributing runtime warmup to the dataset. Summed zone high-water marks cannot establish simultaneous heap peak, and current deltas need the stated bookkeeping/direct-VM qualifications. A fresh process per shape/representation/sharing case, explicit keep-alive/release scopes and transient FP32-to-FP16 sources make the independent/shared experiments interpretable. This can close TOOL-08 with qualified process measurements; it must not be restated as object-precise peak heap or guaranteed 50% RSS savings.

The allocation-event probe remains distinct from memory snapshots and elapsed samples. Known C/Array/no-op controls and refusal to replace a live logger preserve existing O03 evidence limitations. The snapshot control should establish successful live observations and fixture execution, not insist on an exact positive RSS delta for a small allocation; the brief already forbids exact-delta assertions. Failures/unsupported APIs stay incomplete evidence rather than zero bytes. Checked width/count arithmetic is sufficient here; no new corpus budget is implied by N=1/257/4096 or timing fixtures.

The claim ledger's scope and lexical mutation tests are consistent with NUM-23/OWN-23. Record removed claims as historical/tombstone entries with an absent-current-statement expectation, rather than forcing their old fingerprint to remain a live anchor; retained/corrected statements must bind to the current source. A named test reference must identify an existing exercised test within its actual domain, not turn that test's existence into a universal guarantee. Full manual inventory remains required because the mechanical scanner is explicitly not a semantic proof system.

Dependency ordering is sound: V02 owns schema/catalog/driver groundwork, V03 owns strict-performance wrappers and test-name inventories, L01/L02 own factorization/PCA numerical wording, Q02/Q04 own tuner/mixed-wrapper behavior, and O02/O03/O05 provide accepted ownership controls. Final ledger reconciliation must follow those accepted implementations. V04 production changes stay comments only; measurement companions/model/consumer code are benchmark support. No hidden prefetch, allocator, numerical or scheduling rewrite is authorized. L04 may consume the measurement discipline later but its large-corpus envelope is not established by these bounded vector fixtures.

Acceptance must retain the proposed raw samples, repeat counts, per-sample-average statistic definition, exact boundaries, source/binary/object association and actual fixture markers. Nine averages and variation are descriptive, not proof of statistical significance. Root-reviewed finite deadlines for longer runs, bounded child cleanup and no status access after timeout satisfy the existing evidence policy. No new timing target, universal accuracy bound or downstream acceptance is introduced.

## Root resolution — design ACCEPT with specified brief amendment

Root explicitly resolved DR1 in the review exchange: preserve exactly V02's declared Euclidean/squared-Euclidean and cosine fused/preNorm families, with both boundary records displayed and family-specific allowed differences. Introduce a common top-level timing scope separating existing reused/prepared-input measurements from setup-inclusive measurements, and never pair across that scope. Require exact complete boundary identity for the same case across runs. Cosine is labeled a prepared-input strategy comparison with preNorm preparation excluded, without an end-to-end speed interpretation; the Euclidean family explicitly compares sqrt inclusion rather than identical numerical outputs. New companions require an explicit declared comparison and cannot auto-pair merely because they share a broad scope.

This is a coherent narrow resolution and preserves the V02 contract without weakening arbitrary scope-mismatch rejection. **Design ACCEPT on that explicit root decision**, subject to incorporating it in the binding brief before dispatch. At the time of this append the source brief still contained the superseded blanket same-operation/scope paragraph, so this report does not falsely claim the textual amendment was already verified. No further design blocker identified.

Re-read the amended on-disk identity and pairing paragraphs after root's follow-up. They now include the top-level scope, exact cross-run boundary identity, both explicit family exceptions and counts, full boundary display, preparation/sqrt qualifications and explicit new-companion pairing requirement. DR1 is resolved in the binding text. **Final design verdict: ACCEPT.**
