# T14 brief: metric overload/witness numerics consistency, and the stdlib-shadowing SIMD sum() (root-created; from P01 phase E and T12 phase 1)

## Findings
- `Sources/VectorCore/Operations/OptimizedDistanceMetrics.swift` declares PUBLIC non-witness overloads on `EuclideanDistance`, `CosineDistance`, `DotProductDistance`, `ManhattanDistance` and `ChebyshevDistance`: `distance(_:_:)` and `batchDistance` for `Vector{512,768,1536}Optimized`.
  - A call with concrete static types picks the overload. Generic code (Operations, TopKSelection, BatchOperations generic paths) calls the protocol witness.
  - The two can differ in bits. P01 phase E observed a 2-ulp difference for a dot1536 candidate (`0xc1ce604c` through Operations, `0xc1ce604e` through the overload; `P01/phaseE` E1; a vDSP probe ruled out nondeterminism).
  - So the same metric value depends on the dispatch path, and a user's direct computation can disagree with search results.
- `Sources/VectorCore/Platform/SIMDExtensions.swift` declares `sum()` for `SIMD where Scalar == Float` and `== Double`. Both shadow the stdlib member: a sequential lane order starting from `+0`.
  - About 104 call sites. T12's stdlib-shadow lint allowlists them pending this review.
  - Inferred from source, not probed: an all-`-0` vector sums to `+0` here, but `-0` under the stdlib. Lane order affects rounding.

## Required
1. **Inventory.** For each overload/witness pair, give each side's arithmetic and route, every in-tree caller of each, and the measured bit agreement over finite and exceptional fixtures.
2. **Policy (breaking changes authorized).** Each concrete overload must be BIT-IDENTICAL to the protocol witness for the same inputs, or be removed.
   - "Identical" means the witness routes to the same kernel, or the overload calls the witness.
   - Documenting a tolerance is not an acceptable outcome without root approval.
   - Coordinate public-surface removals with D02. D02's refresh consumes T14's outcome.
3. **Mechanical class closure.** One test per metric × optimized width × fixture class asserting bit equality between the concrete call and a generic call. Plus a lexical guard: every public concrete `distance`/`batchDistance` overload on a `DistanceMetric` type has a witness-equivalence test entry.
4. **sum().** Decide whether to keep it (document the order and the zero-sign behaviour, name the tests, keep the T12 allowlist entry with the new reason) or replace it with the stdlib member (measure the numeric change on the existing suites; CHANGELOG). Add a test that pins the decided semantics: zero sign, order-sensitive fixtures.
5. CHANGELOG entries for any behaviour change. Ledger 0 problems. Run the Python checks out of repo.
