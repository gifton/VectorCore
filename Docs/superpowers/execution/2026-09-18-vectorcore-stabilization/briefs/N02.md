## Approximate equality and accuracy

All affected predicates require finite, nonnegative tolerance before any empty/equal shortcut; negative zero is valid zero. NaN or infinity tolerance returns false, not a trap. Any nonfinite coordinate/value makes the comparison false, including matching signed infinities and matching NaN payloads. Signed zeros compare equal. Vector dimensions must match before either borrow; two empty vectors compare true only with a valid tolerance. For finite coordinates use absolute error<=tolerance. Generic Scalar subtraction may overflow to infinity for a difference larger than its finite domain; with finite tolerance that correctly rejects. No unconditional conversion of arbitrary Scalar to Double is needed.

Apply this contract to public VectorProtocol.isApproximatelyEqual and all three PrecisionValidator vector-equality and conversion wrappers. Update the conversion tolerance comment:0.001 is an absolute scalar error, not a percentage. Preserve width/storage guards and exact factory/provider routes.

Scalar distance accuracy keeps its existing hybrid relative definition: e=abs(Double(reference)-Double(computed))/max(abs(Double(reference)),Double(Float(1e-8))). Compare e against Double(tolerance). This avoids Float difference overflow for opposite near-max finite values and keeps the original Float denominator floor. Both inputs must be finite. Batch must use the identical per-pair formula with Double accumulation of error summaries, converting final max/mean to Float only once. Invalid tolerance, mismatched lengths, or any nonfinite pair returns(false,+infinity,+infinity), including invalid tolerance on empty arrays. Valid empty arrays return(true,0,0). For fully finite pairs, allValid is the conjunction of e<=tolerance; a Float summary may become infinity only if its actual Double statistic is unrepresentable. Do not silently skip bad rows from the mean or call infinity a valid accuracy measure. No changes to AccuracyStatistics/performance profiler or precision-selection gates here; those belong to Q02/V04.

## safeLog option semantics

Choose input handling explicitly, consistent with N01 safeNormalized: first apply existing Vector.handleNonFinite(options:) to the original vector. Retain that method's strict-before-propagate-before-replacement precedence and exact NonFiniteError types/indices. Its replacement flags apply to input coordinates before logarithm. Consequently replaced+Inf becomes log(Float.max); replacedNaN becomes0 and enters the domain policy below. Do not edit handleNonFinite itself.

Process the handled coordinates in index order. For value<=0 (including an unhandled-Inf), strict throws VectorError.invalidValues for the first such index with a logarithm-domain reason; otherwise propagateNaN returns an all-NaN vector; otherwise replaceNaNWithZero yields0; otherwise preserve the existing fallback-Float.max. Other values use Foundation.log; an unresolved NaN or+Inf remains nonfinite. Strict input nonfinite classification occurs before any domain failure, regardless of coordinate order. A successful strict call therefore consists entirely of logarithms of finite positive Float inputs and returns finite coordinates. Default options remain replaceNaNWithZero. Unknown OptionSet bits retain their inert behavior; do not change raw values or presets.

This intentionally resolves the old narrower method documentation: options apply to original nonfinite inputs and to the separate nonpositive log domain. It changes strict NaN/+Inf from nonfinite success to an error, and gives explicit replacement semantics. No broad rewrite of safeDivide, safeNormalized, checkNonFinite or dynamic helpers.
