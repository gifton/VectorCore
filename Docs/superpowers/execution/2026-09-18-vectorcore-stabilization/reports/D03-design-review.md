# D03 independent design review

**ACCEPT design-only.** Read the complete current Logger.swift and canonical API-31 against the candidate. No builds or runtime probes. The design addresses the two demonstrated/source-established defects without changing public signatures or broadening logging configuration.

Forwarding the unevaluated message into the admission helper closes all five wrapper instances. One minimum-level snapshot under the existing lock, followed by unlocked exactly-once evaluation and backend reuse, permits reentrant configuration access and nested logging without extending the lock around user code. The snapshot is the admission decision: a message that changes minimumLevel must not retract its own already admitted record. The25-case matrix correctly excludes an impossible disabled-critical case. Existing level mapping and source-location formatting remain explicit obligations. VectorError's optional String argument is already evaluated at the caller; only fallback description and downstream formatting gain laziness.

ContinuousClock duration from one captured start gives cumulative rather than lap semantics. Converting seconds and attoseconds individually to Double avoids integer multiplication overflow; Duration's representable components yield finite seconds and milliseconds within Double range. Negative injected elapsed time is explicitly suppressed. Finite nonnegative thresholds compare directly as Double; no arbitrary duration conversion or practical cap is necessary. Invalid thresholds suppress emission/formatting without changing the nonthrowing signature. The specified one clock read per log call is compatible with suppression: tests should preserve that invocation-count contract even for invalid thresholds rather than silently assuming an early return means no read.

The internal Sendable clock closure and isolated configuration/emission seam can support deterministic tests while preserving public behavior. Mutable sequence/sink test state must be owned and synchronized by the fixture; marking a capturing closure Sendable alone is not synchronization. The default seam must retain real public shared configuration/backend behavior, which the separate bounded public child verifies. Debug dual-output tests must distinguish message evaluation count from output sink calls. No OSLog storage/persistence guarantee follows from admission.

Baseline message-spy RED is reachable for debug/info/warning/error at a higher valid minimum. The timer's old civil-clock dependency stays a source fact; a new injectable clock does not retroactively reproduce a host time jump. Reentrancy and lock policy are controls, not automatically baseline defects. Bounded child isolation/restoration, actual compile/run and focused Debug/Release are sufficient scoped evidence without a new sanitizer or speed claim. Existing misleading examples are within the one-file documentation scope. No concrete blocker found.
