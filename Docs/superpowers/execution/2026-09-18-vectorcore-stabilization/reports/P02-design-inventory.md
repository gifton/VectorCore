## Public routes and provider precedence

`Operations.findNearestBatch` (Operations/Operations.swift:149–198) validates positive k, required nonempty arrays, every query/candidate dimension and cross-set equality before dispatch. An installed BatchKernelProvider receives the original k/metric and whole query batch at183, before the GEMM gate at189. The protocol default (Protocols/BatchKernelProvider.swift:55–64) delegates each query through the provider's scheduler and findNearest witness; an override can implement the entire batch. This is source-established correct precedence, not a dispatch defect. Existing BatchKernelProviderTests.findNearestBatchUsesOverride and findNearestBatchDelegates use Q4/Q5 with N300 (81–115), so they do not actually shield an eligible Q>=8 GEMM call: API-41 remains a coverage gap. Add a supported optimized metric/type fixture at Q8/N256 with both distinct override and default-loop sentinels; preserve validation-before-provider, original errors and arbitrary provider results. A sequential ComputeProvider is scheduling policy, not a precision override; it does not disable the separate CPU GEMM gate.

`gemmFindNearestBatch` (Operations.swift:206–225) admits Q>=8,N>=256, Euclidean/Cosine and concrete512/768/1536 arrays. Other metrics and generic/Dynamic inputs use per-query fallback. `gemmBatchRun` (228–260) materializes Q*N Float scores, calls MatrixDistance, pointer-selects each row, then formats Euclidean squared scores with a NaN-preserving square root. Pointer selection imposes its existing Int32 candidate-count bound; an Int-indexed new route must not silently inherit that limit. Existing direct optimized Operations admission is squared Euclidean/dot/cosine with its own kernels, not necessarily numerically identical to generic metric witnesses or GEMM.

`Operations.distanceMatrix` (746–775) is a separate throwing generic metric route with exhaustive shape checks, provider.parallelExecute over rows and nested result arrays. Empty input returns one empty row per setA row. It does not use MatrixDistance or the BatchKernelProvider search witness. Do not infer matrix-provider behavior from search precedence.

`BatchOperations.pairwiseDistances` (201–270) reads one E06 snapshot/core count, gates concrete GEMM with enableMatrixRouting/matrixRoutingMinN, then rewrites each diagonal using the requested metric (R03). Its independent non-GEMM row gate is N100. It is nonthrowing and preserves complete results under cancellation; it has no Operations provider override. Typed GEMM creates flat N² output and then allocates every nested row while flat remains logically live. Euclidean row formatting currently uses `v>0?sqrt(v):0`, mapping NaN to0; this is explicitly documented/qualified, not a new P02 fix. Any new flat/reusable output must preserve or explicitly migrate that route's score and diagonal contract. The source model approaches two N² Float buffers during reshape, plus packs; optimizer lifetime and measured peak remain separate questions.

## Existing MatrixDistance storage and arithmetic

MatrixDistance.swift:39–73 defines an immutable Sendable PreparedCandidates owning Array<Float> packed rows and optional norms, plus n/d/normalized metadata. Its initializer is internal. Public prepare([V]) copies each vector into a new contiguous n*d buffer; normalized preparation mutates that owned buffer through accepted N01 NormalizationCore, while Euclidean preparation stores n squared norms. Value copies may share Array backing through COW; there is no escaped raw-pointer owner or mutation API. It is not a borrowed view onto a caller's centroid cache. Prepared queries do not exist: every call packs queries anew and computes query norms or normalizes them.

One-shot into overloads (83–89,139–145) prepare candidates on every nonempty call. Prepared overloads (93–123,149–177) reuse candidate bytes but allocate query packing and, for Euclidean, q norms; into output can itself detach if its Array backing is aliased. Allocating overloads add full Q*N output. Thus prepared/into does not imply zero allocation, and there is no public arbitrary row stride, external pointer, norm-supply or reusable query-input surface.

Euclidean uses Float norms plus SGEMM alpha−2 cross term and then `cross+queryNorm+candidateNorm`, clamping negatives to0 and retaining NaN. Cosine normalizes owned rows then SGEMM alpha1 and comparison-clamps1−dot to[0,2]; zero rows remain zero and invalid rows becomeNaN through N01. Accepted direct/cosine exceptional policies differ across routes. The large-offset near-neighbor audit is a qualified recorded observation, not a newly reproduced failure here. A tile bounds temporary output but does not cure Gram cancellation. Even omitting a mathematically constant query norm changes Float rounding/ties; a limited rerank candidate set can already have excluded the true direct winner.

Shape/arithmetic boundaries: prepare derives d solely from the first candidate; prepared invocation checks first-query dimension, preparation mode and exact output size. packRows (196–211) blindly copies d Float bytes from each row's byte view. Products vs.count*d, d*Float.stride, q*n, i*d and offsets precede local checks in several routes. rowSumOfSquares/normalizeRows force base pointers; gemmCrossTerm (248–271) divides X.count by d and converts q/n/d/leading dimensions to Int32 for legacy CBLAS. Empty top-level into calls are no-ops even if out is nonempty; nonempty zero-dimensional rows violate the documented positive-dimension precondition. Docs/Numerical_Behavior.md:69–103 already assigns common positive dimension, initialized sufficient buffers, representable products/BLAS counts and exact output to callers. These unchecked contracts are not new demonstrated corruption. A new checked surface can preflight all dimensions/count/stride/address-span and LP64 conversions using pure arithmetic tests, before copy/norm/BLAS work, without inventing a practical dimension cap.

## Actual VectorIndex consumer, beyond the historical audit

Inspected sibling source only, not built or modified. CentroidBatchScore.swift:37–91 accepts borrowed query/centroid pointers, q/kc/d, cached norms/inverse norms and an inout output of at least q*kc elements. Unsupported metrics return false without touching output; supported zero sizes return true after capacity precondition. Positive work calls SGEMM directly with Int32 dimensions/strides and borrowed buffers synchronously. Euclidean emits centroidNorm−2dot (no query norm, sqrt or clamp); dot emits−dot; cosine uses1+negativeDot*qInv*cInv, inverse epsilon1e−12 and raw sqrt(queryNorm*centroidNorm)>.ulpOfOne guard, without Core's normalized-row clamp. queriesAreNormalized substitutes norm/inverse1. These are selection scores, not interchangeable Core public distances. A direct MatrixDistance substitution would change actual arithmetic and degenerate policy.

There are two live callers in IVFIndex.swift. Training assignment for cosine/dot (377–433) already processes point tiles min(N,4096), reuses tileRows*kc output, borrows existing flatData at a tile offset and centroidsFlat, then strict ascending first-min argmin. Its comment claiming tiling cannot change floating-point scores is not independently established here; SGEMM blocking/backend choices can differ, so migration needs actual parity evidence rather than that comment as proof. Batch search (887–932) instead flattens all Q queries once, allocates Q*kc scores, borrows centroidsFlat and sorts each score row into nprobe indices. It does this setup even for metrics whose run returns false. After synchronous scoring, an immutable context retains COW array values for concurrent search. No pointer survives the borrow closure or an await in the scorer call.

The actor's rebuildCentroidCache (466–488) maintains ContiguousArray<Float> centroidsFlat and norm/inverse arrays from nested centroids, using keepingCapacity/reserve then append. Reusing that cache is the concrete consumer opportunity; adopting a second owned PreparedCandidates merely duplicates it. Existing direct consumer tests IVFBatchGEMMParityTests:138–279 cover Euclidean/dot/cosine scalar references, degenerate centroids, normalized queries and unsupported metrics, plus batch-search parity elsewhere in that file. Those are source tests, not freshly verified downstream runtime evidence. Consumer migration requires pinned sibling revision and authorized scope later; this inventory grants neither.

## Bounded choices root can make without production workload targets

A per-call precision policy can define a CPU direct reference versus legacy Gram route and gate independence without claiming exact real arithmetic. Root must name the reference kernel/accumulation, admission score, nonfinite/zero/tie law, and whether provider witnesses remain authoritative or an explicit CPU-only precision call bypasses them. Calling a mode simply exact would overclaim. Test near-equal large-offset fixtures across Q7/8,N255/256 and concrete widths, with an independent scalar Double/analytic oracle and route sentinels; require direct mode consistency with its declared reference, not universal GEMM equality.

A caller-selected temporary byte limit can be deterministic without choosing a production default budget. Root must define included buffers (query/candidate packs, norms, score tiles, top-k partials), excluded input/result ownership, simultaneous worker multiplication, minimum feasible work and too-small-budget outcome. Full matrix result bytes Q*N cannot fit an arbitrary scratch cap by tiling alone; nested-result reshape adds ownership cost. BLAS/runtime internal memory and allocator overhead are not generally controlled by a library logical-byte model. Pure checked planning tests plus actual Release allocation/current-memory observations can verify the selected boundary; no arbitrary scale or RSS ceiling should be inferred.

Narrow storage alternatives are consumer-owned contiguous inputs borrowed only for a synchronous call, or immutable owned reusable packed inputs with explicit construction/copy semantics. Both could expose row/column/stride and output view capacity without adding async pointer lifetimes. A borrow needs initialized/addressable extent, no overlapping output/input, owner lifetime and mutation exclusivity obligations; a normal escaping struct cannot promise safe nonescape by naming. An owned Array/ContiguousArray adapter may reuse COW storage if it does not normalize/mutate; cosine preparation cannot both mutate a borrowed cache and promise preserved inputs. Raw cross-term plus consumer postprocessing would match the actual centroid scorer more closely than claiming identical full-distance semantics, but root chooses whether such an API belongs here. Norm provenance/type/mode must prevent stale or mismatched prepared data.

For API-24, an explicit flat/reusable result route can avoid mandatory nested reshape; merely adding it does not remove the old nested API's cost. P01 owns repeated batch validation and local heap sizing, so P02 must not duplicate those edits. API-25 closure requires actual consumer parity and observed removal of candidate repacking, not just an unused view API. TOOL-10 production-scale acceptance remains staged until actual workload intent/budgets exist; bounded fixtures can establish concrete ownership/route/precision contracts now, not downstream scale readiness.

## Existing coverage and measurement coordination

MatrixDistanceTests covers ordinary finite parity, limited identity clamp, widths, nonempty Dynamic rows, empty no-op and prepared equality/reuse. It does not establish universal no-NaN behavior, checked ragged/stride domains, large-offset ranking or allocation envelopes. Prepared equality tests compare related production paths, so retain an independent numerical fixture. E06's child-isolated BatchGEMMRouting and real phase observations, R03 diagonal/custom metric controls, N01 normalization and P01 selection-score distinctions must remain.

The current MatrixDistanceBench times one-shot matrix computation with reused output, so candidate/query preparation is inside each timed call (N64/256/1024, widths512/768/1536); its only output consumption is out[0].isNaN. It is not a prepared-input or real centroid-cache benchmark. Current PR smoke names dot/distance/normalize at512; no downstream scale result follows.
