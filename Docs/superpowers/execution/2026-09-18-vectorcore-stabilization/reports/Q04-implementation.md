## Implementation and scope

The nine public wrappers now share one @usableFromInline endpoint/capacity validator. It checks the lower bound and upper bound before subtracting endpoints, then checks output capacity. Invalid range and short output use distinct named fatal diagnostics in ordinary Debug and Release. A valid empty range returns immediately. Nonempty wrappers map only candidatesFP16[range] to immutable owned storage handles and pass 0..<count to the unchanged arithmetic core. Compact output is still relative to the output view's own base, not the original candidate index.

Only the nine wrappers, their shared validation helper and adjacent documentation changed in production. Full base/final code inventory covers Sources, Tests, Scripts, Benchmarks, and Package.swift: 321 original files and 325 final files. Four new files are the regression matrix and public allocation Swift/C/Python fixtures. Constructors, diagnostics, borrow APIs, arithmetic cores, SoA, tuners, Package.swift and sibling sources are unchanged. No existing expectation was edited. Touched documentation replaces unsupported speedup/error claims with the compact-output, validation and O(requested count) metadata contract. Unsafe output initialization/capacity/aliasing remains the caller's obligation; this does not validate arbitrary pointers.

The repeated caller inventory found the nine wrappers and existing test/benchmark callers; no automatic production routing migration was needed. Existing FP16 value-range validation is included as a consumer but does not replace the new candidate-index matrix.

Finite references use Double scalar reductions over actual stored FP16 values. Distinct candidate patterns make rebasing visible. Each output must first be finite; the comparison does not hide NaN/Inf in an abs/max reduction. The tolerance is a conservative forward-error bound scaled by absolute accumulated terms: 16 × width × Float epsilon (with a bounded cosine scale), rather than an accuracy claim for arbitrary inputs. Exceptional values are checked separately, bit-for-bit against the unchanged original-range core; that is parity evidence, not an independent accuracy oracle. The existing cosine core assigns similarity zero if its denominator is not finite or not greater than 1e-9, then clamps similarity; zero/tiny/nonfinite controls preserve this policy and do not claim universal NaN propagation.

## Matrix and child process coverage

Across all nine width/metric routes, N=0/1/2/3/11 includes start/interior/end empties, singleton, pairs, triples, full ranges and odd tails: 288 finite range cases. Offset output views check bit-exact parent prefixes and every unrequested suffix element. Valid empty cases also use nil-base zero-capacity output. The exceptional matrix has 315 wrapper/core comparisons, including signed zero, tiny norms, infinities, NaNs and Float extrema across singleton/pair/triple/odd/full ranges.

The rejection matrix is nine parameter combinations × five scenarios = 45 fresh children per Debug/Release run: negative lower bound, excessive upper bound, out-of-bounds empty range, Int.min..<Int.max, and short output. Each child maps a real shared file containing sentinels; the parent verifies all bytes unchanged, so no-write-before-rejection is an observation rather than inference from a crash. Physical storage is valid and large enough throughout; no expired pointer or invalid-memory dereference is introduced as a probe.

Every child installs its termination handler before launch, captures stdout/stderr in a file, has a 15-second execution deadline and at most two seconds of owned-PID cleanup, and throws on timeout before reading termination properties. Successful expected rejection requires child entry, the intended named diagnostic, abnormal status, and unchanged shared bytes. The child-entry test is intentionally a no-op in the parent and is excluded from credited coverage. The focused run reports 22 test functions in six suites, including that no-op; the new parameterized function additionally runs all nine argument cases. Existing mixed-distance consumer suites and FP16 value-range validation run alongside the new matrix. Valid-only ASan selects the two real valid matrix functions and no child entry.
