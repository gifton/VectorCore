## Supported C surface and accumulation

Remove the umbrella header's proposed-but-unimplemented declarations from the public header, retaining them only in a new clearly nonbinding design document if useful. Keep every implemented exported feature query, FP32 dot/L2/range512, generic INT8 dot, and accepted L01 LAPACK entry/sentinel. Generate the declared/defined symbol inventory from the actual build and link an ordinary C and C++ consumer against every retained function. Do not expose internal architecture functions as public API or implement proposed kernels opportunistically.

Correct the umbrella's blanket runtime feature-query wording: current ARM NEON/dotprod queries report compile-target macro availability, whereas the x86 queries use runtime feature builtins. Document the actual distinction and test against the compiled configuration. Do not change dispatch or infer runtime SDOT discovery from a macro.

Document the actual range512 output contract: results occupy out[0..<(end-start)] independently of start, with the caller providing valid initialized input rows, sufficient output and nonoverlap. Inputs require start<=end, strideFloats>=512 for referenced rows, representable row offsets/address span, and live buffers throughout the synchronous call. A valid empty range performs no pointer access. Keep the existing unsafe interface and compact indexing; no hidden lengths or arbitrary pointer validation claim. Test nonzero start, padded stride, offset output with guards on both sides, untouched suffixes and empty range. Compare finite FP32 results to an independent Double sum with a justified tolerance, without claiming exact parity between FMA and scalar paths.

Define generic vc_dot_int8 as the exact integer dot product reduced modulo 2^32, then interpreted in the Int32 range. The fixed 512/768/1536 cases still equal the full mathematical integer result because their worst-case magnitude is bounded by1536*16384=25,165,824. Do not use signed-overflow compiler flags or rely on out-of-range unsigned-to-signed casts. Use unsigned scalar accumulation and an explicit safe final numeric mapping (e.g. bits<=INT32_MAX converts directly; otherwise -1-Int32(UINT32_MAX-bits)). Product formation in Int32 is safe for two Int8 operands. SIMD lane accumulation/horizontal combination must implement the same modulo law; any scalar tail/final addition occurs in unsigned arithmetic. A small private helper is allowed for shared mapping and pure boundary checks.

Audit scalar, ARM NEON/SDOT and x86 AVX2 paths, including horizontal reduction and every tail. Replace i+block<=lanes guards with equivalent remaining-count checks maintaining i<=lanes; every subsequent increment must stay <=lanes. Test helper boundary arithmetic near SIZE_MAX without allocating gigantic buffers. The pointer domain remains unsafe: lanes valid readable bytes per input, output a value, zero lanes permits no reads. Do not add an arbitrary lane cap or alter fixed-width quantized arithmetic/gates. Preserve V02's optional-C dispatch sentinels and distinguish dispatcher, scalar and actual architecture entry execution.

Actual baseline UBSan RED should execute scalar overflow on131072 all(-128)*(-128) pairs and the relevant tail/final-combination witness where supported. Add cancellation-pattern fixtures whose final mathematical sum fits Int32 but whose earlier prefix does not. Independent Int64 references suffice for the bounded test vectors, followed by an independently computed modulo mapping. Cover lanes0/1/15/16/17/31/32/33/63/64/65, fixed widths,131071/131072/131073 and a larger bounded case that crosses multiple modulo boundaries. Permute signs, use zero and unequal magnitudes, and compare all actually executable paths. Run ASan/UBSan on actual source, not a rewritten fixture. Cross-compilation/disassembly can support review of an unavailable architecture, but all-architecture NUM-32 closure remains staged unless real matching execution evidence exists. No installation of an emulator or claim of x86/SDOT execution by inference.
