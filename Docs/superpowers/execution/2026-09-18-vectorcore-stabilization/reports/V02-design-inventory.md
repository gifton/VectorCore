## Unsupported/ignored options and validation

AppMain:52–178 silently ignores unknown arguments and many absent/malformed values; dims/batchNs compactMap silently drops invalid tokens; negative/zero/huge batch sizes are not rejected at parsing. Samples<=0 clamp to1; repeats<=0 falls back to automatic timing. Unknown profile uses short; unknown mode does nothing; unknown suite only warns and skips. Unknown output format/progress/filter mode have fallback behavior. Empty selected output can succeed. Root should decide errors and valid empty selection explicitly before implementation; no performance requirement follows.

Profile applies before mode; explicit minTime/dims/batchNs override relevant presets. Seed CLI precedes VC_RUN_SEED (decimal/hex); label CLI precedes environment. Boolean CLI overrides environment; AB defaults on unless VC_BATCH_AB=0, SoA/mixed default off, AB-only forces AB on. SoA/mixed additionally require existing size heuristics, so requesting a flag does not guarantee a case. Invalid regex compilation is silently dropped by CaseFilter: an entirely invalid include list becomes include-all, and invalid exclusions vanish. Glob mode is anchored; regex mode is substring matching. Filters uses a nonisolated(unsafe) mutable process-global cache; current CLI suite loop is sequential, not evidence of safe concurrent external invocation.

useCKernels/useUnderscored/releaseSize flags are captured as requested metadata but do not alter compiled code. The actual Swift condition is VC_USE_C_KERNELS (underscore spelling), distinct from runtime VC_USE_CKERNELS. Package.swift always depends on VectorCoreC and does not define that Swift condition. Requesting `--use-ckernels` cannot enable it after compilation. Negative requests likewise cannot disable a compiled branch. Build configuration metadata defaults to release, while EnvCapture's git SHA/current PATH swiftc describe runtime surroundings, not necessarily the binary build. Binary size alone is not artifact identity. EnvCapture has unbounded waitUntilExit/pipe reads for git/swiftc; bounded metadata acquisition or explicit unavailable metadata needs root scope adjudication, not false build provenance.

## A/B identity and report integrity

CaseParsing recognizes dot/dist/normalize/batch/mem; slash-delimited matrix names have no structured matrix parameters. Noop is unstructured beyond kind. Both ABComparisons.swift and AppMain pretty summaries include the complete variant in cosine grouping keys; optimized-fused and optimized-preNorm therefore cannot pair. Euclidean grouping by D/N/variant/provider works, generating2 pairs per D/N/provider; intended cosine adds1. With default three dimensions/two Ns/three providers, current Euclidean count36 and intended cosine count18 are source-derived. Duplicate keys overwrite silently. Sorting lacks a provider tie-breaker after otherwise equal keys. A complete pairing contract must define exactly one member of each side, compatible units/workload, missing-pair behavior and deterministic keys/order; do not treat zero output as successful requested A/B coverage.

PreNorm candidates are normalized outside measured work while fused includes norm arithmetic in its kernel. Preserve that measurement-boundary distinction in pair metadata/documentation; these are strategy costs under different preparation assumptions, not interchangeable numerical outputs. Pairing should not collapse generic/optimized or provider identity. Timing denominators must be finite positive before ratios; no universal speed superiority follows.

compare_benchmarks.swift decodes only results and matches names. It ignores all metadata, overwrites duplicate baseline names, permits empty intersections, accepts unsupported metric strings through fallback, and divides by unchecked baseline values. Missing-case failure is optional `--strict`; even strict needs a meaningful nonempty matched set. Root must choose compatibility versus explicit override policy for architecture/device/toolchain/build configuration, effective compile flags, input seed/workload identity, measurement settings/unit count, and case set; commit IDs/labels naturally differ and should be retained rather than necessarily equated. Compare requested and effective state separately. CSV metadata rows interpolate values without the quoting used for data rows, so comma/quote/newline/carriage-return metadata requires an explicit serialization contract. These are integrity obligations, not new regression thresholds.

## Actual C reachability and bounded constraints

VectorCoreC is always compiled/linked as a dependency. CKernels.swift:35/49/78 FP32 dot512/l2sq512/rangeL2sq512 wrappers have no production Swift callers. CKernelsSmokeTests directly exercises dot512 only under the Swift flag and otherwise is a no-op. Do not enable dormant FP32 routes merely to make benchmark C metadata meaningful.

The six live CKernels.dotInt8 call sites are QuantizedKernels.swift:583–585 and772–774. Equal-scale symmetric zero-point-zero Euclidean invokes dot(q,q), dot(q,c), dot(c,c); asymmetric/different-scale Euclidean takes accepted Double affine logic. Symmetric valid zero-point-zero dot/cosine uses three integer dots through centeredSums; asymmetric paths retain wide accumulation. Public callers are fixed512/768/1536 INT8 Euclidean/dot/cosine methods and their batch compositions. Existing normal benchmark suites contain FP32/optionalFP16, no INT8 cases; C-on cannot establish changed dispatch for those cases. The internal generic implementation is not evidence of arbitrary public custom-length support.

At fixed1536 length, each product magnitude is<=16384, so dot absolute accumulation<=25,165,824. Euclidean sum of squared differences<=1536*65025=99,878,400; decomposition intermediates fit Int32. These arithmetic bounds support existing fixed-width fixtures. The exported raw C API accepts arbitrary size_t lengths without checking buffers or accumulator range: scalar signed Int32 += can overflow; vector lanes/reductions wrap at large sums and scalar tails/final additions can overflow. Merely promoting the returned Int32 to Int64 does not repair a too-wide call. Loop i+16/32/64 conditions also assume representable valid extents. Bounded sentinel cases should use actual fixed widths plus deliberately small tail lengths for direct-C controls, not claim safety at arbitrary lane counts or widen V02 into numerical kernel repair.

vc_dispatch chooses ARM NEON or x86 AVX2 for INT8, else scalar. ARM SDOT versus vmull/vpadal is compile-time __ARM_FEATURE_DOTPROD, not a general runtime SDOT detector. x86 uses sign-extension, madd_epi16 and unaligned loads; ARM uses widened products/non-saturating accumulation. A local arm64 run establishes only its selected branch, not x86 runtime evidence. FP32 C implementations use ordinary Float accumulations, no universal nonfinite/overflow guarantees. Range C writes compact out[0..<end-start], despite header text claiming out[start..<end]; requires valid512-wide rows, safe row*stride arithmetic and adequate output. No validation exists there; leave dormant routing unchanged.

LAPACKLinearAlgebraProvider imports VectorCoreC independently of VC_USE_C_KERNELS and calls availability/sgeqrf/sorgqr/sgesdd/ssyevd. LP64/workspace concerns belong to accepted L01 design, not an implication of the optional INT8 flag. Therefore “C off” must mean optional kernel dispatch off, never that no C code is linked/executed. Header TODO-only proposed symbols are declarations, not implemented routes; do not add tests claiming they exist.

A bounded route-sentinel option for root is a separate linked test artifact instrumenting the existing vc_dot_int8 entry, forwarding to the unchanged real implementation and recording actual entry counts. Invoke public symmetric fixed-width Euclidean/dot/cosine and asymmetric fallback controls under separately built on/off Swift modules; independent scalar Int64/Double oracles retain correctness. Counts must distinguish three calls per applicable invocation from zero fallback calls and identify actual object/module/executable bytes. A direct C call alone proves the C implementation, not Swift dispatch; a compile flag/import/string alone proves neither. This suggests a mechanism, not a chosen V02 driver interface or authorization to activate FP32 wrappers.
