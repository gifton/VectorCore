Int.max is valid for each: it can force serial/no-GEMM behavior or one logical chunk/batch on a small actual input without large allocation. oversubscription must be finite and strictly positive, with `Double(max(1, ProcessInfo.processInfo.processorCount)) * oversubscription <= Double(Int.max).nextDown`; reject an infinite product or out-of-range result. Tiny positive factors are valid and produce at least one target logical chunk. Negative zero is invalid. No user workload, maximum data size or latency target is inferred from these representability guards.

## Exactly which setting controls which path

- process: nil batchSize uses snapshot.defaultBatchSize; an explicit size overrides it. snapshot.parallelThreshold selects serial versus the accepted E02 parallel scheduler based on input vector count. Callback batch shapes remain successive contiguous ranges, with a shorter final batch, and outputs flatten in original batch order.
- map/filter: snapshot.parallelThreshold selects the route using input count. Other chunk/default-batch fields do not define callback grouping for these per-vector methods.
- statistics: snapshot.parallelThreshold selects the route. The parallel path derives its logical chunk size from snapshot.minimumChunkSize and oversubscription using the safe rule below; N03's exact original logical-chunk merge order and full-count/nonfinite behavior remain unchanged. The internal explicit-chunk helper remains independent of global configuration and preserves its existing contract.
- findNearest: replace the ParallelHeuristic choice with `vectors.count >= snapshot.parallelThreshold`; k<=0/empty still returns empty after the entry snapshot. Parallel paths use the safe logical chunk rule below. This deliberately activates all six optimized 512/768/1536 Euclidean/cosine helpers at the configured threshold. Their correctness, NaN/tie/global-index behavior and E02 worker limits must be validated through the public route. Keep serial helper's existing private per-width chunk sizes: minimumChunkSize and oversubscription apply to parallel nearest/statistics logical partitions only. Remove the now-unused local metric/variant heuristic classification, without changing shared ParallelHeuristic used by other APIs.
- pairwiseDistances: snapshot.enableMatrixRouting and matrixRoutingMinN keep their existing GEMM meaning and concrete metric/type restrictions. Preserve its separate N100 serial/parallel per-pair gate. parallelThreshold is documented as controlling the linear batch APIs above, not this quadratic builder. E02 still bounds row workers. Disabling matrix routing does not change Operations.findNearestBatch's independent gate. Other chunk fields do not control pairwise row partitioning.

This table is the public scope of each setting; do not imply every setting affects every method. Remove unsupported speedup, optimality and universal crossover claims from touched docs. Keep metric semantics, safe output capacity, storage/layout and R03 direct self scores unchanged.

## Safe logical partition rule

For actual N>0, let C be the operation's captured positive active core count. Compute a floating target C*oversubscription, but clamp it to actual N before any conversion to Int. If the target is >= Double(N), targetChunks=N; otherwise targetChunks=max(1, Int(target)) (the finite nonnegative truncation is then safe). Even if hardware counts change after a configuration was validated, this actual-work clamp must prevent overflow or trapping conversion. N=0 has no chunks and requires no division. Use `ideal = N / targetChunks + (N % targetChunks == 0 ? 0 : 1)`, then `chunkSize = min(N, max(snapshot.minimumChunkSize, ideal))`.

Remove the signed power-of-two rounding heuristic entirely; it is not a public contract and can overflow for valid large settings. Chunk endpoints are start + min(chunkSize, N-start); chunk counts use quotient/remainder, never N+chunkSize-1. Do not materialize arrays of all input chunks merely to schedule work. oversubscription changes logical partition count, NOT the E02 hardware-capped worker K. Preserve at most C library workers per phase and zero extra nested workers. More logical chunks than workers execute sequentially within each assigned worker range. Statistics merges logical chunk results in chunk-index order, never worker completion order. Changed partitions can alter floating-point rounding, which is already qualified by N03; no bitwise partition invariance is promised.

An internal pure partition helper taking explicit N/C/config is allowed for boundary tests without depending on host core count. Actual behavioral tests must additionally inspect the scheduler/partitions on real operations using E02's task-scoped observations, extended with immutable logical-range information only if necessary. No process-global test hook, public force-parallel knob or synthetic production-only selector is needed.
