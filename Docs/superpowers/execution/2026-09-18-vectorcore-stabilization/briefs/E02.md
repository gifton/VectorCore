# E02 — Bounded structured scheduling and reduction laws

Root-approved contract after independent design review. Depends on accepted E01, O01 and R03; also wait for N03 and E04 integration because their accepted statistics and OperationContext implementations must be preserved. API-04/API-27/API-28/API-42/API-48 candidates. Read reports/E02-reachability-review.md and its mechanical inventory, then repeat reachability at the actual dispatch base. Breaking changes are authorized. No throughput, CPU-thread, global concurrency or production memory-envelope guarantee is added.

## Scheduling unit and bounds

Use one shared internal structured-execution utility for the retained library task-group routes, with throwing and nonthrowing forms as needed. Each shared scheduler invocation (one execution phase) creates at most K child worker tasks in total, each visiting its assigned contiguous work units sequentially. A composed public operation such as cosineSimilarityMatrix may run normalization and matrix phases sequentially, each with its own bound; cumulative submissions across its lifetime may exceed K, while outstanding library worker tasks do not accumulate across completed phases. K is bounded by both the supplied positive concurrency limit and the number of work units. Do not create one task per item/pair or allocate an array of closures/tasks before applying the bound. A sliding window is unnecessary: coarse contiguous worker ranges satisfy this contract. Each task owns its partial output; the parent alone assembles ordered output. Avoid concurrent access through shared unsafe output pointers or unchecked Sendable wrappers.

The root limit for ComputeProvider defaults is maxConcurrency, not deviceInfo.maxThreads. Reject nonpositive maxConcurrency with invalidConfiguration before any callback, including empty input. Int.max is a valid positive limit and is clamped to actual work before arithmetic. CPU modes retain their existing serial/automatic/parallel threshold decision and coarse chunk preference. Default and CPU minChunk overloads validate a positive hint even for empty input; use safe division/endpoints and never split into more than K workers. Their partition boundaries are not a stable public API. Keep accepted ComputeRangeBoundary representability behavior, including negative range origins and Int.max neighbors.

BatchOperations and TriangularMatrix use max(1, activeProcessorCount) as their root worker limit. Retained ExecutionOperations transforms/matrix use a validated positive context.maxThreadCount; validate context.preferredChunkSize before using it. Preserve existing serial thresholds, result semantics, R03 matrix diagonals and N03 accumulator/partition semantics. E06 owns wiring live BatchOperations settings; do not activate ignored configuration fields here. N03's explicit chunk helper may have many logical chunks, but schedule those chunks through at most K workers and merge the resulting accumulators in original chunk order.

Share a task-local library parallel-region marker across defaults, CPU and retained batch/matrix routes. Mark the callback region even when executing serially: a nested library invocation in that region executes inline without creating child workers. Preserve the existing internal CPUComputeProvider.isInsideParallelRegion test control, either as a compatible additional suppression check or through an explicitly migrated internal test seam. This is a bound on library-created worker tasks, with phase-local callback bounds and no additional workers from nested calls. Independent root invocations and user-created fan-out (Task, task groups, async let or detached tasks) are outside that bound. Suspended outer callback frames, coordinators and OS threads are not additional active leaf compute bodies. A deeply nested inline call stack can contain multiple unfinished callback frames per worker; no bound on that stack depth is implied. A custom provider that overrides scheduling owns its own conformance to these laws.

Inputs/results remain in input index order. process flattens per-batch output in batch order; filter retains input order. Completion order must not affect reduction merge order. Matrix builders use rows or bounded contiguous pair ranges as work units, with exact cell coverage; do not flatten N*N task descriptors. Preserve symmetric-metric restrictions and TriangularMatrix's strict-upper-triangle computation, including zero callbacks for sizes zero/one. This scheduling change does not eliminate the matrices' required quadratic output payload.

## Cooperative cancellation and failures

Throwing schedulers validate structural inputs, then check cancellation before any callback or child submission, before each library-managed work unit, after each completed user body, and before returning success. A work unit is one item for parallelExecute/parallelForEach/map/filter, one requested batch for process, one row for scalar transforms/matrices, and one rangeWork invocation for parallelReduce. A row or range kernel can contain arbitrary synchronous work; the library cannot interrupt that body. User closures must cooperate for responsiveness within their own work unit. No wall-clock cancellation deadline is promised.

On a body error, cancel siblings, cease further user work as their next checkpoint observes cancellation, await structured cleanup, and propagate an original error rather than returning partial success. If multiple bodies fail/cancel concurrently, no fixed winner is promised. At most K bodies can have passed a checkpoint before cancellation is observed; tests must distinguish in-flight bodies from bodies started after an observation. Parent cancellation must also affect serial branches. Keep loop execution in a Swift task context; do not route the retained loops through CPUContext.execute's GCD continuation, which loses task-local/cancellation state. Internal context parameters serve the documented scheduling hints on these retained routes, not a new executor/device guarantee.

Nonthrowing APIs (BatchOperations nearest/pairwise/statistics and TriangularMatrix.buildParallel) retain their complete-result contract and run all work even when the task is cancelled. Document that policy; do not fabricate zero-filled/partial output or silently add throwing signatures. They still honor the bounded scheduling and nested-region policy. Direct provider execute should check cancellation before and after its async body in CPUComputeProvider; the protocol documents the conformer obligation. No promise is made to force termination of a cancellation-ignoring body.

## Reduction and synchronous range-kernel policy

parallelReduce is a partition reduction, not an arbitrary sequential left fold. rangeWork must return a valid aggregate for its entire range, combine must be associative for partition-independent mathematical results, and initial must be its identity. Commutativity is not required because partials combine in ascending range order. Use initial exactly once in the parent combination, including the nonempty sequential path; empty input returns initial without invoking rangeWork or combine. Never insert initial into every worker or recursively reduce partials with new initial values. Floating-point addition is not associative, so mode/partition bitwise equality is not promised. Use exact integer addition and ordered string/array concatenation to test the laws, plus explicit floating-point qualification in docs.

CPUComputeProvider.executeBatch remains a synchronous, single full-range kernel invocation for every nonempty candidate array, and no invocation for empty input. Its documentation must state that mode/threshold/minChunk do not schedule this helper and that there is no autotuning or concurrent pointer access. Retain its existing public signature and require output capacity at least candidate count before invoking a kernel, with a named guard for a short buffer; an oversized suffix is outside the logical output. Remove the unused private measureProbes function. The optional initializer's currently unused minChunk argument must be explicitly documented as a compatibility argument with no effect; do not secretly activate it or imply measured tuning. The per-method minChunk overloads remain the operative hints. Spy tests cover all modes/settings, exact range/call counts and suffix preservation using a correctly written kernel.

## Incorporated review requirements

Preserve N03 original logical-chunk accumulators and its exact chunk-index merge order when distributing those chunks among bounded workers; do not merge by worker completion or collapse logical chunks into a new numerical partition. Test gates must require no more than K simultaneous entrants and must release every waiter even after an assertion failure. Per-phase observations distinguish cumulative submissions from outstanding workers in composed calls.

## Root clarification after v4 review

The synchronous ordered parent `combine` closure is also a user callback. Both default and CPU reduction implementations must run every combine inside the shared library parallel-region marker and check cancellation immediately before and after each invocation, as well as before returning. This does not redefine rangeWork partitioning or add workers: it prevents continuing through later combines after the first combine cancels the task. Preserve initial exactly once, ascending partial order, no callbacks on empty input and the accepted structural-validation precedence. Establish an actual cancelling-combine RED against frozen v4; cover both providers, both overloads, first-combine cancellation and direct marker observation inside the synchronous callback. Do not construct user-created asynchronous fan-out to simulate an impossible direct await from combine. This requires v5 production evidence; older runtime records keep their actual source versions.
