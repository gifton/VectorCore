# T05 brief — make the test output-path policy label-aware and scope-aware (root-created)

## Problem (observed 2026-10-04)
`Scripts/ci/tests/test_swift_test_output_paths.py` (from T03) tracks `#filePath`/`#file`/`#fileID`/`currentDirectoryPath` taint **per file, by name**. That limitation was documented. On real code (V04's `Tests/BenchmarkContractTests/BenchmarkSelectionContractTests.swift`) it produced a false positive that a rename could not fix:
- Legitimate `#filePath` **reads**, used to read `Benchmarks/.../Suites/*.swift` for fingerprinting, tainted common names: `source`, `text`, `suites`, `name`, `cases`, `metadata`, `unavailable`.
- `_mentions` then matched those names as **argument labels** in an unrelated write call: `CSVWriter.write(cases: …, metadata: …, failures: …, unavailable: …, to: csvOutputPath)`. The path there comes from `V02_CSV_OUTPUT` or `temporaryDirectory`.
- V04 had to move two test classes into another file to appease the guard. A guard that forces code reorganization is too coarse.

## Required (keep every existing true-positive negative control passing)
1. **Argument labels are not mentions.** In `_mentions` (and wherever names are matched), an identifier immediately followed by `:` as an argument label inside a call does not count as a mention. Also exclude member names after `.`; for example, `foo.path` does not mention a tainted `path` unless `foo` itself is tainted.
2. **Scope taint to the declaring body.**
   - A `let`/`var` tainted inside a function, closure or computed-property body taints that name only within that body, including nested bodies.
   - File-level declarations, and function or property NAMES tainted by their bodies, still taint file-wide. A call to `benchRoot` or `source(…)` anywhere is a real use.
   - Use a brace-depth-based body segmentation consistent with the existing `_statements`/`_bodies` helpers. Document the approach and its limits: string literals containing braces, and so on.
3. **Negative and positive controls:**
   - (a) The exact V04 false-positive shape, reduced to a synthetic snippet: one function reads via `#filePath` into `source`/`name`, another writes with labels `cases:`/`name:` to a temp path. It must PASS.
   - (b) A same-named untainted local in a different function. It must PASS. This replaces or updates the old `test_taint_is_per_file_by_name`, which pinned the limitation.
   - (c) A tainted local used in a write in the SAME function. It must still FAIL.
   - (d) A tainted function or property name called from another function and used for a write. It must still FAIL.
   - (e) A write whose argument is `x.path`, where `x` is tainted. It must still FAIL.
   - All existing controls must keep their verdicts.
4. Re-scan the whole tree: `Tests/` must be clean. Separately, run the improved scanner against the V04-c workspace's pre-relocation version of `BenchmarkSelectionContractTests.swift`. Extract it with `git -C <V04-c worktree> show <tree 81b8880>:Tests/BenchmarkContractTests/BenchmarkSelectionContractTests.swift`. Show that the false positive is gone, as evidence that the relocation would no longer have been necessary.
5. Update the docstring: the scope rules and the remaining limits.
