2. Root ruling, VectorCore.Logger vs os.Logger: this collision predates the toolchain change (os.Logger has existed since macOS 11). It is not blocking: module-local declarations shadow imports inside VectorCore, and only downstream files importing both modules must qualify the name. VectorCore.Logger is core public API used by sibling packages, and its disposition belongs to D02 (public API disposition, downstream migration). D03's approved brief preserves the Logger signature until then. The interim mechanism is a single allowlist entry with a justification naming D02 as owner. ProgressReporter is renamed now because it broke the build and lives in the low-reach benchmarking product.
3. Root ruling, Release `swift build --build-tests -c release`: the brief's command was wrong. Tests use @testable import, which needs -enable-testing; `swift test -c release` adds it and `swift build --build-tests` does not, under either build system. This is not a product defect. The only CI `build --build-tests` use (ci.yml Intel triple) is Debug. Release evidence comes from the focused `swift test -c release` runs.
