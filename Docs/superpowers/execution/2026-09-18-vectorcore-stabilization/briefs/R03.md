## Behavior

BatchOperations.pairwiseDistances and internal ExecutionOperations.distanceMatrix compute every diagonal using the supplied metric, including negative dot self scores and cosine distance1 for zero vectors. No universal zero-diagonal shortcut. This includes the BatchOperations GEMM dispatch: wrapper diagonals must agree with the requested built-in metric's direct self result. Existing off-diagonal GEMM numerical differences remain documented, with finite-aware tolerances on well-conditioned tests; this task does not establish nearby-vector relative accuracy. Preserve symmetric-matrix API scope and explicitly document that custom metrics must be symmetric. Do not promise arbitrary directed metric parity or redesign row scheduling.

Array<Vector<Dim768>>.cosineSimilarityMatrix returns actual similarity: identical nonzero vectors approximately1, opposite approximately-1, orthogonal0, and any pair involving a zero vector0 (including zero self). Preserve the existing normalization-once pipeline if practical: after correct negative-dot matrix diagonals, negate the distance-score matrix; alternatively use an equivalent explicit similarity computation. Clamp finite rounding excursions to [-1,1] if needed, without mapping NaN/Inf to plausible finite values. N01 owns extreme-range normalization; this task's proof uses ordinary finite values and exact zero.

All general SoA cosine routes write exactly the logical candidate prefix0..<soa.count. In particular, zero-query early returns in blocked2/blocked4/tiled implementations must leave oversized output suffixes untouched. N0 writes nothing. Offset buffer views must leave both surrounding prefix and suffix sentinels untouched. Keep the existing documented output-capacity precondition/checked-wrapper errors; do not broaden an unsafe API's contract or activate a new routing gate. Preserve layout, padding, thresholds, ownership and existing nonzero arithmetic.
