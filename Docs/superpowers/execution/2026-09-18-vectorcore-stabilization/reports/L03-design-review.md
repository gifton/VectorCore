## Mathematical consistency

The dimensionless substitution and log-parameter Jacobian are correct: ell=A+2*beta*log(t), df/dA=-f(1-f), df/dB=-2*beta*log(t)*f(1-f). Stable logistic evaluation prevents direct exponent overflow; finite checks must also cover beta/log products, derivative products, accumulated normal equations and damping, not merely candidate SSE. The stated finite gradient criterion is an explicit engineering stationarity rule and appropriately avoids a global-optimum guarantee. Failure after200 iterations or stalled/singular trials is observable rather than silently publishing an initial guess.

Rounding beta to returned Float b before mapping log(a) is coherent with the actual exponent used by the optimizer. Checking the returned coefficients' dimensionless curve against the converged Double curve makes positive subnormal a admissible only when its quantization preserves the requested fidelity. The chosen64*Float.ulpOfOne absolute curve allowance is a numerical publication tolerance, not an arbitrary workload cap. Independent minimization fixtures must still distinguish a stationary but poor fit from the expected small-ratio minima; the proposed different-solver reference satisfies that need if retained/regenerable and accompanied by explicit curve/SSE tolerances.

The accepted smooth design includes the lower-bracket epsilon correction, true endpoint checks, Double physical sigma, tied/equality limiting policy and post-solve floor distinction. The upper tau2 proof and finite Float-input/Double-workspace domain remain sound. No positive-root residual is falsely promised for infeasible, unidentifiable or floor-dominated rows. Duplicate-ID calibration counts and later max fusion remain distinct and documented. Zero bandwidth no longer implies certainty for positive delta.

Finite-aware throwing SGD preserves the existing Float arithmetic and clipping only within its checked domain. It is therefore consistent for a finite coefficient pair accepted by curve fidelity to fail later on an overflowing Float power/product/update: curve calibration fidelity is not a guarantee that every layout state can be evaluated with the old Float gradient formula. Diagnostics/tests should retain this stage distinction. Checking before clip4 is essential; final-buffer checks alone would not catch a masked intermediate NaN. Public input immutability and nontransactional internal inout failure are compatible.

## Representation boundaries and validation

The2^53-1 schedule bound and checked effectiveEpochs*max(1,negativeSampleRate) bound are conservative but defensible numeric representation choices for exact integer count/epoch tracking in Double. They are not a production work limit or responsiveness guarantee, and the brief says so. They do not prove every fractional cadence/update exactly representable; the separate finite/checked due-count conversion remains necessary. Never infer safe Int conversion from <=Double(Int.max), and skip nonpositive due work before attempting a nonnegative conversion. Tests of accepted boundary values belong in pure helpers, not actual enormous loops.

The count/byte checks, early point-count rejection and complete provided-row shape validation cover the former public allocation-before-error routes. The ratio-based PCA initializer avoids the tiny-projection reciprocal overflow while keeping PCA production read-only. Explicit nonfinite config rejection precedes graph/PCA/initialization, and shape checks precede supplied-coordinate value checks. Existing supplied-graph validation of nominally irrelevant options is preserved consistently; it does not silently expand neighbors into a work control.

CSR all-offset preflight precedes every neighbor/distance dereference and resolves the exact interior-overshoot ordering defect without outlawing valid unsorted, uneven, isolated or duplicate rows. KNN-specific LP64/count guards are explicitly authorized, so shared L02 flatten checks are not incorrectly treated as sufficient for KNN's GEMM/output shapes. The count/byte and Float-array domain choices do not promise successful allocation, upstream vendor safety or L04's deferred memory envelope.

For implementation precision, pin typed errors for checked-size rejection consistently in the helper tests and public paths (e.g. invalidDimension for unrepresentable dimensions/counts, invalidData for malformed CSR). The brief already fixes config invalidOperation and runtime operationFailed; the remaining representability error spelling should not be accidental. This is a scoped clarification rather than a blocker.
