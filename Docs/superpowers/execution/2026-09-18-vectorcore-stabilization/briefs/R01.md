# R01 — Preserve the requested metric witness

Status: root-approved contract; dispatch base is recorded in state.json when a worker slot opens.

## Contract and migration

Float-vector search accepts `any DistanceMetric<Float>`. Change `TopKSelection.nearest`, `batchNearest`, the `VectorCollection.search` requirement/default, and all `OptimizedDistanceMetrics` factory returns accordingly. Open the supplied existential into the existing generic helper (or directly invoke its witness); never recognize a type and manufacture another metric or silently substitute Euclidean. Preserve every configuration value carried by a custom or built-in metric. A non-Float metric is rejected at compile time. Breaking changes are authorized: callers holding `any DistanceMetric` must narrow to the Float-associated existential or explicitly cast and handle an incompatible scalar before calling.

Factory names are case-insensitive for every `MetricType.allCases`, including `dotProduct`. Preserve raw values and return nil for unknown names; do not introduce aliases or fuzzy matching.

Keep existing Top-K ordering, NaN and tie contracts. The default collection implementation returns the selected witness's distances and corresponding IDs; metric-aware relevance score changes belong to R05. Preserve the existing provider-first `Operations.findNearest`/batch route, including the override when CPU GEMM would otherwise apply. Do not change provider protocols or numerical kernels in this task.

## Regressions and independent oracle

Create one mechanically enumerated facade table covering Euclidean, cosine, Manhattan, dot product, Chebyshev, Hamming, Minkowski with a nondefault p (use 3), and a custom configurable reverse-order metric. Use `any DistanceMetric<Float>` in the table. The custom metric must carry configuration that changes its scores; exercise at least two settings so a reconstructed default cannot pass.

For each table entry and each facade (`nearest`, `batchNearest`, default `VectorCollection.search`), compute expected scores by calling the supplied witness directly on each candidate, then independently sort `(index, score)` by ascending score and index and take the requested prefix. Do not use `TopKSelection` or the facade under test to construct expected membership. Assert both indices/IDs and finite distances with a tight absolute-plus-relative tolerance. Use nonzero, nonidentical query/candidate vectors for the cosine rows. Cover k=1, an intermediate k, k greater than candidate count, k=0, and empty candidates. Use a minimal test collection with deliberately nontrivial IDs so index/ID confusion fails.

Add the literal regression: query `[0,0]`, candidates `[[3,3],[4,0]]`, Chebyshev k=1 must select index0 with distance3 (Euclidean selects index1). Add literal configured custom results that differ from Euclidean. For the batch facade, use more than one query and compare each independently.

For every factory enum case, test its raw name, uppercase name and alternating-case name; compare the returned witness to direct `createMetric()` on a discriminating query/candidate set. Assert an unknown name returns nil. A count-only test is insufficient.

Retain existing TopKNaNContractTests/TopKNaNWrapperTests as ordering controls and BatchKernelProviderTests as provider reachability controls. A compile-contract fixture should prove a generic helper with `M: DistanceMetric, M.Scalar == Double` cannot pass M to the Float facade, while its Float counterpart compiles. Record the exact compiler diagnostic and command; keep this fixture outside the SwiftPM target so intended failure does not break ordinary tests.
