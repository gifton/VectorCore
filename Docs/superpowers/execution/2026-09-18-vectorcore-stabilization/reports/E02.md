# E02 bounded structured scheduling and reduction laws

## Implementation and migration

The retained task-group routes now use `BoundedExecution`. One phase submits at most the positive root limit, clamped by available work, using contiguous worker ranges. Each worker builds its own output; the parent restores range order. No shared unsafe output pointer, unchecked Sendable output wrapper, per-item task array or quadratic matrix task descriptor array was introduced. The task-scoped observer records phase begin/end and actual worker submission/completion; it is nil in ordinary execution.

Default providers use `maxConcurrency`, rather than `deviceInfo.maxThreads`. Nonpositive limits reject with `invalidConfiguration`, including empty input; unrepresentable range lengths retain `invalidRange` precedence. Positive `Int.max` limits and hints are clamped before partition arithmetic. CPU modes retain their threshold decisions and minimum coarse chunk preference. Initializer `minChunk` remains explicitly ineffective; per-method hints remain operative. The legacy CPU suppression task-local and a shared library region marker suppress nested worker creation, including callbacks on serial branches. User-created fan-out and independent roots are outside this phase-local bound.

Throwing routes validate structure and check task cancellation before work/submission, around each managed work unit and before success. Errors cancel sibling tasks and structured groups await cleanup. A synchronous row/range body remains an indivisible work unit and must cooperate internally for responsiveness. Retained context loops stay in Swift tasks instead of crossing `CPUContext.execute`'s GCD continuation. Context fields are scheduling hints, not an executor/device promise. Nonthrowing nearest, pairwise, statistics and triangular matrix operations retain their complete-result policy when cancelled.

Reductions combine ordered partition aggregates into `initial` exactly once in the parent, inside the shared callback region with cancellation checks before and after each combine. Empty input invokes neither rangeWork nor combine. The documented algebra requires an associative combine and identity initial, not commutativity; arbitrary sequential left folds and partition-independent floating-point bits are not promised. N03 statistics keeps each original logical chunk's accumulator and original chunk-index merge order even when many chunks share one worker.

`CPUComputeProvider.executeBatch` remains a synchronous single full-range call for nonempty candidates and no call for empty candidates. It now rejects insufficient output capacity with a named guard before invoking the kernel. Mode, thresholds and initializer chunk compatibility settings do not schedule or autotune it. The unused private measurement routine was removed. Correctly written kernels preserve oversized suffixes.

Live map factory errors now propagate rather than trapping at `try!`. Retained matrix rows are exhaustively shape-checked before metric callbacks in Debug and Release, and the existing matrix routing threshold is compared without forming `n*n`. R03 self scores, symmetric-metric restriction and similarity semantics remain. Accepted N01 normalization is unchanged. E04 OperationContext is byte-identical to the base.

The refreshed caller inventory at base `433efec697853f1a680317eaf9706dc56675267b` supports removing only the approved dormant nearest/reduction/centroid component, transform combine, CPUContext's unused parallel/chunk helpers, and Sync methods/forwarders other than N03 statistics and batchStatistics. The separate NaNInfinityHandling Sync extension is unchanged. All 272 base code files were present and matched before implementation; the final inventory contains 275 files with eighteen scoped changes.

Root-approved scope addenda are included. First, ExecutionBoundaryTests no longer treats zero/negative default-provider concurrency as a successful configuration: positive-provider success coverage remains, while invalid providers now assert rejection and no callbacks, including huge representable and empty ranges. Second, exactly six optimized nearest parallel helpers changed from private to internal for direct scheduling tests. No public routing gate or signature changed. Four existing child helpers in MemoryPoolBoundaryTests, NormalizationRangeContractTests, VectorCollectionTransactionTests and MatrixMetricContractTests now throw explicitly after a timeout and bounded cleanup, before reading process termination properties. Their earlier guard-return/continue/isRunning checks already guarded access; these are conservative scanner-policy migrations, not four newly reproduced unbounded waits. Normal scenarios, diagnostics and cleanup deadlines remain. The existing child-process Python gate gains a pure conservative scanner for a timeout flag followed by a nonthrowing timeout assertion and subsequent termination-property access. It is a forbidden lexical pattern check, not Swift control-flow proof.

## Numerical qualification for E06

Current public nearest heuristics do not reach the six optimized parallel helpers for widths 512/768/1536 and Euclidean/cosine. Tests exercise these existing helpers directly through the approved internal access; E02 does not activate them. Their finite outputs are checked against independent scalar Double formulas, ties by exact bits, and exceptional outputs against unchanged direct range kernels.

An initial test incorrectly expected every NaN candidate to yield a NaN fused-cosine result. All 777 failures were this repeated expectation. A retained standalone probe linked against unchanged baseline Release objects confirmed fused cosine returns positive-zero bits for the candidate `[NaN, 1, 0, ...]` at each width; Euclidean retains NaN in these fixtures. E02 preserves this numerical policy and reports it for E06 routing review rather than changing kernels or claiming universal NaN propagation. Accepted Top-K NaN/tie tests remain required regressions.
