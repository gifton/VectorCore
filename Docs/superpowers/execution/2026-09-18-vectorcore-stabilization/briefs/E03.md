# E03 — Atomic configuration mutation

Root-approved contract. Schedule only when BatchOperations.swift is free from E01/E02/N03/E06 work. API-03 closure candidate; no task dependency. Breaking @Sendable closure migration authorized.

## Context and design

Package.swift enables StrictConcurrency and ExistentialAny for Core. Actual I01 Debug compiler invocation confirms -swift-version6, StrictConcurrency, ExistentialAny; no default-isolation flag or approachable-concurrency opt-ins. The container is a generic actor, with no UI/MainActor ownership. Current BatchOperations.updateConfiguration separately awaits get and update; source and audit show stale snapshots overwrite intervening changes. Individual actor memory access is already isolated.

Add an actor-isolated synchronous `modify(_ body: @Sendable (inout T) throws -> Void) rethrows` operation to ThreadSafeConfiguration. Inside the actor, copy the current binding to a candidate, invoke body without suspension, then publish candidate only after success. The operation must not await, create Tasks, or call an async closure between reading and publication. Keep existing get and whole-value/key-path update operations. No locks, unsafe sendability annotations or new dependencies/platform floors.

Change BatchOperations.updateConfiguration to take the synchronous @Sendable throwing closure and be async rethrows, forwarding through one awaited actor modify call. Existing nonthrowing closures need only their existing await; closures capturing mutable non-Sendable state must migrate to immutable Sendable snapshots. Update the API example to include await. This task adds no numeric configuration rejection: values retain the previous publication policy; E06 defines/validates consumed settings later. If a caller's closure throws, propagate the identical error and preserve every prior BatchOperations.Configuration field. Do not activate the currently ignored live configuration at operation gates.

Generic T:Sendable need not be a deeply copied value. Candidate assignment cannot undo effects performed through external reference aliases or arbitrary closure side effects. Document that modify atomically publishes the T binding and that rollback of contained mutable references requires caller-supplied value/snapshot semantics. BatchOperations.Configuration consists of value fields and supports the complete rollback claim. Do not promise universal deep transaction rollback or claim Sendable alone proves value semantics.

## Regressions

Retain runtime RED: 100 structured concurrent BatchOperations updates increment one integer field, expected initial+100. Repeat a bounded small number of rounds if needed to expose the audited race and report actual counts; do not inject sleeps or production hooks to fake it. Separately, 100 updates to each of two independent fields must preserve both totals. New actor.modify tests exercise a local value struct similarly. Closure is synchronous: no blocking semaphore/barrier inside it, which would deadlock the repaired actor. A start barrier outside the update may coordinate tasks.

Use isolated subprocesses with complete initial-state restoration for global configuration scenarios. Suite-local serialization alone does not isolate unrelated suites that mutate the same global configuration; local actor scenarios can remain in the parent. Cover all six configuration fields: successful publication, a closure mutating every field then throwing the unique sentinel, complete previous-value preservation, and subsequent successful update. Exact identity comparisons for stored floating configuration bits are appropriate for rollback, not approximate numerical equality. A concurrent snapshot observation must never see a partially mutated field tuple. Verify generic actor get/whole-value/key-path update controls remain valid.

External Swift6 consumer must import public VectorCore without @testable, call actor.modify and BatchOperations.updateConfiguration from nonisolated and actor/MainActor callers with immutable Sendable captures, and compile successful nonthrowing and throwing forms. A separate negative fixture captures a non-Sendable mutable object in @Sendable update and must fail at the intended capture boundary. Retain exact diagnostics; compile failure is contract evidence, not runtime RED. No @preconcurrency/unchecked workaround.
