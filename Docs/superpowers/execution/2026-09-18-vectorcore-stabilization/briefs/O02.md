# O02 — Tiered mutation writeback and copying cost

Status: contract approved; dispatch only after O01 acceptance/integration. Root will record the base. Preserve O01's lifetime/COW repair.

## Observable contract and implementation boundaries

Mutable buffer borrows use partial-write semantics consistently: writes performed before a thrown error persist in the mutated value, while retained copies and preexisting iterators remain snapshots. This applies to all four tiers, including empty storage. The closure's return value/error must propagate unchanged. Do not roll back element writes. Both InlineBuffer's array-to-tuple writeback and TieredStorage's local-tier writeback must run on every exit. Standard bulk mutation must write back its array at all.

Unique standard/aligned scalar writes must not copy the complete buffer. Remove incidental enum/class retains before testing uniqueness or mutating Array storage. Root approves the move-out/restore pattern used by O01: temporarily replace the private enum payload, mutate the extracted owner, restore it (defer on throwing paths). A shared owner detaches once; later unique writes reuse it. Check aligned ownership at the actual outer class, not `var mutableSelf = self` inside a method. Standard Array should see only real aliases, not the enum's temporary extra retain. Avoid an unconditional new allocation.

Do not activate unrelated callers of the previously broken bulk primitive. This task repairs its contract and verifies it directly. TriangularMatrix scalar/setAt and fromFullMatrix construction should benefit from the fixed storage path without rewriting parallel scheduling. E01/E02 retain integer-boundary and task-budget policy. Reserve-capacity/tier-transition features are out of scope unless this mutation repair demonstrably affects them.

## Behavioral regressions

Mechanically exercise counts 0,1,4,5,512,513,2048,2049 and matrix sizes 3,4,32,33,64,65. Normal and throwing buffer writes must preserve actual changed values and the return/error. Cover both initially unique and retained-copy cases, retained iterators, first/last element writes, and empty buffers. Use exact integers; inspect every original element rather than only counts. Include reference-bearing elements on throwing writeback and check replaced/new element lifetimes to ensure defer restoration introduces neither loss nor double destruction.

For nonempty counts, capture backing owner addresses and retain the original while first mutating a copy; first mutation detaches, next ten scalar writes and repeated bulk borrows reuse the new allocation. Check ordinary numeric matrix subscript and generic setAt. Address observations are necessary value-semantic controls but are insufficient on their own for a performance claim.

## Release allocation evidence

Retain fresh before/after optimized evidence for repeated unique scalar writes, one shared detach followed by unique writes, and complete matrix construction at n33/64/65 and a geometric size series. Measure allocation/copy events, not wall-clock thresholds or address stability alone. Preferred method is an external allocation interposer/probe against the actual Release library. A validation-only exact-source counter fixture plus actual Release generated-code evidence is acceptable only if the report distinguishes fixture event counts from library evidence and demonstrates the standard Array COW path as well as explicit aligned allocation. Root must adjudicate sufficiency before OWN-13 closure; do not quietly downgrade this requirement to pointer checks.

If using an interposer, validate the probe itself against known Array/aligned allocations, bound the measured region to the operation, and record which allocation entry points are counted. Do not infer absence of copying from an unverified zero counter. If using a source fixture, mechanically strip instrumentation and verify the remaining bodies match current source; never modify the historical audit fixture. Check optimized uniqueness/copy call paths to account for compiler-generated Array COW. No production instrumentation or new dependency.

For unique writes require no full-buffer detach events after setup. Retained-copy mutation produces one detach, later writes none. Construction allocation/copy bytes must grow linearly with stored element count within the measured series; record raw counts/bytes and setup boundaries. Do not claim latency improvement or production scale readiness.
