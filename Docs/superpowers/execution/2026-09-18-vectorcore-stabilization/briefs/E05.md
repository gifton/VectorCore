# E05 — Reentrant calibration and single publication

Root-approved contract, independently accepted in reports/E05-design-review.md. API-29 only; Q02 retains tuner measurement quality, strategy accuracy and key provenance. No performance target, new routing gate, GPU work or sibling edit. Inspect Providers/AutoTuning.swift and the actual Operations.computeDistances calibration caller before implementation.

## Observable concurrency contract

AutoTuning's synchronous API must never call a calibrator or print/log arbitrary formatted output while holding its state lock. Protect cache, in-flight reservations and cumulative timing under the same lock. One callback at most may be executing for a given existing (dim, kind) key; different keys can calibrate concurrently. Preserve the existing key definition for this task.

Choose nonblocking same-key behavior: after checking an existing published value, a request encountering an in-flight reservation immediately returns defaultTuning(dim:), without invoking its callback and without publishing that provisional default. This applies equally to recursive calls and concurrent callers. It deliberately avoids waiting on a synchronous caller that may itself be the active calibrator. Direct recursion and cycles across two keys must finish. A concurrent `get` may observe nil until publication; no partial tuning is exposed. This is single-flight execution with a provisional fallback, not a promise that all simultaneous callers receive identical values.

Reserve under the lock, release it, invoke the callback on the calling thread, then reacquire to publish and retire the reservation. A manual `set` during calibration wins: keep the explicit cached value, return it from the successful calibrating call, and do not overwrite it with the measured value. Later requests receive that manual value. A same-key recursive set has the same behavior. Logging takes an immutable snapshot under the lock and formats/prints it afterward; no unlocked read of accumulatedCalibrationTimeMs remains.

Extend the calibrator closure to `() throws -> CalibrationProbes` and calibrateIfNeeded to `rethrows`. Existing nonthrowing closures remain callable without try. If a callback throws, retire its reservation, retain any concurrently set manual value, charge its measured elapsed time, and propagate the identical error. Do not cache a default merely because a callback threw. A subsequent request can retry unless the existing time budget has been exhausted. A fatal trap/nonreturning callback cannot be recovered; no bounded callback-duration claim is made.

Keep the existing 20ms cumulative calibration time as an admission safeguard: sum durations of completed callbacks, including failed callbacks and overlapped work. Before starting a new key, a reached cap publishes/returns its default without calling user code. Already admitted callbacks may finish after the cap; concurrent admissions and an arbitrary slow callback can overshoot it. This is not a hard wall-clock or per-call deadline. Disabled configuration retains its current no-callback/default behavior, with get returning nil. No environment mutation inside a running test process: use fresh child processes for disabled/bias/printing controls.

## Callback failure and arithmetic safety

Because a reservation must be retired on every recoverable path, guard the calculation boundary against invalid user probes before floating-to-Int conversions. This is a narrow safe-fallback contract, not Q02 calibration-quality closure. For dim<0 or providerCores<=0 return the default without invoking/reserving/caching a callback; check these before a cached-value shortcut. Zero dimension remains valid. Probe fields must be finite, nsPerCandidateSeq>0, parallelOverheadNs>=0 and effectiveParallelFactor>0. Invalid probes publish the default and retire the reservation. Finite inefficient probes retain the existing inefficient threshold behavior.

For otherwise valid probes, preserve the existing calculation/bias/clamp/alignment formulas where their intermediates are finite and representable. Any nonfinite intermediate or unrepresentable integer conversion instead produces the default. Avoid rounded Double(Int.max) upper bounds that admit Int.max+1; compare against safe finite caps before converting. Keep all existing documented min/max tuning constants. A manual value published while calculation runs still wins over a fallback. Do not change `set` validation, add public initializers or alter kernel selection in this task; public type-construction/API usability belongs to D02 and strategy validation to Q02. Tests may use @testable to construct the existing memberwise values, while a compile fixture can consume public CalibrationProbes/Tuning values supplied as parameters.

## Independent review clarifications

A manual set does not retire an active reservation; the original callback owns its eventual cleanup. Stop the callback-duration timer immediately on success/error before numerical calculation, and document that nested callback durations count individually, so nested work can contribute to both outer and inner durations. Preserve the exact Int.max/2 inefficient sentinel directly rather than converting its rounded Double representation back to Int. For the actual Operations.findNearest route, the public return is an array, not SearchResults metadata: use k equal to fixture candidate count and verify every returned index/distance plus array cardinality.
