Every selected case has a boundary version, top-level timing scope (prepared/reused-input or setup-inclusive), operation/work unit, input/output representation, and explicit inclusion flags for packing/conversion, output allocation, provider scheduling/observations, kernel work, output consumption and correctness validation. The case catalog used for execution supplies this record; a second unrelated list is insufficient. Fixture and boundary identity must change when measured work changes. Missing/legacy identity follows V02's explicit metadata-override policy, never an accidental compatible default.

Existing scalar/vector cases may use a simple boundary; batch/matrix cases must say what their bodies actually do. Distinguish prepacked kernel-plus-consumer timings from setup-inclusive timings. A public matrix API that packs internally is an API-call measurement even if caller inputs/output are reused; never label it a prepacked GEMM kernel. Existing AoS/provider calls include their scheduler, observation and intermediate-allocation costs. Existing SoA/FP16 conversions outside timing remain outside their prepacked case. Existing fused/preNorm cosine preparation differences remain explicit. Work units stay candidates for vector batches and produced entries for matrices, with checked products.

Provide separate opt-in setup-inclusive companions for representative existing batch routes: optimized AoS FP32, SoA FP32, AoS FP16 and SoA FP16 at widths512/768/1536 wherever their actual route is supported. Each starts from the same immutable FP32 query/candidate fixture and ends with all requested scores produced and consumed; each invocation creates its output and performs that route's required query/candidate preparation. Inputs/independent references are prepared outside. Reuse the actual current kernels and V02 catalog/filtering: unavailable optional routes are reported as unavailable, never silently replaced or counted as tested. Keep existing default route eligibility; new companions are explicitly selected through a supported timing-scope option or separate documented suite, resolved by the implementer and reported before editing CLI. No duplicate full runner.

The reusable-output counterparts explicitly exclude preparation/output allocation. Different top-level scopes cannot form an automatic speedup pair. Per-case cross-run comparison requires exact full boundary identity under V02's metadata policy. Preserve V02's two declared A/B families and counts through explicit family-specific allowed differences: Euclidean versus squared Euclidean compares inclusion of sqrt and therefore different numerical outputs; fused versus preNorm cosine compares prepared-input strategies with preNorm preparation excluded. Display both full boundaries and the comparison's purpose; the latter is not an end-to-end strategy-speed claim. Other mismatches remain invalid. New companions require an explicit declared comparison to pair, rather than inheriting one from a broad scope/name match. A reduced-precision comparison reports its measured error on that fixture; equivalent requested distance outputs do not imply bitwise-equivalent arithmetic. Preserve V01's real provider observations/error propagation and V02's selection-before-setup rule. Never subtract a separately measured preparation cost to manufacture an end-to-end value.

## Observe actual outputs and inspect optimized code

All timed routes must consume the numerical result, not just the bytes of an owning handle. Preserve V01's existing consumed provider reductions. Matrix must traverse all produced scores into an opaque scalar checksum/fold after each invocation; checking a structurally zero self-diagonal is insufficient. The same rule applies to new batch companions. A deterministic UInt64 fold of Float bit patterns is acceptable and avoids cancellation in the consumer; it is an anti-elision observation, not a numerical oracle or collision-free fingerprint. Tests change each first/middle/last output individually and confirm the consumer sees the change for those fixtures. Numerical correctness remains out of the timed body using independent references and finite-aware comparisons.

Current blackHole writes an unsynchronized global sink. Keep sink use confined to the serial benchmark measurement driver; workers return values to the parent and do not write the shared sink. Do not claim it is thread-safe. If implementation needs concurrent consumption, return to root for a per-instance design rather than adding a global lock to all measurements. Clarify that generic sink bytes cover a value's representation only; no annotation proves traversal of heap elements.

Reusable-output labeling applies only to actual caller-owned reusable buffers. Provider-owned intermediate/result allocations remain included and must be recorded separately. If the existing AoS/provider API cannot reuse a requested output, label its actual API boundary or mark that counterpart unavailable; do not introduce a production kernel or imply allocation-free execution.

Retain emitted code from actual Release linked objects/executables, with compiler/link commands and source/object/module/binary hashes. Inspect at least one provider AoS batch, one SoA/FP16 batch and the matrix consumer route; record symbol/instruction/call anchors showing the real operation and output dependence survived. A separately compiled toy scalar function is not evidence about the measured route. If inlining changes symbol names, inspect the actual caller and record that association. Absence of an easy symbol is not proof of elimination. Prefetch helpers must not be called hardware prefetch instructions unless the inspected path actually contains them; no new intrinsic is authorized.

For representative512D fixtures use bounded N values such as257 and4096 for vector routes and17/65 for matrix routes; these are validation fixtures, not a production envelope. Run warmups, retain at least nine raw sample averages and actual repeats, and report median and variation with the statistical unit explicitly per-sample average ns/operation. Measure the same consumer on a precomputed output as a separate consumer-only record with identical N/output representation. Show that overhead; do not automatically subtract it or treat it as zero. Run one measurement process at a time, retain host/toolchain/build flags/thermal observations when available, and report unavailable fields honestly. No pass/fail speed threshold.

Use calibrated allocation-event/requested-byte instrumentation on representative actual timed bodies, after setup/warmup, to establish which phase allocates. O03's existing process-local collector can be linked unchanged into a dedicated V04 probe with a new fixture; retain known C, Swift Array and no-op controls. It refuses to replace an existing diagnostic callback, and it cannot be shared across simultaneous probes. Output checks happen after stopping the collector. Allocation counts and requested bytes are independent of elapsed samples and may not be relabeled retained/peak memory. If a desired instrument is unavailable, retain the limitation and keep that acceptance item open instead of replacing measured data with source arithmetic.

## Separate handles, payload models and measured process memory

Replace MixedPrecisionPerformanceBenchmark's footprint table with explicitly labeled columns: owning-handle stride, logical scalar payload bytes, and optional independently measured records. For width D, scalar payload is D*MemoryLayout<Float>.stride versus D*MemoryLayout<UInt16>.stride with checked arithmetic. The 2:1 scalar-width relationship excludes headers, capacity, alignment, padding, conversion temporaries and sharing. The100000-vector example may remain only as a labeled logical-payload and handle-array model; it cannot call either value total footprint or actual savings. Independent test constants cover512/768/1536. Do not assume equal values imply shared storage or that repeated value copies allocate new payloads.

Rename the MinimalTests methods currently called MemoryFootprint to traversal/magnitude timing, preserving their real anti-elision/numeric checks and V03's strict-performance observation wrapper. Updating names/inventories is a coordinated migration, not removal of tests. Keep pool drain documentation limited to releasing available handles; retained array capacity and external aliases can keep allocations alive. Replace GC/lock-free/refill claims with the actual ARC/value-cache/lock behavior after Q02.

Add a standalone Release public-API memory probe with fresh bounded process per representation/width/N/sharing case. Required fixtures include N1,257,4096 at all three widths for FP32 and FP16, independently constructed equal-valued vectors versus repeated copies of one vector. Independently constructed FP16 values are converted from transient per-element FP32 sources, and the source payloads must not remain retained during the final measurement. All vector coordinates are touched/consumed. Prove the fixture's intended construction path and preserve original values; do not infer alias identity from equality. Keep datasets alive across the measurement with explicit lifetime scopes, then release them before the final snapshot. Use separately warmed runtime/probe setup and report pre-creation, retained, and post-release snapshots.

For Darwin, use checked `task_info(MACH_TASK_BASIC_INFO)` snapshots for process resident bytes and process-lifetime maximum resident bytes. The current SDK mach/task_info.h defines both units as bytes. Report the kernel return code/count and unavailable values explicitly. The maximum is cumulative since process start, not reset at the dataset window and not dataset-specific peak. Fresh children bound prior work; retain the pre-creation maximum too, and do not subtract maxima as though the result were an exact allocation measurement.

Use `malloc_zone_statistics(NULL, ...)` for current allocator `size_in_use` and `size_allocated`, labeled as process-wide sums across zones. The current SDK malloc/malloc.h calls max_size_in_use a high-water mark of touched memory and says NULL sums zones; do not relabel the sum of zone high-water marks as simultaneous process peak. Omit that field or report it only under its precise aggregate name. Current allocator deltas may include runtime/bookkeeping noise and exclude direct VM allocations; report signed deltas and raw snapshots, not an exact byte count attributed solely to the dataset. Process resident values likewise include other memory and allocator retention. Record logical payload alongside these measured values without predicting a50percent RSS reduction. This supplies measured retained/peak process observations with explicit scope, not object-precise peak-heap attribution.

Memory probes record complete workload/representation/sharing/seed/build/source identities, fixture lifetimes and measurement API/units. Calibrate allocation-event mechanics independently and include a touched known allocation in the snapshot probe to validate that observations are live, without an exact RSS-delta assertion. A task_info failure, allocator unsupported platform or missing fixture is an explicit uncompleted measurement, not zero bytes. Do not add a sampled-memory thread, hook production allocators, intentionally exhaust memory, or change macOS SDK/platform floors. No GPU/RSS budget claim.
