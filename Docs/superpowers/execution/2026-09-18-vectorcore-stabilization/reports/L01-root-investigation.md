## Source-established numerical paths

- QR accumulates Float squared norms, then forms Float alpha-beta and its reciprocal, updates Float factors and accumulates Float Q. A widened sum immediately narrowed into those old operations would not close the class. Known actual audit RED: [s,s] at 1e-25 and 1e20, with representable sqrt(2)*s, loses normalization or returns NaN/Inf.
- SVD uses Float alpha/beta/gamma and compares gamma squared to epsilon squared times alpha*beta. Both sides underflow or overflow at ordinary well-conditioned global scales. It then uses Float zeta-squared rotations, Float final squared norms and a reciprocal. Known actual audit RED: scaled column-major [1,0,1,1] has wrong spectrum and U correlation about0.707 at1e-12/1e15 despite condition number2.618. Reconstruction alone is an insufficient oracle.
- Eigen Float Frobenius sum can overflow and currently rejects otherwise representable spectra; tiny scales can lose its threshold. Float theta-squared rotation is another range concern. Only lower triangle is semantically input; the ignored upper triangle must not acquire a finiteness requirement accidentally.
- Existing header claims unconditional robustness/convergence and <15 sweeps exceed the actual finite 60-sweep implementation and evidence. Replace with tested/qualified statements when repairing.
- Existing LA.maxAbsDiff and orthoDefect can hide NaNs through max reductions; new regression references must be finite-aware and those touched legacy invariant helpers need an explicit nonfinite failure result.

## Root numerical direction under consideration

Retain Householder QR, cyclic symmetric Jacobi eigen and one-sided Jacobi SVD, column-major layout, spectrum ordering and wide-SVD transpose mapping. Use Double working factors, accumulators, convergence tests, reflector parameters, rotations and normalization throughout, with conversion to public Float only at the result boundary. Float inputs have ample exponent headroom in Double for original squares/products under the existing Int32 dimension model, but do not claim that this alone proves arbitrary-condition convergence. Use a stable two-term hypot/rotation construction rather than squaring a potentially huge ratio, and direct widened division when normalizing.

Define a dimension-aware relative convergence criterion; do not compare squared Float expressions or retain a Float-noise explanation after moving work to Double. Preserve bounded sweeps and throw operationFailed on genuine nonconvergence. Check public result conversion and reject overflow/nonfinite factors with a typed error rather than return invalid decomposition. Exact rank-deficient null-space basis completion remains explicitly outside this repair; distinguish it from the full-rank orthogonality defect. Final policy for unrepresentable nonzero subnormal spectra versus normal Float rounding is still to be specified in the binding brief.

Finite-input validation should consistently reject nonfinite referenced input for both Swift and LAPACK providers (QR/SVD all entries, symmetric eigen only lower triangle). Do not reject ignored upper-triangle NaNs. Result validation at both providers may be needed to give a coherent Float representability contract; the exact ownership scope must include LAPACKLinearAlgebraProvider if selected. Input arrays must remain value-unchanged.

Independent fixture direction: analytically known 2x2 golden-ratio spectrum; one-column [3s,4s] (norm5|s|) and [s,s]; orthogonally constructed rectangular full-rank matrices with known spectrum; both tall and wide; diagonal and small symmetric analytic matrices with known eigenvalues. Use exact power-of-two Float scaling across subnormal/normal/extreme exponents, and scaled Double reconstruction/orthogonality/residual calculations. Compare spectra using a Float-rounding-aware allowance at subnormal output, rather than promise relative error below output spacing. Include actual scales with representable outputs and explicit output-overflow cases. The golden-ratio fixture can use high-precision Decimal-generated expected values; no NumPy/LAPACK output may serve as the sole independent oracle. Existing PCA task-local Swift-provider route needs a small ordinary-range end-to-end control; centering policy stays L02.

## Workspace investigation remains separate

Local C findings: vc__lwork_from_query casts ceilf(q) to int64 before validating finite/range, adds 1/64 margin and clamps to INT32_MAX; sgesdd computes signed 8*minmn before size_t cast; ssyevd trusts integer query positivity; allocation byte products have no common checked helper. Swift dimensions individually fit Int32, so their product fits 64-bit Int; that fact does not prove C/Fortran workspace arithmetic. No practical memory corruption or giant allocation has been reproduced.

Reviewer is inventorying local arithmetic/testability and boundaries of what can be established about Accelerate query internals. Root has not selected an arbitrary panel/workload cap. Candidate local repairs include checked pure workspace/byte helpers, validation before Float-to-integer conversion, widened auxiliary counts, distinct workspace-overflow error mapping and pre-query representability checks derived from actual routine requirements. Public supported-envelope wording must distinguish arithmetic representability from allocation success and practical workload scale. Tests should exercise pure boundary calculations without giant arrays, plus normal linked C/Swift calls.

## Primary reference material consulted

- [Netlib DLARFG](https://www.netlib.org/lapack/explore-html/d8/d0d/group__larfg_gadc154fac2a92ae4c7405169a9d1f5ae9.html): reference Householder generation uses norm/hypot and safe-range handling. This is algorithm guidance, not proof of the proposed Swift implementation.
- [Netlib DGESVJ](https://www.netlib.org/lapack/explore-html/d9/deb/group__gesvj_ga7aec05d2a1523bbeee77ece21b12187c.html): one-sided Jacobi SVD documents orthogonality/convergence, scaling and representable singular-value limitations. No claim is made that the simpler Swift fallback has all LAPACK accuracy guarantees.
- [Netlib SGESDD](https://www.netlib.org/lapack/explore-html/df/d22/group__gesdd_gab9ffdde22b38f0cc442e44cbea23818f.html): thin-vector workspace guidance includes 4*k*k+7*k, with integer workspace8*k (k=min(m,n)); the documentation calls these sufficient rather than universally tight minima.
- [Netlib SSYEVD](https://netlib.org/lapack/explore-html/d8/d30/group__heevd_ga3cac18a55c8b7b87a42cfa26c1f3499a.html): eigenvector mode needs at least1+6*n+2*n*n floating workspace and3+5*n integer workspace for n>1; eigenvalues-only differs. These reference requirements do not alone prove vendor query-internal arithmetic safe.
