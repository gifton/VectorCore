## Division

Compute each scalar quotient directly, never unconditionally multiply by a reciprocal. VectorProtocol and VectorFactory /, /= and inPlaceDivide must agree for faithfully stored coordinates; concrete optimized / must also use actual division. Preserve existing vector zero-divisor rejection (+0 and -0), including empty vectors. Raw and array providers retain native IEEE division for zero/nonfinite divisors: signed zero, infinities and NaN classification follow direct scalar division. No new blanket finite-input restriction on division. For affected raw scalar-division methods, count>=0 is a documented precondition and count0 accesses nothing. Preserve exact in-place aliasing where current callers use it; partial overlap remains a caller obligation, not a new support claim.

The SIMDProvider default and SwiftFloat/Accelerate Float+Double scalar division implementations need separate coverage; SwiftDouble inherits the default. SIMDOperations forwarding, DefaultArraySIMDProvider, SwiftSIMDProvider adapter and AccelerateArraySIMDProvider must observe the repaired behavior. Do not replace the failing vDSP scalar divide with another untested reciprocal path. Elementwise vector/vector and raw binary division are controls; change them only if the same actual defect is reproduced and root approves that scope. Do not redesign generic operator factory-error handling beyond the requested arithmetic.

## Numerical core

For FP32, Double accumulation has a proven range margin: Float converts exactly; each square has at most48 significant bits; nonzero squares are >=2^-298 and <2^256; at most Int.max terms on this host sum below2^319. Accumulate squares with compensation (or a root-reviewed equivalently justified scheme), compute a Double norm, and divide in Double before rounding output coordinates once to Float. Do not reconstruct or invert a Float norm. The same helper can return optimized magnitude/magnitudeSquared by rounding the final widened result once: infinity is valid when that scalar result is actually unrepresentable, while normalization can still succeed. Float16 may likewise widen exactly to Double; it must not accumulate a large q in Float16.

For Double and wider native scalar formats use positive finite s=max(abs(x)), compensated q=sum((x/s)^2), then output (x/s)/sqrt(q). Do not form s*sqrt(q) or1/s for normalization. Never indiscriminately narrow arbitrary Scalar to Double. The full finite-range regression guarantee covers Float and Double and faithful built-in storage; a generic native fallback must detect nonfinite/unrepresentable q and return a checked failure before writes (unchecked rejection) rather than assert a universal range theorem for exotic BinaryFloatingPoint formats. Output underflow is permitted where coordinates are too small to represent; use normwise/absolute accuracy, not relative accuracy for every tiny component.

A shared internal/usableFromInline helper may live in Operations/Kernels/NormalizationCore.swift. No new public unchecked bypass or scalar-format protocol is needed. It must work through valid scoped borrows, support O04 Float-natural alignment, and never inspect a pointer outside its owned borrow. No allocation proportional to an unvalidated external count. Preserve S01 shape guards and O04 binding/allocator changes.

## Observable normalization policy

Checked normalized() Result and optimized checked in-place kernels validate all input before writes. Empty input fails invalidOperation("normalize", reason naming empty); nonempty input containing any NaN or infinity fails the same error family with a nonfinite-component reason; otherwise all signed zeros fail with a zero-vector reason. Nonfinite classification precedes zero classification. Failure leaves all original coordinate bits unchanged. Finite nonzero Float/Double faithful representations succeed with finite, correctly directed near-unit output, even when the scalar norm or reciprocal cannot fit. The generic mathematical transformation cannot promise lossless output for INT8/custom lossy storage: retain an explicit representation-fidelity qualification and leave quantization quality/parameters to Q01.

Typed normalizedUnchecked() requires finite nonzero input and a representable internal normalized calculation. Enforce that precondition in Debug and normal Release with an identifiable diagnostic, before mutation; no -Ounchecked guarantee. The pointer overload additionally retains O04 dimension0 no-access behavior, rejects negative dimensions, and rejects nonempty invalid input before writes. Existing documented undefined/unchanged behavior for unchecked invalid vectors becomes deliberate rejection; record migration and update stale comments.

Permissive array-provider normalize, normalizedFast, normalizeFast and normalized(tolerance:) preserve empty/zero/nonfinite inputs unchanged by coordinate bits. They may return an unnormalized input, which their docs must say. Finite nonzero inputs use the same stable mathematics. Fast default tolerance remains1e-6. Custom tolerance must be finite and >=0 before any early return; -0 is accepted and, like+0, disables early return. The early-return test remains strict abs(computed widened norm-1)<Double(tolerance), using norm, not squared norm. A large valid tolerance intentionally permits a non-unit return. Do not silently unify this with existing isNormalized squared-norm1e-6 or NormalizationHint auto-detection0.001 conventions.

Both Operations.normalize's default-provider path and public Array.normalized() async via TransformOperations must share permissive zero/nonfinite policy. TransformOperations has separate serial/parallel normalization bodies and must be repaired in both. Retain each route's current execution/scheduling gates and input order; propagate factory creation errors unchanged. Each row has its own dimension and still passes through the required factory; preserve S02's dimension/factory behavior and honor explicitly supplied providers. Custom providers may define their own semantics; do not bypass their witness.

Root route-inventory addendum: public Vector.safeNormalized in NaNInfinityHandling.swift independently reconstructs a Float magnitude and must join this repair. First apply existing handleNonFinite(options:) to the original vector, retaining that method's strict-before-propagate-before-replacement precedence and error types. If the handled vector still contains nonfinite coordinates, return it unchanged by bits; permissive options need not guarantee a normalized or finite result. Otherwise normalize finite nonzero handled coordinates through the stable core. For all-zero handled input retain the existing safeNormalized special case: throw zeroVectorError(operation:"normalization") if strict, otherwise return all-NaN if propagateNaN is set, otherwise return the handled zero vector unchanged by bits. Thus replaceAll can replace infinities with finite extremes and normalize the resulting vector safely; NaN-only replaceAll becomes zero. Do not reconstruct a Float magnitude or reciprocal. This intentional policy clarification requires tests and migration documentation; safeDivide/handleNonFinite/safeLog remain read-only here. The added route must receive scoped independent design review before dispatch.

MatrixDistance normalization uses the stable Float core: finite nonzero rows normalize, zero rows remain zero, nonfinite rows become NaN rows. Keep the NaN-preserving ternary distance clamp. Verify actual prepared/unprepared GEMM query/candidate propagation, including invalid-vs-zero and unaffected valid pairs; filling a row is not sufficient evidence. Packing, dimension/size arithmetic, score meanings and diagonal policy remain R03/other tasks.

NormalizationHint normalizedWithHint conveniences must verify the actual returned Float coordinates before advertising true, including custom lossy IndexableVector conformers. Use finite-aware widened norm residual <=8*Float.ulpOfOne. Checked convenience returns nil if the result cannot satisfy that postcondition; unchecked convenience may return a wrapper with isNormalized false and no cached unit magnitude if representation writeback loses it. Built-in faithful outputs should satisfy the postcondition. Keep caller-asserted known-unit constructors unchanged and retain I01 invalidation/decoded-hint policy. Do not alter unrelated auto-detection tolerances.

NormCache's buildNormalized_* consumers gain finite-range correctness from checked normalization but keep failure inputs as before; describe zero/nonfinite retention accurately. Its three preNormalized helpers must propagate nonfinite dot results as NaN before finite clipping, so invalid retained inputs do not become plausible finite distances. Ordinary NormCache.build and batch_cosine_withNormCache still have separate dot/norm-square range limits; do not change or claim them repaired. Full cosine/distance-range safety is not N01 closure.
