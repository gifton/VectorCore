## Parameters and calibration

Share one calibration operation between LinearQuantizationParams and QuantizationSchemes.perVector. Original finite ordered minValue/maxValue, including signed-zero bits, remain metadata; reject nonfinite or reversed bounds with a named nonthrowing guard before arithmetic. All-zero range uses scale1/zeroPoint0 while preserving requested isSymmetric. Symmetric nonzero: ideal scale=max(abs(Double(min)),abs(Double(max)))/127, zeroPoint0. Asymmetric: include zero using lo=min(Double(min),0), hi=max(Double(max),0); ideal scale=(hi-lo)/255; zeroPoint is nearest-away rounding of -128-lo/idealScale, floating-clamped to[-128,127] before Int32 conversion. Compute zero point from ideal Double scale, then round scale to Float and clamp upward to Float.leastNonzeroMagnitude.

Newly calibrated tuples must decode every legal byte to finite Float. Let d=max(abs(-128-zeroPoint),abs(127-zeroPoint)); cap scale at the greatest Float whose exact Double product with d is <=Double(Float.max). Compute a Double quotient candidate, Float-round, then step down if Double(candidate)*Double(d) exceeds Double(Float.max). The product of a Float significand and d<=255 is exact in Double. Use the lesser of rounded ideal scale and this cap. Symmetric storage/quantization supports the full byte domain[-128,127]; near Float.max positive endpoint saturation can be about one step. Correct misleading[-127,127]-only claims. All-zero scale1 is already safe.

Endpoint regression acceptance is abs(Double(decoded)-Double(input)) <= Double(scale)+2*Double(abs(input).ulp)+2*Double(abs(decoded).ulp), with a least-subnormal floor and explicit finite checks on input, decoded value and tolerance. Use finite ulp spacing; never nextUp-max subtraction, which is infinite at Float.max. This is the bounded regression criterion, motivated by the review's real-arithmetic one-step argument; do not claim a universal finite-precision proof. Arbitrary out-of-interval inputs have saturation semantics, not this endpoint bound. Zero inclusion intentionally trades some narrow far-from-zero interval resolution for a representable zero point.

QuantizationSchemes single-vector perDimension remains unsupported and rejects before an empty shortcut. Per-vector empty values use scale1/offset0. Its manually supplied QuantizationParams arrays/analysis statistics are separate existing contracts; do not broaden this task to their redesign.

All direct empty SoA/calibrator operations use canonical min=+0/max=+0/scale1/zeroPoint0. SoA defaults to symmetric; the ordinary internal calibrator preserves requested symmetric/asymmetric mode. Unsupported perChannel calibration rejects explicitly before empty handling. Explicitly supplied parameters remain validated/preserved even on empty conversion.

Distribution calibration uses an absolute-magnitude percentile: finite p in(0,100], validate p and every input coordinate before sorting/empty return. For N>0, select sorted absolute magnitude at clamped nearest-rank index ceil(Double(p)*Double(N)/100)-1; p=100 selects N-1 directly. Clamp in floating space before any Int conversion, so a rounded Double(Int.max) is never converted out of range. This defines the floating evaluation of rank, not exact rational indexing for every enormous N. Calibrate[-threshold,+threshold] symmetrically. Empty input returns canonical zero parameters after argument validation. Include explicit small-N examples and extreme artificial index-helper controls without huge allocation.

## Conversion, decoding and nonfinite policy

Scalar/AoS/SoA conversion shares the observable Double operation: value/scale+zeroPoint, round nearest-away, clamp to[-128,127] in Double, then cast. No Float reciprocal or cast-before-clamp. Ties refer to the computed Double intermediate, not an exact-real rational theorem for every legacy tuple. Finite Float divided by a positive finite Float is below2^277, safely within Double. SoA padding uses quantize(0) and is never interpreted as a logical candidate.

Scalar and SIMD FP32 decode agree bit-for-bit with Float(Double(scale)*(Double(code)-Double(zeroPoint))), rounded once. Do not round Int32 zero points to Float before subtraction or form a Float bias that can overflow/cancel. Positive finite scale and finite ordered metadata are required; symmetric implies zeroPoint0. Add custom LinearQuantizationParams Codable validation using the same existing five keys, preserve all valid decoded fields exactly, and reject invalid tuples via DecodingError rather than a nonthrowing trap. Asymmetric legacy Int32 zero points outside byte range remain valid. Do not recalibrate decoded tuples or require metadata to bound every raw code. Such legacy tuples can project to Float infinity; their mathematical affine coordinates remain finite in Double, and the new-calibration finite guarantee does not apply to them.

Throwing INT8 array initializers retain shape-error precedence, then reject every nonfinite payload before extrema/calibration with VectorError.invalidValues and actual invalid indices. Existing nonthrowing scalar quantize/from/repeating/calibrator/SoA surfaces require finite input with identifiable guard/fatalError diagnostics in Debug and normal Release. No generic try! trap as a validation boundary. Maintain S01 storage shapes and exact encoded structure. validateQuantization at all widths should reflect the full parameter predicate, not only scale>0. No new public unchecked constructor or manual tuple-insertion escape hatch.

## Decoded-vector metrics, including EX-04

INT8 metric semantics use real affine decoded coordinates s*(q-z), evaluated in Double; they do not first project each coordinate to Float. Public concrete wrappers and QuantizedKernels generic/specialized implementations must agree. Raw dot-product sign remains unchanged; negative-dot distance conventions elsewhere are not altered. Generic VectorProtocol extension metrics and ordinary FP32 distance kernels remain separate range contracts; do not add protocol requirements or reroute every metric witness in this task.

Cosine: preserve the symmetric integer fast path only for positive finite scales and zero points0. At built-in widths Int64 integer dot/squared sums are safe (maximum squared sum1536*128^2=25165824). Cancel both positive scales before division. Asymmetric cosine also cancels scales, using exact centered integer dot and squared sums before conversion to Double. Each centered coordinate fits Int64 and each product is less than2^63 in magnitude; a built-in sum is less than2^75. Implement a small internal signed two-word accumulator (Int64 high, UInt64 low with reporting-overflow carry/sign extension), avoiding an Int128 availability dependency. Convert negative sums by forming their unsigned two's-complement magnitude before converting high/low to Double; signed high*2^64+low would introduce cancellation. The magnitude conversion need not promise correctly rounded Double for every75-bit integer; the bounded fixture tolerances below apply. Either decoded zero vector has distance1. Clamp finite similarity to[-1,1], return1-similarity; invalid intermediates must not be masked as finite distances.

EX-04 extension is approved: symmetric dot final scaling stays in Double until the final Float result, avoiding scale-product underflow/overflow before multiplication by the accumulated dot. Asymmetric/different-scale dot uses the same exact centered integer accumulator, followed by Double scale multiplication once. Exact integer cancellation must remain exact zero before scaling: compensated summation cannot recover errors already introduced in decoded-coordinate products. The product of two Float scales is exact in Double and lies between2^-298 and2^256; the scaled built-in dot is below2^331. Finite input can return Float infinity only when the mathematical result is outside Float range (within the documented bounded numerical tolerance); preserve IEEE NaN where applicable.

Scalar and SoA INT8 Euclidean integer fast paths require exact scale equality plus symmetric/zero-point0, not approximate equality. Exact equality is correct here because it is an algebraic routing invariant. Retain integer accumulation with final Double sqrt/scaling before Float rounding. Unequal/asymmetric fallback must evaluate both original affine decodes without first rounding each product to Float or losing a small difference through separate Double-product rounding. A Float scale times a centered Int32-derived coordinate can require up to56significand bits. Use a shared Double product-plus-residual helper (fused multiply-add residual), error-free subtraction/expansion of those products, then round the difference to Double before positive square accumulation. A finite mixed Float coordinate is already exact in Double and uses zero residual; route nonfinite mixed coordinates through the stated IEEE policy before finite-only residual transforms. Retain exact cancellation fixtures below; do not replace them with an oracle making the same rounded-product subtraction. Use Double differences and positive accumulation through sqrt, rounding only the final distance to Float. For built-in widths decoded coordinates <2^160, differences <2^161 and squared sums <2^333; Float mixed coordinates fit this bound. Do not broaden this bound to arbitrary custom storage/lane truthfulness.

Changing the equality gate routes more cases into fallback, so fix/test that fallback in the same task. Ordinary nonfinite FP32 mixed inputs follow Double IEEE difference/square propagation (NaN stays NaN, a genuine infinite difference can yield infinity); do not clip them to finite values. Both SoA result paths require capacity>=logical vectorCount before work and write only that prefix. Add the missing integer-path guard, with a named rejection diagnostic; preserve empty no-write and suffix sentinels. Do not change SoA layout/padding ownership or enable optional C kernels. Existing compiled Swift integer paths remain; uncompiled C alternatives are explicitly unverified.

## Quantized mutable borrows (EX-01)

Declare transactional-on-throw semantics across512/768/1536: a thrown body discards the temporary and preserves original raw storage and parameter bits exactly, rethrowing the original error. No quantization occurs while unwinding, including after temporary NaN/Inf writes. A normal return first validates all temporary coordinates, then recalibrates and publishes once; nonfinite output rejects with the named quantization precondition because rethrows cannot introduce a new error. Successful no-op borrowing may recalibrate/change raw codes, scale and symmetry. A valid legacy tuple whose Float projection already overflows will reject even after a successful no-op body; a throwing body still preserves original bytes/error. Document and test that distinction. O02's ordinary-storage partial-write policy does not extend to this quantized temporary API.
