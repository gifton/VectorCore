# Root contract decisions

These decisions resolve selected catalog checkpoints. A task is dispatched only after its exact brief, regressions and file ownership are ready. POLICY.md records the user's authorization for breaking changes and deferral of performance targets.

## S01 — Shape

Ruling: fixed-dimension values must never publish a storage count different from their width; dynamic scalarCount must derive from owned storage rather than a second independently stale dimension field. Fixed-width element mutation remains supported. Raw fixed storage replacement must validate the complete candidate before publication, including nested collection writes and generic protocol setters. Existing nonthrowing setters may reject invalid shapes with a documented precondition; throwing constructors and decoding must throw. No truncation or padding is permitted. This avoids silently changing values or accepting out-of-bounds states; an overly restrictive setter costs source adaptation for callers that temporarily resize a fixed-width vector.

The implementation brief will cover optimized FP32 widths 384/512/768/1536, INT8 widths 512/768/1536, DynamicVector, generic fixed controls and immutable FP16 controls. Existing VectorProtocol.storage get/set can remain if every built-in setter enforces its invariant. Root may approve a checked replacement API where needed; there is no obligation to preserve the ability to fabricate malformed vectors. Direct construction and decoding must share validation. The unsafe borrow's count must equal scalarCount at every public route.

## I01 — Hints

Ruling: invalidate hints before yielding any mutable access, including nested access through the public wrapped vector, storage and throwing mutable-buffer closures. Replacement invalidates even when the replacement happens to be equal. Decoded vector data is authoritative; serialized optimization hints must not be trusted to claim a vector is unit length. Conservatively clear decoded hint metadata rather than depend on N01's currently unrepaired magnitude implementation. Explicit `isNormalized: true` construction remains a caller assertion with a documented obligation. This eliminates stale/forged metadata; cost is recalculation after decoding or no-op mutable access.

A custom reference-semantic conformer whose aliases mutate without passing through the wrapper cannot be made observable by a value wrapper. Document the conformer's value/snapshot obligation rather than claiming universal alias tracking. The initial Core invalidation repair can precede S01, as the catalog permits; full shape and downstream CPU/GPU closure remains staged.

## I02 — Identity

Ruling: cache identity includes candidate count/order and an immutable snapshot of every coordinate's Float bit pattern, verified for equality after hash lookup. A digest alone is never identity. Bit-pattern equality deliberately distinguishes signed zeros and NaN payloads for conversion caching. Retained snapshots must participate in byte accounting alongside padded FP16 storage; logical byte accounting is not measured RSS. This closes collision and mutation false hits; cost is retained identity memory and full-coordinate comparison on matching hashes.

The I02 brief must specify checked count/byte limits, oversized-entry bypass, LRU replacement/eviction, and zero/negative capacity behavior before dispatch. Enforcing a caller-supplied byte budget is correctness; selecting a production operating envelope remains deferred. SoA storage is immutable ContiguousArray<UInt16>, so returned values can retain their own backing allocations beyond eviction: the budget describes cache-retained payload, not every caller-held result.

## R01 — Metric witnesses

Ruling: constrain Float-vector facade parameters and Float metric factory return types to `any DistanceMetric<Float>`. Invoke the supplied witness directly rather than recognizing types and constructing replacement metrics. A Double-only metric should fail type checking at this Float API boundary, rather than silently selecting Euclidean. This is an authorized source break for unconstrained existential callers; migration is to preserve/constrain the associated Float scalar, or explicitly cast and handle rejection outside the facade.

Preserve the existing TopKSelection ordering/tie/NaN contract and existing provider-first Operations route. R01 changes the two broken facades (TopKSelection.nearest/batchNearest and VectorCollection.search) and the metric-name factory; provider protocol redesign belongs to D01/D02. Test all built-ins, nondefault Minkowski, configured custom witnesses, direct scores/membership, and case-insensitive factory names.


### I02 budget/API follow-up

A cache byte budget will be explicit, not inferred from an unselected production workload. The new initializer requires `maxBytes` and may retain `maxSize: Int = 100` as the independent entry-count guard. Both limits must be nonnegative; zero disables retention while getOrCreate still returns a conversion. Remove the unconfigured global `shared` instance (unused by Core's production call sites) rather than selecting a speculative global memory budget. Existing callers migrate to an actor instance they own with a chosen budget.

Remove the public `store(soa, for: vectors)` association API: it can attach an unrelated precomputed payload to an otherwise exact identity. The public cache API becomes get/getOrCreate/clear/statistics; private insertion always binds a snapshot and a conversion produced from the same candidates. Callers of manual store migrate to getOrCreate. This authorized source break is preferable to claiming exact conversion correctness while retaining an unchecked public association boundary.

Budget accounting includes retained allocated payload capacity for identity UInt32 arrays and padded FP16 UInt16 storage, using checked multiplication/addition; oversized/overflowing entries bypass retention without evicting useful entries. Dictionary/LRU metadata and caller-held returned arrays are excluded and must be named explicitly; this is not an RSS or transient-peak limit. Access-order keys must reuse the retained snapshot on hits so dictionary and LRU do not accidentally retain two independent equal snapshots. Evict least recently used entries until both count and byte constraints fit, with exact decrement on eviction/clear and no duplicate accounting on hits. Deliberate hash-collision tests need an internal fingerprint injection seam; full bit-pattern equality still decides identity.


## E01 — Loop/chunk domain (pre-dispatch ruling)

Validate positive explicit batch sizes, chunk hints and unroll widths before empty/serial/parallel routing. Empty valid requests do no work (reduce returns its initial value); negative counts are rejected. A Range<Int> whose mathematical length is not representable as Int is outside the materializing execution APIs' domain: the final E01 brief refines the early precondition proposal to a recoverable VectorError(.invalidRange), because all affected execution APIs already throw. Validate before Range.count. Tiny near-Int.max/Int.min ranges remain valid. Compute bounded endpoints as start + min(chunk, remaining), with remaining proven representable; avoid start+chunk followed by min and overflow-prone ceil-division numerators. Protocol defaults require separate coverage from CPU overrides. Reduction identity/ordering and outstanding-task bounds remain E02, not silently changed by arithmetic repair.

O01's exclusion of general triangular size overflow is not an audited E01 closure requirement in the original catalog; retain it as an unverified boundary concern until specifically designed, rather than claiming a fix or silently expanding task scope.


## N01 — Range-safe numerical core (early ruling, route policy still pending)

For finite nonzero input, normalization must not require the full norm or its reciprocal to fit in the input scalar. Compute a positive finite scale `s = max(abs(x_i))`, accumulate `q = sum((x_i/s)^2)` with a range/accuracy-appropriate accumulator, then form each result as `(x_i/s)/sqrt(q)`. Do not reconstruct `s*sqrt(q)` or `1/s`. Float routes should use widened accumulation; Double extremes need scaled/exponent-based independent references, not merely Double-as-oracle. Direct scalar division is the correctness primitive for a representable quotient; the audit already disproves a blanket vDSP substitution. Any optimized fast path must be separately proved/tested across normal/subnormal divisors and tails.

The catalog's source/read list is a starting point, not the complete route inventory: normalization also has VectorNormalization.swift fast/tolerance entry points, concrete optimized vector wrappers, and MatrixDistance row normalization; division also has VectorFactory, SwiftDoubleSIMDProvider and SIMDOperations forwarding paths. N01's bounded brief must map these routes, reserve any required additional writes, and explicitly assign matrix semantics to R03 where appropriate. Zero/nonfinite and checked/unchecked/tolerance policies remain to be specified before dispatch. No claim of N01 readiness or closure is made by this preliminary mathematical ruling.

## Q01 — Quantized cosine and conversion (early ruling; calibration policy pending)

For symmetric INT8 vectors with positive finite scales and zeroPoint0, cosine cancels both scales: evaluate integer-code dot and squared magnitudes in a sufficiently wide accumulator, then form Double(dot)/(sqrt(Double(q2))*sqrt(Double(c2))). All built-in widths have small enough integer sums for the existing Int64 accumulator; this statement does not cover arbitrary custom laneCount. Do not form Float scale-squared products. If either decoded vector is zero, preserve distance1. Clamp only a finite similarity to [-1,1]; invalid intermediate values must not become a plausible finite distance through min/max behavior. Asymmetric input needs a separately tested bounded/scaled or Double decoded-vector route instead of inheriting unrepaired FP32 cosine normalization. Test all three widths, self/opposite/orthogonal, unequal scales and tiny/huge finite calibration ranges.

Quantization must classify and clamp floating intermediates before any integer conversion. For finite Float input and positive finite Float scale, Double division can represent the quotient's range, including subnormal scale; do not replace division with a Float reciprocal that can overflow. Scalar, packed AoS and transposed SoA routes must share observable rounding/saturation. The source inventory includes LinearQuantizationParams, all three INT8 array/repeating/from initializers, two SIMD conversion implementations, calibrators (including public empty SoA calibration), and decoded parameters. Validating a symmetric flag must also establish zeroPoint0 before it selects an integer fast path.

Still pending before dispatch: choose a common affine calibration/constant policy (including zero is a candidate supported by the audit), establish finite endpoint error bound and extremes, select explicit nonfinite rejection/fallback across throwing/nonthrowing APIs, preserve valid legacy decoded parameter tuples, and settle EX-01's quantized mutable-borrow commit/error semantics. Do not silently add defer while invalid quantization can trap during error unwinding. Current deliberation is not an approved Q01 implementation brief.

## O04 — Memory boundaries

Final bounded contract is briefs/O04.md. Naturally aligned Float pointer normalization is supported via unaligned SIMD loads; numerical range policy remains N01. All optimized Float-array constructors copy scalar lanes without requiring stronger alignment, and owned SIMD→Float borrows restore binding on all exits. alignedCopy uniformly updates initialized, nonoverlapping destinations; uninitialized callers migrate to the standard pointer initializer. AlignedDynamicArrayStorage retains requested alignment on its Swift fallback, with per-call failure injection and matching deallocation. Common AlignedMemory explicitly binds fresh storage, validates count/byte arithmetic and allocates one uninitialized element for a logical zero count. OWN-25 remains qualified forced-failure evidence, not a real OOM/misalignment reproduction. The brief explicitly expands common allocator/all-width constructor scope and retains separate MemoryPool/AlignedValueStorage concerns.

## R02 — Replacement and identifiers

Final contract briefs/R02.md removes the unsafe generic update default and requires each mutable collection to implement transactional replacement. SimpleVectorCollection validates then replaces under one lock; explicit duplicates throw. Generated IDs scan unused nonnegative successors, never rewind on removal/clear, and explicitly represent exhaustion after Int.max. Explicit IDs do not advance that cursor. Simple search/batch reads capture a dictionary binding snapshot under lock and invoke metric code after unlocking; default protocol composition does not promise an atomic concurrent snapshot. No claim of deep immutability for custom reference aliases. This is an authorized source migration for conformers inheriting update.

## R04 — Bounded heap and legacy ordering

Final contract briefs/R04.md preserves streaming comparator orientation: root precedes retained members; bounded heaps retain the last capacity members in that order. Bulk construction must select the same membership. Negative limits reject; zero retains nothing; a large limit does not require an eager large allocation. KNearestHeap deliberately adopts shared TopKSelection numeric-before-NaN, ascending distance/smaller-index order, retaining NaN fillers only after numeric candidates. This is a new documented legacy policy, not historical parity. Generic comparator equivalence has no stable drain-order promise. Current public Operations/TopKSelection use TopKBuffer; internal ExecutionOperations still has a separate legacy small-k caller and sort branch. No branch rewrite or broad parity claim.

### N01 route-policy refinement (brief still pending)

Root chooses direct per-coordinate division for vector/array/provider scalar division rather than reciprocal multiplication. Existing vector /, /= and inPlaceDivide reject +/-zero divisors; raw/array providers retain IEEE division behavior for zero and nonfinite scalar inputs. All routes preserve signed-zero results where native division does; finite representable quotients must not overflow solely due to reciprocal construction. Exercise generic VectorFactory witnesses separately from VectorProtocol defaults, concrete optimized operators and both static providers/array adapters.

Checked Result normalization rejects empty/all-zero and any nonfinite input before mutation, returning invalidOperation with the cause. Valid finite nonzero FP32/Double representations normalize without requiring scalar norm/reciprocal representability. Unchecked typed methods will have explicit finite/nonzero preconditions in Debug and Release; the pointer overload retains dimension0 no-access behavior but nonempty invalid data rejects before writes. Permissive array/normalizedFast/normalizeFast/custom-tolerance APIs preserve zero or nonfinite input unchanged and document that they may return an unnormalized input. Tolerance must be finite and nonnegative, even on empty/invalid input;0 disables early-return tolerance. Default fast tolerance remains1e-6. Near-unit early return must be based on a finite-aware reliable calculation, not the currently failing raw magnitude path.

MatrixDistance row normalization is an additional owned N01 route: finite nonzero rows normalize safely, zero rows stay zero, nonfinite rows become NaN rows so distance entries cannot turn invalid input into plausible finite values through clipping. Exact packing/dimension/score semantics remain other tasks. Generic/optimized normalization consumers (NormalizationHint conveniences, NormCache, Operations normalization, TransformOperations) need explicit tests/read reachability; known-unit caller assertions remain caller assertions. Built-in INT8 is not IndexableVector; quantized output approximation remains Q01 and must not be presented as a full-precision unit-vector guarantee.

The earlier scaled-domain algorithm remains the Double/wider strategy. For FP32 a reviewed equivalent is accumulation and division entirely in Double: every finite Float square is representable in Double (at most48 significant binary bits), Float min-subnormal squared remains above Double min-normal, and even Int.max copies of Float max squared are below Double max. Therefore a widened norm can be used without reconstructing an unrepresentable Float norm. A compensated or otherwise justified accumulation and tests are still required; no speed claim. A shared Float helper can also repair optimized magnitude/magnitudeSquared by rounding the final widened result once, eliminating the existing subnormal direct-Float-square fallback. Generic BinaryFloatingPoint routes must not indiscriminately narrow wider scalar types to Double; preserve at least their scalar precision with a scaled native fallback, and widen Float16 as needed.

Still needed before N01 dispatch: complete bounded write/test inventory, precise finite-aware residual tolerances and independent Double-extreme oracles (closed-form scaled patterns or retained high-precision Decimal-generated fixtures), failure/error compatibility fixtures, matrix/hint consumer coverage, and explicit staged API-39 downstream limitation. No N01 worker is authorized by this refinement alone.

### N01 final dispatch contract

The full contract is now briefs/N01.md, following independent reports/N01-design-review.md. It expands owned normalization routes to both TransformOperations bodies, actual-output verification in hint conveniences, and finite-aware preNormalized consumer clipping, while ordinary NormCache range remains excluded. Generic formats preserve native precision and fail checked normalization if their scaled accumulator cannot represent q; Float/Float16 use exact Double widening. Permissive no-op/tolerance early returns are explicitly exempt from unit-vector regression bounds and must preserve bits/predicate instead. Full residual bounds apply only when normalization occurs. API-39 remains staged for actual VA evidence. Dispatch still requires accepted S02/O04 and the Core I01 repair; no N01 implementation has begun.


## Q01 — Final bounded quantization contract

Root approves briefs/Q01.md after independent final design review. Both calibration APIs include zero for asymmetric ranges; newly calibrated tuples keep every byte decode finite using an exact-product-checked scale cap. Empty, nonfinite, percentile, wire-validation and mutable-borrow transaction policies are explicit. Valid legacy asymmetric Int32 offsets remain accepted; their FP32 projection can overflow. EX-04 dot/Euclidean/mixed/SoA repairs are included after the actual Release witnesses in reports/EX04-results.log.

Review found decoded Double-product accumulation can turn exact affine dot cancellation into infinity. Root selected exact signed two-word centered integer accumulation before scale multiplication, with unsigned magnitude conversion; no stronger Double correct-rounding theorem is claimed. Root then found exact affine coordinate differences of one collapsing to zero after separate Double products. The contract requires product/FMA-residual expansions and error-free subtraction, independently checked against exact integer fixtures. reports/Q01-affine-difference-* records an optimized offline arithmetic experiment, not production execution. Final reviewer observations (up to56significand bits and routing nonfinite mixed values before finite-only residual transforms) are incorporated. Core implementation and acceptance remain pending.


## N03 — Population magnitude statistics

Root approves briefs/N03.md after reports/N03-design-review.md. Use the current generic Float magnitude expression, then shared centered Double statistics for async serial/parallel and the independently discovered synchronous occurrence. Empty yields count0/zeros; any nonfinite delivered magnitude gives countN/twoNaNs. Population deviation divides by N. Parallel partials merge by original chunk index, with no promise of partition-independent bits. Existing live settings remain disconnected until E06, and E03 must be accepted before dispatch. Exact two-point/constant and independent two-pass/Decimal fixtures cover both sides of999/1000 and actual partition sizes. No component covariance, magnitude-witness redesign or performance claim.


## R05 — Explicit score witnesses

Root approves briefs/R05.md after independent reports/R05-design-review.md. Add a defaulted optional DistanceMetric.relevanceScore witness; unknown metrics return nil rather than inheriting a guessed transform. Known nonnegative metrics use widened inverse distance, negative-dot uses a stable logistic interpretation, and nonfinite distances have no generated score. Replace the metric-free computedScore property with an explicit computedScore(using:) method. Explicit stored values remain untouched; wire fields remain unchanged. Actual collection producers use the same metric witness outside locks and do not alter ranking. R02 must be accepted first because its snapshot producer is shared. No score-calibration, probability, underlying-distance or downstream claim.
