## Observable and numerical contract

For finite Float coordinates use p_i=abs(x_i)/sum(abs(x_j)) and return the Float-rounded sum of -p_i*ln(p_i) for p_i>Float.ulpOfOne. The strict normalized-probability cutoff is retained deliberately: the result is the documented truncated entropy, not exact Shannon entropy for arbitrarily small probability mass. Include every coordinate in the denominator even if its entropy term is omitted. The cutoff never applies to the absolute input sum. All-zero input returns positive zero; any NaN or either infinity returns NaN regardless of position or other coordinates. Signs and signed zeros do not affect finite entropy.

Widen Float coordinates exactly to Double before abs/summing. Sum positive magnitudes with compensated Double arithmetic, and accumulate entropy terms in Double, rounding only the final result to Float. Finite Float magnitude times an Int-sized count is below2^191 on this64-bit target; the smallest nonzero Float divided by that bound is above2^-340. Thus positive Float coordinates and the denominator fit this widened algorithm without a Float sum/reciprocal. This is a range argument, not an exact-sum or universal error theorem. Never use min/max alone to detect NaN. Avoid array/provider temporary chains: two scoped passes with O(D) work/O(1) auxiliary scalar storage are sufficient.

Both entropyFast branches and public entropy must implement the same contract. Existing internal entropySmall/entropyLarge may forward to a shared implementation; retain internal symbols for existing serialized/inlinable call compatibility unless root approves removal. If consolidating the gate, re-derive the now-shared path across all dimensions and test both helpers directly at small/large widths.
