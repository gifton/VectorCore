# T10 brief: test child-process harnesses respawn without bound and orphan grandchildren (root-created)

## Finding (V04 phase F independent review, I-5, 2026-10-04; evidence `.stabilization-recovery/2026-10-03/V04/phaseF-review/`)
- 18 test files re-launch the test binary for a child probe by rewriting only the FIRST `--filter` value: `arguments.firstIndex(of: "--filter")` → replace `[index+1]`. Example: `FP16DiagnosticsBoundaryTests.swift:18`.
- With several `--filter` arguments, the remaining filters survive, so the child also runs OTHER probe-spawning tests, which spawn their own children. In one focused 9-filter run, the reviewer's chain grew to about 110 live processes and about 460 logs in /private/tmp. The reviewer killed them by PID.
- Timeouts kill only the direct child (`kill(process.processIdentifier, SIGKILL)` or `terminate()`), so grandchildren are orphaned.
- Files (root grep at integration 3b7ea85):
  MixedPrecisionRangeWorkTests, BatchConfigurationContractTests, MemoryPoolBoundaryTests, E06ConfigurationTestHelpers, VectorDispatchContractTests, FP16DiagnosticsBoundaryTests, UnsafeMemoryContractTests, PCACenteringContractTests, LoggingPublicConsumerTests, ExecutionSchedulingContractTests, ConfigurationTransactionTests, VectorShapeContractTests, SoAFP16CacheIdentityTests, UMAPRangeContractTests, LinearAlgebraRangeTests, SearchResultScoreContractTests, MatrixMetricContractTests, AutoTuningConcurrencyTests. ExecutionBoundaryTests also has a child probe.

## Required (after T09 merges; T09 edits FP16DiagnosticsBoundaryTests and MixedPrecisionRangeWorkTests)
1. **One shared child-launch helper in the test target:**
   - remove ALL existing test-selection arguments (`--filter`, `--skip`, and any other selection flags the runner accepts), then set exactly one filter for the probe;
   - mark the child with an environment variable, so a child never spawns a probe of its own (fail loudly if it tries);
   - launch the child in its own process group, and on timeout or failure kill the whole group;
   - keep each test's existing bounds, diagnostics and assertions.
2. Migrate all 18+ call sites to the helper. Keep each probe's semantics: same environment, same expected outputs, same exit handling.
3. **Mechanical closure.** Add a lexical policy test (Scripts/ci/tests/, on swift_lexing.py) that rejects ad-hoc rewriting of `--filter`/`--skip` arguments, and direct `Process()` launches of the test binary, outside the helper. Use inline RED fixtures, controls and bite checks, and make it pass out of repo.
4. **Evidence.**
   - Before and after: run a focused `swift test` with 3+ `--filter` arguments that include several probe tests. Before shows the process growth (count PIDs, bounded by a watchdog that kills ONLY the processes it spawned, by PID). After shows a bounded tree and exit 0.
