# P01 — Complete hashing and bounded selection storage

Root-approved design after independent review; all stated prerequisites remain required before dispatch. Read P01-design-inventory.md and OWN-07/API-23/API-24/API-45. Require accepted R01/R03/R04/O03/V04 and E06; refresh routing/callers after E06. S03 owns TopKResult decoding and must land before this task touches the same file. No production throughput or dataset target; breaking VectorMath count/tie behavior is explicitly selected below.

## Hash every equality-significant coordinate

Replace the four optimized vector types' sampled hash with a scan of every SIMD storage block in index order, plus the fixed dimension. Use Swift Float/SIMD Hashable semantics, preserving equal signed-zero hashes; do not hash raw float bits, cache hashes in mutable/COW storage or change equality. Hash cost becomes O(D), rather than constant sampled work. Process-seeded hash results are not persistent identifiers. Ordinary unequal-value collisions remain legal and no universal collision-free promise is made. I02's cache key/fingerprint and storage ownership stay unchanged.

Tests cover384/512/768/1536, copies, signed-zero replacements in every block and independently constructed equal values. Structured sparse and dense corpora vary only interior coordinates formerly omitted, including late differences. Actual Set/Dictionary insert/lookup must preserve all unequal finite values. Verify that a corpus does not deterministically collapse into one hash; do not require all hashes unique or hard-code final hashes. Add a maintained source/structural check that each implementation feeds the complete block iteration and does not revert to the four sampled blocks, with a mutation fixture restoring that omission. This checks coordinate coverage, not mathematical hash quality. Baseline/final Release dictionary measurements use identical fixtures and consumed lookup totals; report hashing cost and distribution separately from dictionary elapsed time.

## Common Int-indexed streaming selector

Retain the existing small-k strategy condition `actualK < N/10` for array/generic public selection. It is a compatibility choice for strategy boundaries, not a newly measured optimal crossover. Clamp positive k to actual N before allocation; k<=0 or empty input returns empty without invoking score callbacks. Small-k selection scans each score once into the existing Int-indexed TopKBuffer and extracts/sorts only the retained entries. Never route Int APIs through the pointer Int32 API or add its count ceiling.

Add a narrow internal score-by-index selection helper so array selection, generic element selection, generic TopKSelection.nearest and VectorMath share the scan law without full-N score/pair arrays on the small-k path. Synchronous score callbacks run exactly once per candidate in increasing original-index order, even for NaN/obviously losing values. No score callback runs during extraction/sort. The large-k path may materialize and sort N pairs, preserving one evaluation per candidate and the existing strategy predicate. Result output preserves original score bits, including zero signs, and original Int indices. Retain `.smallerIndex`/`.insertionOrder` and `.smallerValue` equivalence semantics exactly; equivalent-key identity/order is unspecified for smallerValue, so no new stable membership assertion.

Keep the numeric-before-NaN policy, both directions where already supported, exact tie policy and min(k,N) count including NaN fillers. Array/generic APIs select ascending scores. Positive dot similarity remains the existing direct optimized dot API's descending policy. Generic distance witnesses remain authoritative, including custom/parameterized metrics; do not silently select a built-in metric because types happen to match.

VectorMath.nearestNeighbors deliberately adopts this common ascending numeric-before-NaN/smaller-original-index policy. k<=0 and empty candidates return [] without metric calls; negative k no longer traps after work and k0 no longer evaluates the metric. Positive k evaluates exactly N callbacks in index order, returns min(k,N), and uses the shared small-k/large-k strategy. Document this intentional compatibility change and test it independently. Remove its false unconditional heap/O(n log k) and Accelerate claims in the touched scope; state small-k and large-k complexity separately.

## Preserve score arithmetic while bounding batch temporaries

BatchOperations retains E06's one entry snapshot, live threshold, logical partitions and six public optimized routes. Nonthrowing nearest still completes under cancellation and nested operations submit no extra library workers. Do not replace existing batch Euclidean/cosine calculations with a different scalar or TopK kernel merely because the mathematical metric matches: their rounding, zero/NaN policy and admission scores are observable. Batch Euclidean currently selects computed root distances; retain root-score admission here. Operations/direct optimized TopK paths select squared distances before formatting roots; retain that distinct contract too.

For small-k BatchOperations generic routes, feed computed scores directly into local heaps. For optimized routes, invoke the same existing BatchKernels range arithmetic on bounded temporary score tiles (maximum256 candidates, shorter tail), then feed every computed score/global index into the local heap. Keep query precomputation and candidate range semantics equivalent to the accepted base. Tile each original logical range independently, restarting at that range's original lower bound; never coalesce or tile across original logical boundaries. A256-candidate tile preserves the existing pair/group-of-four boundaries and original tails; exact per-candidate parity remains the acceptance gate. Do not copy candidate slices or change kernels. Before edits, prove by caller/source inventory which existing helper supports offset output/rebasing and how the exact original score is obtained. Compare complete per-candidate scores for tiled versus accepted untiled execution on finite, root-tie and exceptional fixtures before relying only on top-k membership. New arithmetic differences return to root rather than receiving a looser tolerance silently.

Bound retained partials by the actual library worker count, not the potentially much larger logical chunk count. E06 permits minimumChunkSize1 and large oversubscription, so returning one heap for every logical chunk can still allocate O(N) metadata. Use the accepted completeMap scheduler over at most `min(C, logicalChunkCount)` worker partitions; each worker processes its assigned successive logical chunks and merges into one heap. Preserve actual logical-range observation for every chunk and original-index tie rules, then merge worker results deterministically. E02 worker phases keep their real submitted/completed accounting; no synthetic worker/core override. Nested/serial execution follows the same complete-result law with no extra tasks. An immutable pure partition helper can cover representability limits without huge arrays. Do not construct an all-chunk array to schedule this work.

Each worker heap capacity is at most min(actualK, number of candidates assigned to that worker); each score tile at most256. The temporary upper model for built-in batch execution is O(C*k + C*256 + k) excluding inputs/results and ordinary runtime overhead, with capacities bounded by actual work. State this model and measure it; do not promise allocation-free or literal constant total process memory. Large-k BatchOperations keeps its full-score/sort strategy to avoid forcing a heap for near-N work; preserve its existing strategy threshold after dispatch inventory. No new tuning threshold based only on intuition.

If preserving E06 test observations needs changes, return the exact test/phase migration to root before editing existing tests. Retain their public six-route, snapshot, partition, metric, cancellation and worker-bound assertions. TopK semantic/result tests alone do not substitute for real route observations after this internal dispatch change.

## Operations validation and partial heap sizes

Keep all public Operations.findNearest/findNearestBatch preflight checks and order: positive k, required nonempty arrays, all row dimensions, then provider/CPU dispatch. Extract a private validated nearest worker only to avoid repeating whole-candidate validation for each query in the already-validated batch fallback. Public single-query invocation still validates every candidate. No public validation bypass. Installed BatchKernelProvider remains first and receives the original k/custom metric; preserve arbitrary provider result/error behavior rather than normalizing it to CPU policy. The batch override still executes once for the full batch; generic ComputeProvider task-local nesting/error/cancellation behavior remains intact.

Explicitly preserve the remaining optimized fallback: cosine768/1536 reaches computeDistances' fused BatchKernels range helpers even though no direct optimized TopK helper exists. Keep those two Operations routes on that existing full-score path, including its calibration/admission behavior and exact fused arithmetic. Their N-score materialization remains a qualified cost in P01; do not silently send them through metric.distance or claim that every small-k Operations route streams. Tests must identify actual fused routing and compare complete accepted scores, including exceptional values. No new Operations tiling is authorized for these two routes.

For the remaining generic CPU small-k fallback, deliberately bypass computeDistances' AutoTuning calibration and local serial/parallel admission, and delegate partition admission to provider.parallelReduce with one Int-indexed heap per supplied range. Calculate the actual metric exactly once per candidate for the whole public call, with no preliminary calibration probes. This is an intentional callback/admission compatibility change: a previously cold key could evaluate up to256 candidates twice and choose synchronous map; the new small-k path always asks the installed ComputeProvider to reduce, with that provider retaining its bounded/nested/serial policy. Within each range scan original order; cross-range callback order remains unspecified. Preserve cancellation checks around provider user callbacks and ordered combination. Large-k generic fallback and all optimized full-score fallbacks retain their existing computeDistances calibration/admission behavior. Shared AutoTuning and ParallelHeuristic implementations stay unchanged. Fresh-process tests with cold AutoTuning keys and custom metric/provider spies prove exactly N small-k metric calls, actual provider entry, no new cache publication by this path, and preserved large-k/optimized controls. Do not change shared numerical eligibility or heuristics just to force branches in tests; observe actual branches and use conforming provider fixtures for range variation.

Existing optimized Operations helpers keep their exact squared/dot/cosine arithmetic and existing k<N eligibility. Reduce each local capacity to min(actualK, range.count), passing that same local capacity to the existing range kernel's `localTopK.k == k` contract. Empty provider ranges produce an empty heap and do no arithmetic; a zero-capacity TopKBuffer must safely ignore push or callers must provably skip it. Prefer adding the narrow zero-capacity guard and named tests to make the repeated class robust. Validate k>=0 before buffer allocation; no eager allocation from an unbounded user k. Preserve merge direction/tie-policy compatibility and destination capacity sufficient for both input capacities. Do not weaken those checks to make one caller compile.

Permit a narrow mutating merge-into operation that feeds a source's live entries into the destination instead of allocating a third destination heap. Preserve the existing public/internal merge signature if callers require it, with source alias/COW independence tested. Swift value copies may still detach; do not claim zero allocation from inout alone. Repeated merges and differently sized partials need full class tests, including empty0, min(k,rangeCount), fullk and two equivalent-key policies. Custom providers may choose arbitrary valid partition counts; the library's C-based resource model applies only to the built-in bounded providers. For disjoint ranges, sum of local retained capacities is at most N; do not model every chunk as allocating full global k after this repair.

API-24's flat matrix-to-row reshape remains outside P01 and is assigned to P02's batch/memory contract. Retain the current public nested-matrix result and GEMM query gate; do not infer a flat-output feature from this task. Its overall record stays partially staged until that separate aspect is adjudicated. Current GEMM Q*N scores remain an explicit materialized cost, even though row selection streams for small k. Source-model improvements alone are not measured peak reductions.
