# E04 — Pool ownership, bounded retention and allocation contracts

Root-approved contract, independently accepted in reports/E04-design-review.md. Covers API-05, API-06, API-32, API-37 and EX-05. Breaking changes below are authorized by the user's policy. Performance targets and downstream execution remain deferred. Read the original E04 work item, E04-design-inventory.md and E04-root-memorypool-profile.md; the latter supplies the measured cache-scan baseline. Dispatch still requires exclusive source ownership and an isolated archive.

## Ownership and initialized elements

The three actor pools (SwiftBufferPool, internal BufferPool, public TypedBufferPool) own both their cached and checked-out allocations. A returned handle is a borrowed capability, not an owning allocation or pointee synchronization mechanism. The caller must retain the provider until release and stop accessing the memory before release. `clear`/`cleanup` free cached allocations only; checked-out handles stay valid. Pool destruction frees both remaining sets exactly once. Retaining a borrowed handle alone does not extend the allocation lifetime; tests of destruction with a live handle count frees without dereferencing the expired pointer.

Every acquisition gets a fresh lease identity, including reuse of the same address. Store the authoritative address, physical capacity/byte count, requested size/count, alignment and lease identity in pool-owned metadata. A release must match that active record before removing it. Duplicate, foreign, stale or forged address/size/identity combinations are ignored without freeing, caching, decrementing or retiring the real live lease. In particular, stale copies cannot release a new lease at the same cached address. SwiftBufferPool's nonthrowing protocol release remains nonthrowing.

TypedBufferPool's raw acquire/release interface cannot express a lease generation. Replace acquire(count:) with a public borrowed typed-handle return and release with that handle argument. The handle exposes requested `count` and a computed unsafe buffer/pointer; its identity and creation are not caller-mutable. Document the source migration explicitly. The internal SendableBuffer also gains a unique acquisition identity. Address metadata may cross an actor boundary; pointed-to values do not thereby become Sendable or synchronized. Do not add blanket unchecked annotations to actors or suppress Swift 6 diagnostics. Any narrowly necessary low-level owner wrapper needs a written ownership invariant and independent review.

MemoryPool retains its different existing owning-handle model: a handle can outlive the pool; a live pool accepts its automatic return, otherwise the handle frees its own allocation. Pool teardown frees only cached entries. Handle metadata must retain the allocation's actual alignment, byte count/capacity and matching deallocator, not merely the latest request's weaker alignment. A 64-byte allocation reused for 16-byte and then 64-byte requests must retain its 64-byte guarantee.

All generic storage is uninitialized on acquisition and must be uninitialized again before release/return. Callers initialize exactly the elements they use and deinitialize them before returning, including on throw/cancellation. Pools release raw allocation ownership and do not guess an initialized count or silently deinitialize generic payloads. Buffer count is requested logical count; physical capacity may exceed it. Zero-count requests expose no elements, but use a minimum nonzero physical allocation whose bytes count against cache budgets. Test nontrivial reference payload lifetime independently from allocation/free balance. Fix the standalone tracked allocator's fresh-memory binding (`bindMemory`, not `assumingMemoryBound`) and its Float fixture's initialize/deinitialize pairing; do not use an invalid fixture to justify production lifetime claims.

## Strict cache budgets and statistics

Budgets govern cached physical payload bytes, not active bytes, RSS, allocator metadata or total process memory. A return must never leave retained bytes above the cap. Prefer admission-only policy: if the returning allocation does not fit the remaining cap or per-size count, free it; existing cached entries need not be evicted to favor a new arrival. Age alone cannot excuse exceeding the cap. Zero budget retains nothing, including zero-count allocations. `clear` sets cached bytes to zero and preserves active accounting. Budget arithmetic uses checked products and subtraction-based admission.

- SwiftBufferPool uses existing maxPoolSize and maxBufferSize, comparing physical rounded bytes. Track active and cached bytes separately. `BufferStatistics.currentUsageBytes` remains active physical bytes and `peakUsageBytes` is peak active physical bytes. With trackStatistics=false, operational active/cache accounting still runs; public cumulative allocation/reuse and peak counters are zero. Current usage remains observable. With true, cumulative counters track successful fresh acquisitions and cache reuses. Clear does not reset cumulative/peak values. Provide concrete cached-byte inspection for tests without changing the BufferProvider protocol requirement. Compute hitRate with widened counts to avoid the public initializer's integer-sum overflow; document zero/invalid negative counter handling (negative counters produce 0).
- Internal BufferPool keeps maxBuffersPerSize and memoryLimitMB, now explicitly a cached-byte cap. Check MB conversion. Track active and cached bytes separately; cleanup has clear semantics. Repeated or foreign release must not change its counters.
- TypedBufferPool requires an explicit `maxCachedBytes: Int` initializer argument, plus existing default maxBuffersPerSize=10. There are no Core callers to migrate. This avoids inventing a workload budget. Add clear and concrete active/cache inspection as needed for its public usable contract/tests.
- MemoryPool preserves existing totalAllocated = outstanding pooled allocation bytes (active plus cached), and totalInUse = live handles, including zero-count handles. Replace flatMap cache summation on every return with maintained cached bytes. Update it on every reuse, admission, cleanup and teardown path. Verify it against an independently recomputed bucket sum under the same lock. Keep statistics names and existing tested late-handle behavior. Operational counters must never wrap; checked admission/accounting failure returns allocation failure at recoverable acquire boundaries, while cumulative diagnostic counters may saturate with that policy documented.

Allocation/free ledgers must count actual allocations and actual matching frees, with identity tracking to detect duplicates. Use per-instance internal allocator injection or an equivalent isolated boundary, never shared mutable process-global hooks for ordinary tests. Production defaults still use the real allocator. Failure injection must be deterministic and scoped to the tested pool/call, not a public failure knob or a fake replacement of pool logic.

## Request and configuration domains

All counts/sizes and budgets are nonnegative. Alignment is a power of two, at least 16 and at least the scalar's natural alignment. All byte products, MB products, power-of-two rounding and active/cache additions must be representable before allocation or state mutation. Rounding must never silently return a capacity smaller than requested. Use exact-request minimum physical capacity 1 for internal/typed pools, power-of-two physical buckets for SwiftBufferPool and MemoryPool. Logical zero stays zero. Use matching allocation/deallocation families. For SwiftBufferPool, use a portable posix_memalign-style boundary or correctly round the physical size for aligned_alloc; no Linux runtime claim without execution.

Nonthrowing configuration initializers reject invalid values with named guard/fatalError diagnostics in Debug and ordinary Release. maxBufferSize may exceed maxPoolSize; it remains a separate admission limit. SwiftBufferPool.acquire throws a documented invalid-request BufferError for negative/unrepresentable size, leaving all state unchanged; allocation failure retains its existing allocationFailed outcome. MemoryPool.acquire returns nil for invalid/unrepresentable count/alignment or allocation failure. Nonthrowing internal/typed acquisitions and MemoryPool.withBuffer reject invalid requests with a named guard before invoking body or allocator. Allocation failure in a nonthrowing typed/raw allocation remains fatal; do not promise real OOM recovery.

MemoryPool.withBuffer validates once, preserves the requested alignment in every fallback, binds fresh raw memory to T and pairs each allocation family with its own deallocator. Test deterministic failure of pooled allocation and of the first direct fallback to reach the final raw allocation. No unchecked count*stride, natural-alignment downgrade or assumed binding of fresh raw bytes is allowed. Keep a handle alive explicitly through the full body (including error unwinding). The final fallback is a best-effort allocation that may terminate on real exhaustion; remove the current false suggestion that an unrelated body rethrows its allocation error.

Preserve current MemoryPool cleanup interval meaning: nonpositive/nonfinite disables the automatic timer; explicit cleanup uses the configured age cutoff (negative finite intervals remove all previously returned entries). Scheduling a huge positive finite interval must not overflow integer nanoseconds or deadline arithmetic. Intervals beyond the timer's representable horizon may leave the timer disabled/distant-future, with this behavior documented and tested. Do not turn this into a timer scheduling redesign.

## Scoped APIs and Swift 6 consumer

Add a BufferProvider default `withBuffer` scoped helper taking a Sendable async throwing body over BufferHandle and returning Sendable R. The helper is `async throws`, not `rethrows`, because acquire can independently fail. It strongly retains the provider for the entire operation, awaits release exactly once after success or thrown error, then returns/rethrows the same result/error. An acquire failure invokes neither body nor release. Cancellation is cooperative: if the body observes cancellation and throws, release finishes before that error returns. A body that ignores cancellation still owns the lease until it completes. Do not use async defer or a detached cleanup task. Replace the noncompiling provider documentation example with this helper and compile that exact public example under Swift 6.

TypedBufferPool offers an actor-isolated synchronous throwing scoped helper over UnsafeMutableBufferPointer<Element>, with a Sendable result/body capture contract; the pointer must not escape and initialized elements remain the body's duty. Its borrowed handle API remains available for explicit lifetime management. Compile concrete nonisolated, actor and MainActor consumers without blanket concurrency suppressions.

BufferPoolContext already awaits release in do/catch; preserve that behavior while adapting lease identity. OperationContext.withTemporaryBuffer must use awaited do/catch release rather than defer Task. Tests verify release-before-return on success, throw and cooperative cancellation, exact error identity, provider retention when the external strong reference is dropped during the body, and active handle survival through clear. Do not claim a type-system guarantee that unsafe pointers cannot escape a closure.

## Regression matrix and acceptance

Establish behavioral RED in the unchanged isolated base: cached actor allocations surviving destruction and a fresh return burst exceeding the configured byte cap. Include actual allocation/free identity evidence, not only synthetic counters. Separately retain source-established invalid arithmetic/fallback defects until a safe bounded probe or forced-failure path reproduces them.

For each actor pool: empty destruction, cached destruction without clear, clear then destruction, multiple clear calls, clear with live leases, destruction with live borrowed metadata, success/throw/cancel scoped return, duplicate/foreign release, stale generation after address reuse, and forged size/address where construction permits it. Zero/exact/below/above cache caps, per-size caps, mixed sizes, bursts and repeated cycles must compare cache bytes to an independent live-allocation ledger after every relevant operation. Typed payloads include a reference-owning type whose deinit count proves correct caller deinitialization, separately from raw frees. MemoryPool additionally covers handles outliving their owner, actual-alignment reuse, all type/size counter transitions, the shared-pool regression's saturation/strict executor cases and both fallback stages.

Boundary tables include -1/Int.min/0/1, maximum representable bucket/product neighbors and Int.max, invalid alignment 0/negative/nonpower/below-natural, negative caps, zero counts, zero caps and MB conversion overflow. Huge valid allocation requests need not be attempted: test checked arithmetic/injected allocation boundaries or named child rejection as appropriate. Every deliberate trap runs in a filtered child with file output, handler before run, 15s execution plus at most 2s cleanup; assert the specific diagnostic and a marker proving no body/allocator entry. No unbounded wait/pipe read. Do not use real OOM as a regression.

Run focused Debug and Release using separate E04 scratches and max6jobs, including new suites and existing MemoryPoolTests and ProviderConformanceTests. Run valid ownership/fallback/reference cases under ASan; exclude deliberate traps explicitly. Run Scripts/ci/check_memory_pool.py in Debug and Release and all watchdog regressions. Compile/run the public scoped API consumer and negative/non-Sendable controls at the intended boundary. Retain setup failures separately.

Root repeats its linked Release allocation probe against final exact sources. Compare all cached-count rows and result/control checks; report remaining bookkeeping allocations honestly. Contention samples are exploratory without a workload or thermally controlled host, and no speedup threshold is required. Independent review must validate ownership/destruction, initialized-element duties, identity validation, accounting arithmetic, fallback allocator pairing, actor isolation and exact source/evidence association. Freeze full diff/new files, commands/exits/hashes, allocation ledger and scope inventory; back up frozen sources outside /tmp before acceptance.
