## Specific questions
1. Is the M3 driver check specific enough? Yes.
   - If the control compiles (a property of either `Float` or `Float?` shape exists), the run exits 0. `expect_success=False` then fails, so it cannot pass.
   - An unrelated compile error (missing module, syntax error) lacks the method-type text and trips the RuntimeError.
   - The positive compile with identical flags runs first.
   - Residual: it is pinned to compiler wording, and it fails closed. A new Swift release that rewords the diagnostic gives a false failure, not a false pass. This is acceptable for an evidence-only tool.
2. Could the policy rule produce false positives on the current tree? No. The repository scan is clean (test run, plus a grep of Tests for both patterns with zero hits). The rule is deliberately narrow, with two known false negatives, both out of scope for now:
   - a comparison split across lines;
   - other path-name heuristics such as `hasSuffix`/`contains("workspaces")`. The latter would be caught only if it used the exact literal `"workspaces"`.
3. Are temp-directory captures unique per run? Yes. Each run creates a `<UUID>` directory under the shared `R05-children` / `L03-children` base. `withIntermediateDirectories: true` makes concurrent creation of the base safe. The report shows /var/folders/.../T/R05-children/<UUID>/ paths printed in the logs. See N2 on cleanup.

Minor wording notes on the diff (not defects in behaviour):
- N1. DistanceMetrics.swift:20-21 says "The widened Double expression gives a single final rounding to Float". Only the final rounding to Float is single. `1 + Double(d)` and the Double division each round in Double, so the chain has more than one rounding, and for tiny d the `1 + d` step is inexact. The test oracle shows 0 ULP at every test point, so this is not a numeric problem. Under the claim discipline, "one rounding to Float after evaluating in Double" would be exact.
- N2. Out of the diff's behaviour but adjacent: the temp-directory capture directories are never removed (R05 and L03 both leave `<UUID>/` behind in the system temp area). Harmless; the OS reaps temp. The parent folder name is fixed, which is intended.
