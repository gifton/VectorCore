# Q04 — Range-proportional FP16 wrapper work

Root design candidate; independent review before dispatch. Prerequisites Q01/Q03, and exclusive ownership serialized with O05/Q02. Read reports/Q04-design-inventory.md and canonical NUM-22. The present defect is O(total candidates) copying/retaining of ContiguousArray handles, not copying every FP16 payload or reconverting unrelated vectors. No production latency target or allocation-free promise is introduced.

## Contract and mechanism

Keep all nine public signatures: Euclidean squared, cosine distance and positive dot for widths 512/768/1536. Preserve arithmetic, FP16 rounding, diagnostics, query representation, synchronous owner-borrow lifetimes and exceptional-value policy. Result[j] corresponds to candidates[range.lowerBound+j], written to out[j]. Output views use their own base; all elements after range.count and any surrounding parent-buffer prefix remain bitwise unchanged. No original candidate indices are written to output.

Use the minimal sliced-map mechanism: validate once, return immediately for a valid empty range, map only candidatesFP16[range] to owned storage handles, and pass 0..<requestedCount to the unchanged internal arithmetic core. Do not retain the original nonzero range after rebasing. The temporary metadata array is O(requestedCount); selected payloads remain shared immutable owners. No raw pointer array, escaped borrow, global hook, new accessor protocol or arithmetic/core rewrite is needed. O05's scoped public borrow migration remains intact; existing internal owned borrows need not be rewritten through that API.

Add one @usableFromInline validation helper usable by all @inlinable wrappers. These nonthrowing unsafe-pointer APIs retain a precondition contract, with guard/fatalError diagnostics that remain observable in normal Release. Validate range.lowerBound >= 0 and range.upperBound <= candidateCount before any range.count subtraction, map, query arithmetic or output write. A well-formed Swift Range already orders endpoints. Then derive the safe count and require out.count >= count. Use distinct named range/capacity diagnostics, shared across all nine. An out-of-bounds empty range is invalid; a valid empty range at start/interior/end returns without indexing query/candidates or dereferencing output, including nil-base zero-capacity output. Correct pointer initialization/capacity/aliasing remains the caller's unsafe obligation; this is not arbitrary pointer validation. Output capacity is permitted to exceed the requested count.

The three internal cores remain implementation details with a validated compact-range caller contract. Do not claim new standalone public safety for them or alter their floating-point policy. Remove redundant/debug-only wrapper-equivalent assertions only if they conflict; otherwise preserve them as internal sanity checks. Avoid modifying unrelated whole-batch maps.

Replace unsupported speedup/relative-error claims in the touched nine-wrapper documentation with the actual compact output, validation and O(range.count) metadata contract, naming the new range-contract tests. FP16 element payload is half the byte width of Float; that is not a measured bandwidth or speedup claim. Other file-wide claim inventory remains V04/Q02.

## Tests and actual work evidence

Create a nine-route matrix with N=0/1/2/3 and a larger distinct-pattern set: empty ranges at zero/interior/end, nonzero-start singleton, two/three entries, full range and odd tail. Use actual stored FP16 values for an independent finite Double scalar reference with justified FP32 accumulation tolerances. Query/candidate values should make index rebasing errors observable. Preserve squared-distance versus positive-dot versus cosine semantics. Finite-aware checks reject NaN/Inf instead of hiding them in max/abs reductions. Check exact-bit sentinel suffixes and parent prefixes around nonzero-offset output views. Compare special-value classification/bits against the unchanged same core route as a separate parity control, not an independent numerical-accuracy oracle. Record the existing cosine nonfinite/near-zero denominator policy honestly; return any new arithmetic defect to root.

Fresh bounded children cover each wrapper's negative lower bound, oversized upper bound, out-of-bounds empty range, extreme Int.min..<Int.max before count evaluation, and short output. Assert intended named diagnostics in Debug and Release, not merely abnormal exit. A parent-process shared buffer or equally concrete observation may verify no writes before rejection; do not infer that from a crash alone. Valid inputs run under ASan. No invalid-pointer probes.

Establish an unchanged-production behavioral RED for the missing named eager validation and/or actual allocation-growth contract. Build a standalone public client against the real Release library with identical baseline/final fixture source and optimization flags. Preconstruct query, candidate data and output outside measurement. Hold requested count 0/1/2/3 fixed while varying unrelated N (including at least two separated large N), and vary the nonzero lower bound. Capture requested allocation bytes as well as events; a constant event count can hide an O(N) handle buffer. Include warmed no-op, known C allocation and Swift Array controls; consume checked outputs outside the measured window. Keep setup conversions and library/compiler metadata initialization out of credited steady-state measurements. Check final fixed-range work is independent of unrelated N and grows at most with requested metadata; do not demand zero allocations for nonempty ranges. If optimized baseline removes the suspected allocation, report it without changing build flags to manufacture evidence and obtain root adjudication. Source-level nine-wrapper coverage can complement, not replace, measured evidence.

Retain exact host/toolchain, command argv, source/object/module/executable hashes, actual baseline and repaired rows, and independent comparison assertions. No RSS-as-allocation proxy, scalar reimplementation-as-library probe, timing pass/fail threshold or downstream/GPU claim.

No quantization kernels, tuner, FP16 constructors/diagnostics, SoA or other production file changes. New MixedPrecisionRangeWorkTests plus narrowly scoped public/allocator/child drivers are allowed. Repeat caller inventory at dispatch; existing valid callers should need no migration. Existing MixedPrecisionRangeValidationTests tests FP16 values, not candidate indices, and cannot substitute for the new matrix.

Run focused Debug/Release new matrix plus existing mixed-kernel/FP16 range tests, actual linked before/after Release allocation probes and valid-path ASan. Freeze full patch including new files, full code inventory, sealed evidence and canonical backup. Independent full review and root reconstruction/allocation comparison precede import.
