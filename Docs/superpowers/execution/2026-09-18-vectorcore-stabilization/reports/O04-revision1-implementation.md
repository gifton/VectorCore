## Behavior and migration

Pointer normalization retains its numerical operations and gates, replacing all eleven SIMD raw loads across all three passes, including unrolled and tail-vector sites, with unaligned loads. Float owners retain binding. Negative dimension preconditions; zero returns without access. Ordinary finite inputs are tested; zero/nonfinite/extreme-range numerical changes belong to N01. Natural Float alignment, live initialized capacity and pointer lifetime remain caller obligations.

All four FP32 array constructors copy four scalar lanes into each SIMD4 value. They neither rebind nor assume SIMD alignment of source arrays. S01 guards and backing are preserved. Vector384's three conversion/borrow sites now use nested scoped rebound from the aligned homogeneous SIMD owner, restoring binding on normal and throwing exits. No public API added. Borrow pointers must not escape, including indirectly in closure return values. No optimizer miscompile was reproduced.

`alignedCopy` now always updates initialized destinations, releasing replaced values. Source/destination must be valid, naturally aligned, initialized and nonoverlapping. This is an ownership contract change: callers using raw/uninitialized destination storage must call standard `initialize(from:count:)` themselves. Preferred alignment remains a positive compatibility hint with no measured optimization promise. Negative count and nonpositive hint reject even at zero count. All three alignment predicates return false for nonpositive boundaries; positive non-power-of-two address multiples remain supported.

`AlignedMemory.allocateAligned<T>` establishes binding on new raw memory and returns uninitialized storage. Count must be nonnegative with representable byte size; invalid counts throw invalidDimension without allocating. Alignment remains a power of two at least16 and now must satisfy T's alignment. Logical zero allocates one uninitialized element and still exposes logical count0. Caller initializes/deinitializes its logical count and releases through AlignedMemory.deallocate/free.

Four AlignedDynamicArrayStorage public construction routes converge on a validated internal designated initializer. A per-call internal throwing primary allocator closure enables deterministic failure injection without globals or public parameters. Primary success retains free metadata. Primary failure requests the same checked size and requested alignment through Swift raw allocation, binds Float, and records Swift raw deallocation. Array routes update already-zero-initialized Float storage. Actual exhaustion may still terminate. This is forced-primary-failure evidence, not real OOM reproduction or proof of old fallback corruption. No wire representation changes; constructor signatures remain available. Rebuild clients using serialized inlinable bodies.

No `assumingMemoryBound`, permanent `bindMemory`, or raw aligned loads remain in those files. The 384 changes match the existing scoped strategy of other widths. Scalar subscript and SIMD arithmetic continue to access their original SIMD owner after the borrow closes. The count guards shield all force-unwrapped owner base pointers and remain unchanged; no numerical/provider gate was expanded.
