## Memory reporting: three distinct quantities

MixedPrecisionPerformanceBenchmark.swift:302–324 uses MemoryLayout<owning vector>.stride for FP32/FP16 “bytes” and100000-vector footprint extrapolation. This is handle-array arithmetic, not scalar payload or allocated/resident memory. For fixed width D, logical scalar payload is4D bytes FP32 and2D bytes FP16, independent of handle size; e.g.512 gives2048/1024. Actual allocation includes backing object headers/capacity/alignment and sharing. Repeated copies can share a COW allocation, whereas independently constructed equal vectors need not. State these as separate columns/records rather than equating payload savings with total retained-memory reduction.

MinimalTests/ComprehensiveBenchmarks.swift:263–290 “MemoryFootprint” methods allocate1000 vectors before XCTest.measure and time summing magnitudes. Rename as traversal/magnitude timing or supply actual memory instrumentation; the current assertions do not measure bytes. V03 owns its26-method observation wrapper/strict-performance migration, so name/report changes must be coordinated after that contract. Do not remove numeric anti-elision assertions while renaming.

MixedPrecisionKernels memory-saving helpers and docs can retain2:1 scalar-format models if explicitly labeled payload-only, excluding metadata/padding/temporary conversion and COW aliases. FP16 pool values retain shared backing storage; draining available handles is not an RSS result. No new observed allocation or RSS value is supplied by this inventory.

## Available instrumentation and its limits

Scripts/ci/tests/O03Allocation.c and O03RunAllocationProbe.py provide accepted Release linked-object snapshots and process-local malloc_logger instrumentation. The C collector records allocation events/requested bytes, payload-threshold subsets and a bounded32-size histogram; it filters failed allocations and verifies its callback semantics. It restores the logger and refuses to replace an existing one. It does not maintain a live-pointer ledger or count frees, so summing its requested bytes is not retained bytes, peak live heap or RSS. Do not relabel accepted O03 rows as those quantities. The provider-call counter and source/module/object/executable hashes can inform a bounded V04 probe, without changing historical fixtures/results.

Accepted E04 per-instance allocator ledgers test exact ownership/deallocation and requested sizes for pool paths; they are not generic process footprint profilers. Root Q01/E04 linked allocation probe reports similarly establish their named measured scopes and already carry no timing claim. Reuse proven instrumentation mechanics only with explicit V04 scope and calibration; avoid concurrent malloc_logger ownership across probes.

MixedPrecisionDiagnostics.swift:309 onward MixedPrecisionProfiler measures per-invocation mach time, stores samples internally and reports statistics; memoryBandwidthGBps derives caller-supplied memoryBytes/mean time, not hardware-counter bandwidth. It does not measure allocations or CPU utilization merely because those fields exist. Its operation closure owns result consumption. V04 must not infer new profiler correctness or arbitrary parameter safety from use in existing tests; Q03 explicitly excludes profiler changes. The shared benchmark Harness reports distributions of per-sample average ns/op rather than individual-operation latency percentiles. Preserve that statistical unit and raw measurement provenance in any retained comparison.
