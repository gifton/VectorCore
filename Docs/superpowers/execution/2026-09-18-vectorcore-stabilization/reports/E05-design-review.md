# E05 independent design review

**Verdict: ACCEPT.** The proposed state machine is coherent and addresses the reachable reentrancy defect without introducing synchronous waiter deadlocks. Read the candidate brief, complete `Providers/AutoTuning.swift`, and the actual public Operations.findNearest → computeDistances calibration path. No implementation edits, builds or delegation were performed. The opening reference should use Providers/AutoTuning.swift, as its exclusive-write list already does.

## State transitions and ownership

Validation/disabled shortcuts precede callback admission. Under one lock, published cache wins first, then an in-flight reservation yields an unpublished provisional default, then the completed-time cap may publish its default, otherwise the key is reserved. Callback execution and tuning calculation occur outside the lock. On successful completion, publish only if no value is already cached, retire the reservation, charge elapsed callback time and capture immutable logging data in one locked transition. Return the winning published value. On throw, retire/charge under the lock and rethrow the same error without publishing a default; an intervening manual set remains cached but does not replace the thrown error.

This ordering supports direct recursion, two-key recursive cycles, concurrent get/set and concurrent different-key callbacks. A manual set must not retire an existing reservation early: it changes the cached value, and the active callback still owns cleanup of its reservation. No generation token is required if reservations cannot be cancelled/replaced and no cache-clear/reset API is added. Same-key callers can see defaults, a manual value or the final calibration at different times; the brief appropriately avoids promising identical simultaneous results.

The synchronous throwing closure remains on its calling thread, so rethrows is appropriate and existing nonthrowing callers need no try. It need not be made escaping or sent to another executor to achieve unrelated-key concurrency. Logging must use the locked snapshot of total time and the winning tuning; neither formatting nor printing belongs in the locked section. Disabled get/calibrate behavior and manual set's existing storage semantics can remain distinct as specified.

Completed callback durations may overlap or nest and still add individually. Direct two-key recursion therefore counts the outer duration, including nested work, and the inner duration: this follows the stated sum-of-callback-durations policy, not a wall-clock budget. Stop the callback timer immediately after callback success/error if the final documentation says callback duration; otherwise explicitly document inclusion of subsequent calculation. Admission before the cap cannot bound a slow/nonreturning callback, and the design makes no such claim.

## Arithmetic and fallback

Invalid dim/cores must be rejected before a cached shortcut, as specified. Invalid probes/floating intermediates must produce the default through the same success-publication path so a manual value still wins and reservation cleanup still occurs. Keep integer conversions below safe representable thresholds; validate before conversion rather than relying on a later clamp. In particular, Double(Int.max/2) rounds to 2^62 on this platform: preserve the exact integer inefficient sentinel directly when capping at it, rather than converting that rounded Double cap back to Int and silently producing sentinel+1. Bias scaling, task-count division, dimension scaling and alignment addition all require their stated checks. No probe-validation repair changes the cache key or measurement-quality policy.

The existing defaults themselves are safe for negative/extreme dimensions because they only compare the dimension with 1024. Positive extreme core counts convert to finite Double; zero/negative values must never reach the divisor. Failures of these recoverable calculation paths must not strand a reservation. Fatal/nonreturning callbacks remain outside recovery, correctly qualified.

## Actual public reachability and tests

A custom metric with DynamicVector inputs, a fresh dimension/key and a fresh child process reaches the generic Operations.findNearest path. It bypasses neither the calibrated computeDistances call nor the supplied metric witness: custom metric classification falls back to euclideanLike, giving KernelKind.euclid, and the calibrator invokes metric.distance directly. Use the default CPU compute provider (no BatchKernelProvider), ensure VC_AUTOTUNE is enabled in the child, and require callback-entry evidence before interpreting a timeout as the original deadlock. A child-specific environment is the correct place to control the lazily initialized tuner configuration.

Operations.findNearest returns an array of NearestNeighborResult, not a SearchResults object with candidatesSearched metadata. For this route, use k equal to candidate count and verify the complete index/distance array and count against the independent custom metric oracle; do not attempt to infer a nonexistent metadata field. The brief's candidate-count requirement is achievable through that result cardinality plus known fixture input.

The bounded child matrix is sufficient if every concurrent scenario verifies actual callback counts and completion rather than merely parent exit. Prove both different-key callbacks enter before release, same-key callers return before release, and get/set complete during a paused callback with finite gates. For overlapping/failure time accounting, a per-state injected monotonic clock is preferable to scheduler-duration assumptions, provided public entry points use the same state algorithm and no production-global mutable clock hook is introduced. Manual-wins tests must use distinct complete tuning tuples for success, invalid fallback and throw. Throw/retry and cap exhaustion require fresh eligible keys or isolated state so cache hits do not mask missing cleanup.

No omitted reachable production route or contract blocker found. Q02 key provenance, measurement quality and strategy selection remain explicitly outside this acceptance; no routing gate, performance goal or public type-initializer expansion is needed.
