# S01 — Enforce vector shape at public storage boundaries

Status: root-approved contract; schedule after the initial bounded tasks and reserve the seven source files below. Breaking changes are authorized; performance workload targets are deferred.

## Observable contract and design

DynamicVector owns its dimension through storage.count. Remove the independent stored dimension; retain an internal computed dimension alias if useful for existing methods and Codable. Public storage replacement may resize a dynamic vector, and scalarCount, endIndex, array/buffer counts, equality/hash and serialization immediately reflect the replacement. Construction with an explicit mismatched dimension still throws. This task does not define new negative-dimension/allocation-limit policies (S02/E01).

Optimized fixed FP32 widths 384/512/768/1536 and INT8 widths 512/768/1536 must reject incorrect storage lane counts before they become a public vector state or reach a kernel. Valid lane counts are respectively 96/128/192/384 and 128/192/384 SIMD4 values. A nonthrowing raw initializer or setter rejects malformed input with a documented precondition naming the required count. Existing throwing array constructors and decoding throw. No truncation or padding. Keep shape-preserving element mutation and public VectorProtocol.storage get/set.

A guarded setter or willSet observer is permitted if tests prove it covers direct assignment, generic protocol assignment, nested collection mutation, inout writeback and throw unwinding. Initialization can temporarily construct a local candidate, but every public initializer must finish valid. Do not accidentally run a fixed-shape check after each append while assembling a constructor's temporary. Synthesized Codable must not bypass validation: explicitly decode INT8 storage and parameters, check lane count before calling a preconditioned raw initializer, and explicitly preserve its existing keyed wire names `storage` and `quantizationParams`. Quantization parameter validity belongs to Q01/S03; preserve valid parameters byte-for-byte here.

For a computed setter, retain efficient internal mutation of already validated backing storage; do not add a whole-vector copy to every library scalar write merely to validate its unchanged count. Do not add an unchecked public initializer or expose mutable backing storage to bypass the guard. Unsafe buffer borrows retain fixed count and can mutate elements only. If Swift accessors force a broader API change, report concrete alternatives to root before implementing.

VectorProtocol docs should state the shape obligation on conformers: scalarCount matches borrowed scalar count; fixed-width replacement validates shape, dynamic replacement updates dimension. This is a contract for third-party conformers, not a claim that Core can mechanically enforce their internals. Generic fixed Vector/DimensionStorage and immutable FP16 representations are regression controls; edit them only with root approval if an actual bypass is found.

## Independent regression matrix

Mechanically enumerate all four FP32 widths and three INT8 widths. For each use short/equal/long lane counts. Exercise raw storage construction, throwing scalar construction, direct replacement, storage.removeLast/append, generic protocol setter, inout storage access (normal/throwing) and Codable. Nonthrowing invalid operations run in isolated child processes: expected success is the explicit shape guard trap, not a later out-of-bounds or unrelated failure. Identify the guard diagnostic and process status; never perform unsafe access on a known malformed baseline value just to manufacture a crash. Demonstrate the baseline accepted malformed shapes via child process return/recorded metadata before the repair.

For valid cases assert scalarCount, logical dimension, Collection.count, toArray.count and both borrowed pointer counts agree, and read the final element. Retain a copy while applying a valid mutation; original and mutated values must remain independent. Equal coordinate/parameter values hash equally. Serialize, decode and compare actual payload and dimension, not just successful decoding. For INT8 inspect original encoded JSON shape first and preserve its keys and SIMD element representation; short/long decoded storage must throw before toFP32 or any kernel is called. Exercise valid toFP32, quantize/dequantize and distance/kernel routes for each width after replacement, with an independent simple finite-coordinate reference and existing parameter tolerances. Inventory every unsafe INT8 entry point and explain why malformed built-in input cannot reach it after these guards; custom malformed conformers remain a documented protocol obligation unless an API-specific guard is required.

Dynamic controls start at two coordinates, replace storage with lengths 0/1/2/3 and a heap-backed size, and assert all count/serialization/hash contracts. Exercise replacement through NormalizationHint and a generic VectorProtocol helper; hints must clear under I01. A dimension-bearing decoded payload whose declared dimension differs from element count must still throw. Generic fixed Vector controls use short/equal/long constructor/decoder values and legal shape-preserving mutation. FP16 controls prove conversions retain declared width and immutable owned storage count; do not invent nonexistent mutable APIs.

No timing thresholds. Record any material additional copy cost as a limitation for O03/O04, but use direct backing storage for internal scalar changes where necessary to avoid a new obvious full-copy path.
