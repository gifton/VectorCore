## Architecture

DynamicVector's internal dimension alias computes `storage.count`; its public replacement can resize and all existing count, equality/hash, JSON and binary-positive-dimension paths immediately observe that count. Explicit mismatched-dimension construction/JSON decoding still throws. Zero-dimensional binary decoding remains rejected by the existing BinaryFormat 1...10000 policy; JSON supports zero. This task does not change that binary policy.

Each optimized FP32 type has an `@usableFromInline internal _storage` backing property required by its existing inlinable constructors/operations. Public storage has a guarded setter and a `_modify` accessor that yields the backing storage under exclusive access and checks its count in `defer`, covering ordinary and throwing writeback. Internal scalar setters, buffer mutation and arithmetic write directly to backing storage. Constructors can assemble backing storage privately before returning their valid value. No unchecked public initializer or public backing access was added.

INT8 backing is private. Its three raw initializers validate lane count. Explicit keyed Codable decodes storage, checks shape and throws `DecodingError.dataCorrupted` before invoking the raw initializer, then decodes unchanged quantization parameters. Encoding preserves the keys `storage` and `quantizationParams` and SIMD4's nested scalar arrays. Numerical parameter validity/calibration/quantization behavior was not changed.

Storage mutation is still available through VectorProtocol get/set. Protocol documentation states the count/shape obligation for all conformers; arbitrary custom conformer internals are not claimed mechanically guarded.

## Unsafe INT8 reachability inventory

- `QuantizedVectorINT8.vectorizedQuantize` reads the associated FP32 type's fixed SIMD lanes; built-in FP32 constructors and mutation boundaries validate these counts. The destination is sized to the concrete INT8 lane count and ends in its guarded initializer.
- `QuantizedVectorINT8.toFP32` reads `Self.laneCount` INT8 chunks and initializes a fixed-size FP32 destination. Built-in INT8 construction, replacement/writeback and decoding now all establish that shape before this method can be called.
- Concrete INT8 `toArray`, scalar Collection access and both scalar-buffer methods route through `toFP32`; mutable scalar buffers retain count and requantize through a throwing fixed-size array constructor. Throwing mutable-buffer coordinate semantics are unchanged and outside S01.
- `QuantizedKernels.euclidean_generic_int8`, `euclidean_generic_mixed` and `accumulate_fused_generic` borrow/query both fixed representations. Their 512/768/1536 Euclidean (both mixed argument orders), dot and cosine wrappers receive the guarded built-ins. The optional C dot path uses `withSIMD4Int8Pointer`, which borrows and reports the actual scalar count; matching concrete built-in widths now establish matching pair counts.
- `QuantizationCalibrator.calibrate` and `calibrateWithDistribution` borrow FP32 storage. The fixed built-ins now satisfy the declared widths; custom OptimizedVector conformance remains an obligation.
- `SoAINT8.transposeAndQuantize` reads guarded built-in FP32 arrays and owns immutable SoA count/layout storage. `batchEuclidean_generic_mixed` and `batchEuclidean_generic_int8` borrow those SoA candidates and guarded fixed queries. Shape repair does not validate caller-owned result buffer capacity or define new SoA allocation/overflow policies.
- `KernelAutoTuner` builds INT8 test data through `init(from:params:)`, then uses the same fixed wrappers; it introduces no mutable bypass.
- Generic `SIMDStorage<SIMD4<Int8>>.minMax` and pointer bridge helpers iterate/use actual borrowed counts; standalone raw arrays/pointers have their own caller contracts, not a declared fixed-vector shape.

No custom malformed conformer or invalid quantization parameter claim is closed by these built-in guards. No numerical kernel routing/configuration gate changed.

## Migration and cost

Valid callers retain the public storage property and raw initializer signatures. Malformed fixed-storage replacement/raw construction now traps; malformed INT8 JSON now throws. Dynamic storage replacement now changes dimension. INT8 wire keys/representation are preserved. Stored-to-computed property/backing-layout changes are a library ABI consideration; existing source use with valid shapes remains supported.

The `_modify` accessor does not create a second array owner: it yields backing storage directly and validates once on completion/unwind. Internal FP32 scalar and arithmetic writes bypass public accessor overhead. Ordinary retained-copy mutation still pays the existing copy-on-write cost. No timing or allocation-count claim is made; O03/O04 remain responsible for measured workload effects.
