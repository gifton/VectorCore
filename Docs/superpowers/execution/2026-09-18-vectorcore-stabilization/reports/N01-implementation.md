## Arithmetic and policies

Scalar division uses native per-coordinate division in the protocol/factory/concrete optimized operators, inherited default, SwiftFloat override, Accelerate Float/Double overrides and both underlying array adapters. SwiftSIMDProvider and forwarding namespaces retain dispatch. Vector +/-zero divisors still reject, including empty vectors; raw/array zero/nonfinite divisors retain IEEE classification and signs. Exact aliasing and count-zero no-access are tested; no partial-overlap guarantee is added.

Root additionally approved the same-class binary repair in the two existing Accelerate provider methods after `N01-binary-control-red.log` isolated vDSP binary division failures for Float and Double. `[s,-s,+0,-0] / [s,s,s,s]` at least subnormal produced `[-Inf,+Inf,NaN,NaN]`; maxFinite yielded nextDown(1) rather than exact 1. Swift providers and generic elementwise operators passed. Direct native binary division avoids introducing a new gate. Its tests cover count tails, source/result distinct, exact alias of either operand, sentinels, and IEEE exceptional values, plus all array adapters.

`NormalizationCore` first validates the full input and then produces a plan. Float/Float16 use exact Double widening, compensated squares and Double division before one final coordinate rounding. Native Double/wider fallback uses positive finite maximum scale, compensated scaled square sum and `(x/s)/sqrt(q)`; no original norm or reciprocal is formed to normalize. Unrepresentable native q fails before writes. Generic custom/INT8 storage fidelity is not promised. Optimized magnitude and magnitudeSquared round their widened results once and may return infinity when the scalar result itself is unrepresentable.

Checked normalization rejects empty, then nonfinite, then all-zero inputs in the normalize/invalidOperation family and preserves original bits. Typed unchecked methods and the pointer method deliberately reject invalid nonempty input with named fatal errors in Debug and normal Release. Pointer count zero accesses nothing, including a deliberately unusable pointer fixture; naturally Float-aligned offsets 0/4/8/12 work without rebinding. Permissive arrays and fast/tolerance APIs preserve invalid input bits. Tolerance is validated first; signed zero disables early return; strict widened-norm predicate and large-tolerance non-unit returns remain intentional.

Both TransformOperations bodies use the permissive stable mathematics while preserving each row's dimensions, factory errors, scheduling gates and order. Operations continues honoring an explicitly supplied provider witness. Matrix rows use stable normalization, preserve zeros and turn invalid rows into NaNs; actual prepared/unprepared GEMM tests verify propagation and unaffected valid pairs. Hint conveniences verify returned coordinates, including lossy custom writeback; caller-asserted constructors remain unchanged. NormCache normalized builders preserve checked failures, and the three preNormalized consumers propagate nonfinite dots before clipping. Ordinary NormCache/cosine dot/norm-square range remains unrepaired.

`safeNormalized` applies existing `handleNonFinite` first and preserves strict/propagate/replacement precedence and existing nonfinite error families. It then normalizes finite nonzero handled input; unresolved nonfinite handled data is returned unchanged; handled zero takes strict zero error, then propagate all-NaN, then unchanged zero. All 32 flag combinations are checked with an independent scalar policy oracle at small and fixed large dimensions, with beginning/middle/end placements and original error indices.

## Migration

- Invalid typed unchecked normalization deliberately traps with a named diagnostic in Debug and normal Release, replacing undefined results or silent unchanged returns. No -Ounchecked guarantee.
- Checked empty/nonfinite input now fails explicitly; finite extreme input can succeed even if its scalar norm cannot fit.
- Permissive zero/nonfinite inputs preserve original bits, including both batch normalization paths; they may remain unnormalized.
- Invalid custom tolerance rejects before early return. Finite large tolerance intentionally permits non-unit output.
- safeNormalized now handles original nonfinite values before normalization; replaced infinities can therefore normalize safely, NaN-only replaceAll becomes zero, and unresolved nonfinite values remain handled but unnormalized.
- Hints only advertise normalized output when actual returned Float coordinates meet the postcondition; lossy writeback can produce nil/false rather than an unjustified unit hint.
- No existing test expectation was changed.
